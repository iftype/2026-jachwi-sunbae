# 카드형 홈 디자인

로그인하면 보이는 홈(`/`)과 본 방 기록 화면(`/properties`)의 디자인이다. 처음에는 `/design-preview` 시안으로 만들었고, 지금은 로그인 뒤 기본 화면으로 쓴다. 시안 주소(`/design-preview`, `/design-preview/records`)는 없앴다. 로그인하지 않고 `/`에 들어오면 랜딩(`/landing`)으로, 토큰 만료 등으로 방금 로그아웃됐다면 까닭을 안내하는 로그인 화면(`/login`)으로 보낸다. 로그인은 `/login`에서 따로 한다. 기존 분석 코드는 수정하지 않는다.

바텀탭 없이 기능 영역을 50:50 두 열로 나눈 시안이다. 왼쪽 열에는 큰 본 방 기록 카드를, 오른쪽 열에는 위에서부터 `사용방법 알아보기`·인프라 지도·동네 찾기 카드를 쌓고, 두 열의 위아래 끝을 맞춰 같은 높이로 둔다. 그 아래 한 줄에 정사각형 아이콘 타일 4칸을 두고 `체크리스트`·`방 비교`를 왼쪽부터 채우며 이름은 타일 아래에 표시한다(긴 이름은 두 줄까지 보이고 말줄임). 나머지 2칸은 기능이 정해질 때까지 배경 없는 빈칸으로 자리만 잡는다. 그 아래에 가로로 넘기는 최근 기록 카드가 이어진다. 마이페이지는 오른쪽 위에 배치한다. 화면 UI만 새로 구성하고 기능은 기존 앱 화면을 그대로 사용한다. 본 방 기록하기는 `/properties`, 인프라 지도는 `/map`, 동네 찾기는 `/neighborhoods`, 사용방법 알아보기는 버튼만 두고 이동할 화면은 이후 연결하며, 체크리스트는 `/checklists`, 방 비교는 `/compare`, 마이페이지는 `/me`로 이동한다. 기존 서비스 소개 페이지(`/intro`)와 소개 영상은 삭제했다.

브랜드에는 노란 배경 오리 마스코트의 머리와 목 윗부분을 잘라 만든 둥근 정사각형 이미지(`shared/assets/jachwi-sunbae-goose.webp`, 160px)만 표시한다. 로고 글자는 이후 이미지로 대체할 예정이라 넣지 않는다. 로고는 라우터 이동이 아닌 일반 링크(`/`)라서 누르면 홈을 새로 불러온다. 파비콘은 같은 이미지를 64px로 줄인 `shared/assets/favicon.png`, iOS 홈 화면 아이콘은 180px `shared/assets/apple-touch-icon.png`를 쓴다. 두 파일은 `index.html` 템플릿에서 `require`로 불러와 이미지 규칙을 거치므로 운영 빌드에서 `assets/favicon.<해시>.png`처럼 해시가 붙은 이름으로 나가고, 아이콘을 바꿔도 1년 캐시에 막히지 않는다. 기능 카드에는 집·체크보드·인프라 지도를 표현한 무채색 플랫 일러스트를 넣는다. 최근 기록의 사진 자리는 빈 영역으로 표시해 전체 크기와 간격을 검토한다.

상단 소개 제목·설명은 표시하지 않는다. 브랜드 아래에는 연한 회색 배경의 둥근 안내 영역을 두고 검은색 팁 문구를 표시한다.

휴대폰 폭에서는 기존 서비스의 `--app-max-width`(24.375rem)를 공유하고, 태블릿부터는 아래처럼 넓힌다. 휴대폰 화면에서는 홈, 지도·리스트, 매물 목록·상세 화면이 가용 너비 전체를 사용한다. 인프라 지도·동네 찾기 지도는 창 폭과 상관없이(휴대폰 폭보다 넓고 태블릿보다 좁은 창 포함) 늘 화면 전체를 쓴다.

예전 매물 목록 홈(검색·진행 상태 필터가 있던 `PropertyListPage`)은 지우고, 기록 목록은 본 방 기록 화면의 지도·리스트로 대신한다. 랜딩 체험 작업은 별도 체크아웃에 보존한다.

`본 방 기록하기`는 `/properties`로 이동한다. 바텀탭 없이 상단에서 지도·리스트를 전환하고 지역 필터를 선택한다. 인프라 지도(`/map`)도 휴대폰·태블릿에서 흰 상단 바 없이 지도를 화면 위까지 쓰고, 지도 위 검색창 왼쪽에 같은 흰 원형 뒤로가기를 둔다(데스크탑은 공용 헤더 로고로 홈에 가므로 숨긴다). 동네 찾기 지도(`/neighborhoods/map`)도 검색창 안쪽 뒤로가기 대신 검색창 왼쪽에 같은 흰 원형 뒤로가기(조건 선택으로 돌아감)를 둔다. 데스크탑에서는 두 지도 화면 모두 검색창(동네 찾기는 뒤로가기 포함)을 지도 위가 아닌 공용 헤더 가운데 자리로 옮겨 회색 칸으로 그린다. 이를 위해 `DesktopHeader`는 가운데에 빈 자리를 두고, 화면은 `DesktopHeaderSlot`으로 감싼 요소를 데스크탑 헤더가 있으면 그 자리로 옮겨(portal) 그리고, 없으면(휴대폰·태블릿, 공개 탐색) 제자리에 그린다. `PropertyAppLayout`이 `DesktopHeaderSlotProvider`로 헤더와 화면을 함께 감싼다. 리스트는 인프라 지도 매물 목록과 같은 공용 `PropertyCard`(사진·이름·보증금/월세·주소·현장 체크 진행 막대)로 그리고, 오른쪽 위에 더보기 메뉴(삭제)를 `actions`로 붙인다. 데스크탑에서는 리스트·지도에서 고른 매물을 주소(`/properties/:propertyId`)로 정하고, 같은 기록 화면이 상세 화면 대신 리스트 자리에 상세를 연다. 상세를 닫으면 `/properties`로 돌아간다. 진행 막대 끝의 완료 개수(예: `0/4`)는 두지 않는다. 휴대폰·태블릿의 동네 뱃지 줄은 헤더와 0.6rem 띄운다. 휴대폰·태블릿의 지도 보기에서는 헤더와 동네 뱃지를 흰 배경 없이 지도 위에 띄우고, 빈 자리는 지도 조작을 막지 않는다. 뒤로가기(흰 원형 버튼)와 지도·리스트 전환은 흰 바탕·연한 테두리·그림자로 지도 위에서도 잘 보이게 하며, 지도와 리스트를 오가도 모양과 위치가 바뀌지 않는다. 리스트와 선택 매물 카드에서는 기존 MSW 응답의 대표 사진을 미리보기로 표시하며, 사진이 없는 기록은 빈 사진 상태로 표시한다. 지도 마커를 누르면 선택한 방의 사진, 이름, 가격, 주소, 체크 진행 상태를 지도 아래 요약 카드로 보여준다. 카드에서 상세 화면으로 이동할 수 있고 닫기 버튼으로 카드를 숨긴다. 리스트 메뉴의 삭제는 기존 매물 삭제 API를 호출한다. 지도 마커 위에는 제목과 숫자 금액을 핀에 붙은 고정 크기 라벨로 표시하며, 긴 텍스트는 말줄임 처리한다. 지도는 기존 MapCanvas를 사용한다. 리스트 항목을 누르면 기존 매물 상세 페이지로 이동한다. 상세 화면은 바텀탭을 숨기고 뒤로가기 화살표 오른쪽에 매물 이름을 왼쪽 정렬로 표시하는 헤더 바로 아래에 `정보 / 체크리스트` 탭을 제공한다. 정보 탭에서는 대표 이미지와 매물 정보를 표시하고 매물 이름도 다시 크게 보여주며 매물명 옆 삭제 메뉴를 유지한다. 체크리스트 탭에는 대표 이미지를 표시하지 않고 체크 상태·메모를 이 화면에서 바로 확인하고 수정할 수 있게 한다. 정보 탭의 기본 정보·부가 정보 `편집`은 별도 수정 화면으로 넘어가지 않고, 상세 위에 어두운 배경과 함께 높이를 끌어 바꿀 수 없는 바텀시트(동네 찾기 필터 시트와 같은 `BottomSheet`의 `resizable={false}`)를 띄워 그 안에서 고친다. 기본 정보 시트는 새 매물 등록과 같은 이름·보증금·월세 입력과 주소 검색·지도 위치 선택을 두고, 지도를 옮기거나 주소를 고른 경우에만 위치를 바꿔 보낸다. 부가 정보 시트는 부가 정보 화면(`/properties/:propertyId/memo`)과 같은 입력 폼(`PropertyAdditionalInfoForm`)을 쓴다. 저장하면 시트를 닫고 상세 값에 바로 반영하며, 닫기·Escape·바깥 배경을 누르면 저장하지 않고 닫는다. 상세 화면의 뒤로가기는 진입한 홈 또는 기록 지도·리스트 화면으로 돌아간다. `기록하기` 버튼은 기존 매물 등록 화면(`/properties/new`)으로 이동한다.

홈·지도·리스트는 기존 매물 목록 조회(`usePropertyList`, `GET /api/properties`)와 매물 파서를 그대로 사용한다. 별도 예시 매물·가격·좌표를 만들지 않는다. 지역은 응답 주소의 동·읍·면, 없으면 구·군·시로 구분하며 좌표 없는 기록은 리스트에서만 보여준다. 이름·금액·주소·체크 진행률도 응답 그대로 표시한다. 홈의 최근 기록을 불러오지 못하면 이미지 자리(이미지는 이후 넣는다)와 `기록을 불러오지 못했어요.` 안내, 공용 `Button`으로 된 `다시 시도` 버튼을 가운데에 세로로 보여준다. 홈의 최근 기록은 `전체 보기` 없이 최신 5개만 옆으로 이어서 보여주고, 체크 진행 현황 없이 사진·이름·금액·주소만 표시한다. 최근 기록 카드는 동네 찾기 TOP5와 같은 공용 `HorizontalRail`로 가로로 넘기며, 레일은 본문 좌우 여백을 넘어 화면 끝까지 이어져 다음 카드가 잘려 보인다.

휴대폰 홈의 기능 카드는 제목 1.2rem·설명 0.78rem으로 두고 글자 위·왼쪽 여백은 1.25rem, 대표 카드 글자는 1.5rem 띄워 조금 아래에서 시작한다. 태블릿(화면 너비 768px 이상)부터 홈은 카드가 넓어지는 만큼 기능 카드 높이를 30rem으로 늘리고 카드 글자와 글자 안쪽 여백을 키우며(제목 1.5rem·설명 0.95rem, 대표 카드 제목 2.3rem·설명 1.05rem, 위·왼쪽 여백 1.6rem. 데스크탑도 같다), 기능 카드·빠른 메뉴 배치는 모바일과 같게 두고(빠른 메뉴 타일은 칸이 넓어져도 5.5rem을 넘지 않는다), 본문 폭을 최대 45rem으로 넓히며 최근 기록은 그 아래에 둔다. 바탕은 흰색이다. 1024px 이상 화면(데스크탑, 아이패드 큰 화면)은 본문을 64rem 폭 안에 두고, 헤더는 다른 화면과 같은 공용 `DesktopHeader`를 화면 전체 폭으로 두며, 안내 문구는 두 열에 걸쳐 두되 전체 폭의 2/3로 줄여 가운데에 두고, 그 아래 왼쪽에 기능 카드를, 오른쪽 19rem 열에 빠른 메뉴 타일 2개와 최근 기록을 둔다. 기능 카드 글자 크기·여백은 태블릿과 같다(공통 `ActionCard`는 글자 크기를 CSS 변수 `--action-card-title-size`·`--action-card-description-size`·`--action-card-large-title-size`·`--action-card-large-description-size`로 받고, 주지 않으면 기존 크기를 쓴다). 오른쪽 열은 기능 카드 위쪽에 맞춰 시작하고, 빠른 메뉴 타일은 사용방법 카드 높이를 넘지 않도록 5rem으로 두며 빈칸은 그리지 않는다. 최근 기록은 모바일과 같은 크기·비율의 카드를 두 줄로 놓아 위에서 아래로 채운다. 기록 화면은 태블릿에서 배치를 바꾸지 않고 본문 폭을 최대 48rem까지 넓히며 글자·여백만 키운다. 데스크탑 기록 화면은 바깥 테두리 없이 화면 전체를 쓰며 왼쪽에 리스트, 오른쪽에 지도를 나란히 보여주므로 지도·리스트 전환을 숨긴다. 로고 옆에는 지금 화면 이름을 띄우지 않고, `본 방 기록` 제목은 화면 낭독기에서만 읽힌다. 헤더는 공용 `shared/ui/desktop-header/DesktopHeader`를 쓴다. 왼쪽 위에는 뒤로가기 대신 오리 로고를 두어 누르면 홈으로 가고, 제목 오른쪽 끝에는 `본 방 기록`·`인프라 지도`·`동네 찾기`·`체크리스트`·`방 비교`로 바로 가는 메뉴를 두어 마우스를 올리면 살짝 둥근 네모로 옅게만 표시하고 지금 화면은 파란 글자(`--color-brand-blue`)로 표시하며, 맨 오른쪽에는 홈 헤더와 같은 프로필 아이콘(`shared/assets/icon-profile.webp`)으로 마이페이지(`/me`)에 가는 링크를 둔다. 동네 뱃지는 오른쪽 지도 위에 띄우고, `기록하기` 버튼은 지도 오른쪽 아래에 둔다. 데스크탑에서 `기록하기`를 누르면 매물 등록 화면으로 넘어가지 않고, 왼쪽 리스트 자리에 기존 매물 등록 화면(`CreatePropertyPage`)을 연다. 닫기 버튼은 등록을 닫고 리스트로 돌아가며, 등록을 마치면 새 매물을 선택하고 `매물을 기록했어요.` 안내를 띄운다. 데스크탑에서 지도나 리스트의 방을 누르면 상세 화면으로 넘어가거나 지도 아래 요약 카드를 띄우지 않고, 왼쪽 리스트 자리에 기존 매물 상세 화면(`PropertyDetailPage`)을 바로 보여준다. 상세의 뒤로가기는 리스트로 돌아가고, 상세에서 매물을 삭제해도 리스트로 돌아간다. 이를 위해 `PropertyDetailPage`는 `panel`(`propertyId`·`onClose`)을 받으면 주소의 매물 ID 대신 받은 ID를 보여주고 뒤로가기·삭제 뒤 이동 대신 `onClose`를 부르며, 매물 등록·상세 화면 모두 패널로 열면 `main` 대신 `div`로 그린다. 이를 위해 `CreatePropertyPage`는 `panel`(`onClose`·`onCreated`)을 받으면 버튼을 화면 맨 아래 대신 패널 스크롤 영역 아래에 붙이고, `usePropertyCreationForm`은 `onCreated`가 있으면 상세 화면으로 이동하지 않는다.

로그인 뒤 화면은 모두 바텀탭 없이 연다. 웹 하단 주요 메뉴를 그리지 않고, 네이티브 탭바를 지원하는 앱에도 탭바를 숨기라고 알리며 탭바 자리 여백을 두지 않는다. 기존 앱 화면(지도·동네 찾기·체크리스트·방 비교·마이·매물 상세 등) 가운데 자체 상단 내비게이션이 없는 화면에는 홈(`/`)으로 돌아가는 뒤로가기 화살표만 있는 상단 바를 붙이되, 마이·방 비교와 동네 찾기 지도(`/neighborhoods/map`)에는 붙이지 않는다. 매물 상세의 뒤로가기는 홈에서 들어오면 홈으로, 지도 카드에서 들어오면 지도로, 그 밖에는 본 방 기록 화면으로 돌아간다. 상세에서 매물을 삭제하면 돌아간 화면의 제목(`본 방 기록`)으로 포커스를 옮긴다. 기존 화면의 카드 표면은 테두리 없는 회색 카드로 맞춘다.

홈에서 이어지는 다른 화면(인프라 지도·동네 찾기·체크리스트·방 비교·마이·매물 화면 등, `PropertyAppLayout` 아래 화면)도 태블릿·데스크탑에 맞춘다. 태블릿(768px 이상)부터는 휴대폰 폭(24.375rem)에 가두지 않고, 지도 화면(`/map`, `/neighborhoods/map`)은 화면 전체를, 나머지 화면은 48rem 가운데 열을 쓴다(`--app-max-width`를 48rem으로 바꿔 화면 아래 고정 버튼도 같은 폭을 따른다). 데스크탑(1024px 이상)에서는 모든 화면 위에 기록 화면과 같은 `DesktopHeader`를 두고 휴대폰용 홈 버튼 줄은 숨기며, 지도가 아닌 화면의 내용은 48rem 가운데 열에 둔다. 지도 위 패널은 넓은 화면을 가로지르지 않게 한다. 공용 `BottomSheet`(동네 찾기 필터 등)는 태블릿부터 30rem 폭으로 가운데에 띄우고, 인프라 지도의 매물 시트는 태블릿에서 30rem 가운데에 두고, 데스크탑에서는 시트 대신 지도 왼쪽 28rem 칸에 고정 목록으로 둔다. 동네 상세는 데스크탑에서 지도 전체를 덮지 않고 왼쪽 28rem 패널로 연다. 공개 동네 탐색(`/explore`)도 태블릿부터 화면 전체를 쓴다.

로그인 화면(`/login`)도 같은 디자인으로 바꾼다. 모든 화면 너비에서 최대 29rem 폭의 한 열을 가로 가운데에 두고, 위에서부터 오리 로고, 홈의 매물 기록 카드처럼 노란 바탕(`--color-card-brand-surface`)에 흰 글자로 `자취선배 시작하기`와 한 줄 안내를 둔 카드, 닉네임·비밀번호 입력, 입력 오류 안내, 파란색(`--color-brand-blue`) `이름으로 시작하기` 버튼, 비밀번호를 비울 때의 공유 안내를 쌓는다. 개인정보 안내만 화면 맨 아래에 붙인다. 닉네임과 비밀번호 칸은 보이는 라벨 없이 placeholder만 두고 0.5rem 간격으로 가까이 붙여 한 묶음으로 보이게 한다. 안내 카드와 입력 사이는 4.5rem 띄운다. 카드 제목은 한 줄로 두고, 맨 아래 개인정보 안내는 설명과 링크를 두 줄로 나눈다. 글자 크기는 당근 로그인 화면(SEED 디자인 시스템)에 맞춰 제목 26px, 안내·입력 16px, 버튼 18px, 도움말·공유 안내·개인정보 안내 14px로 두고, 입력칸과 버튼 높이는 52px, 모서리는 12px로 둔다. 라벨은 화면 낭독기에서만 읽힌다. 버튼 색은 마우스를 올리면 부드럽게 어두워진다. 안내 카드에는 사용방법 카드의 오리(`guide-goose.webp`)가 오른쪽 아래에서 고개를 내밀며 들어온다(움직임 줄이기 설정에서는 움직이지 않는다). 입력은 공용 `TextField`의 새 `filled` 변형을 쓴다. 로그인 동작은 그대로이고, 로그인 후에는 홈(`/`)으로 이동한다.

`매물 기록하기` 카드는 노란색(`--color-brand-yellow`) 배경에 흰색 제목과 그 아래 작은 설명(`직접 본 매물을 기록해요`)을 두고, 노트·연필·집 3D 이미지(`pages/design-home/assets/record-*.webp`)를 각각 왼쪽 아래·왼쪽 위·오른쪽에 카드 가장자리에서 조금씩 잘리도록 둔다. 화면에 처음 그려질 때는 노트·연필·집 순서로 위에서 투명하게 내려와 반동 없이 제자리에 멈추며 나타나고, 마우스를 올리거나 키보드로 포커스하거나 손가락으로 누르면 연필은 아래로 내려가며 크게 기울고, 노트는 제자리에서 왼쪽으로 돌고, 집은 살짝 떠오르며 기운다. 움직임 줄이기 설정에서는 움직이지 않는다. 이미지 자산을 쓰기 위해 웹팩 이미지 규칙과 타입 선언에 `webp`를 추가했다. 이미지 규칙은 `asset/resource`로 두어 작은 이미지도 `data:image` URI로 번들에 넣지 않고 별도 파일 URL로 내보낸다.

인프라 지도·동네 찾기 카드, 체크리스트·방 비교 타일, 마이페이지 버튼은 같은 톤의 3D 이미지(`pages/design-home/assets/*.webp`, 마이페이지 아이콘은 데스크탑 공용 헤더도 쓰므로 `shared/assets/icon-profile.webp`)를 쓴다. 원본(1254px)에서 화면 표시 크기의 2배 정도로 줄여 WebP로 변환했다(카드 320px, 타일 192px, 마이페이지 96px). 카드 이미지는 오른쪽 아래 가장자리에 조금 걸치게 두고 마우스를 올리면 살짝 떠오르며 기운다.

`사용방법 알아보기` 카드는 부리보다 채도를 조금 낮춘 파란색(`#6b9ae6`) 배경에 흰색 제목을 휴대폰에서는 두 줄, 태블릿부터는 한 줄로 두고, 투명 배경 오리 이미지(`pages/design-home/assets/guide-goose.webp`, 200px)가 오른쪽 아래 가장자리에서 고개를 내밀도록 둔다. 처음 그려질 때는 오리가 카드 아래 밖에 있다가 0.3초 뒤 고개를 내밀며 들어오고(움직임 줄이기 설정에서는 움직이지 않는다), 마우스를 올리면 오리가 살짝 떠오르며 기운다.

홈의 카드와 바로가기 타일은 공통 컴포넌트로 만든다.

- `shared/ui/action-card/ActionCard`: 제목·설명과 3D 그림이 있는 기능 카드다. `tone`(`neutral`·`brand`·`informative`)으로 바탕색과 글자색을, `size`(`medium`·`large`)로 제목 크기를 정한다. 그림은 `illustration`에 넣고, 보통 `ActionCardIllustration`의 `placement`(`corner`는 오른쪽 아래 모서리에 걸침, `peek`는 아래 가장자리에서 고개를 내밂)로 놓는다. 화면 이동이면 `to`로 링크를, 동작이면 `onClick`으로 버튼을 그린다.
- `shared/ui/rail-card/RailCard`: `HorizontalRail`에 넣는 카드의 동작만 맡는 틀이다. `to`(와 라우터 `state`)를 주면 이동 링크를, `onSelect`·`selected`·`disabled`를 주면 눌림 상태가 있는 선택 버튼을 그리고 포커스·눌림·선택·비활성 표시를 맞춘다. 모양은 children과 `className`으로 정하므로 홈의 최근 기록 카드(사진 위·정보 아래)와 동네 찾기 순위 카드(`RankedCard`)가 같은 틀에 다른 내용을 넣는다.
- `shared/ui/shortcut-tile/ShortcutTile`: 정사각형 아이콘 타일과 이름으로 된 바로가기다. 타일 크기는 놓인 그리드 칸 너비를 따르고, `to`·`onClick` 규칙은 `ActionCard`와 같다.

색과 모서리는 `app/styles/tokens.css`의 토큰으로 묶어 한곳에서 바꾼다. 보조 브랜드색 `--color-brand-blue`, 카드 표면 `--color-card-surface`·`--color-card-surface-hover`, 톤별 카드 표면 `--color-card-brand-surface`·`--color-card-informative-surface`와 그 위 글자색 `--color-on-card-accent`, 화면 바탕 `--color-page-subtle`, 가격 강조 `--color-price`, 모서리 `--radius-card`·`--radius-tile`을 추가했고 글자·테두리·보조 글자·포커스는 기존 토큰을 쓴다.

홈 맨 아래 푸터(`ui/HomeFooter`)에는 한 줄 소개(`본 방의 기록이, 내 방을 고르는 기준이 되도록.`), `서비스 소개`(`/about`)·`개인정보·광고 측정 안내`(`/privacy`) 링크, `© 2026 자취선배`를 위쪽 구분선과 함께 둔다. 모바일·태블릿은 가운데 정렬, 가로 데스크탑은 64rem 폭에 왼쪽 정렬한다.

두 열 배치, 4칸 빠른 메뉴와 빈칸처럼 홈에만 있는 레이아웃은 재사용하기 어려워 `pages/design-home`에 둔다. 매물 기록 카드의 노트·연필·집 장면은 `ui/RecordCard`, 로고와 마이페이지 링크는 `ui/HomeHeader`, 빠른 메뉴는 `ui/QuickMenu`에서 만든다. 기능 카드 묶음은 `ui/HomeFeatures`에 두어 휴대폰·데스크탑 홈이 함께 쓴다.

## 데스크탑·휴대폰 화면 나누기

데스크탑(1024px 이상)과 휴대폰·태블릿 화면은 주소를 나누지 않고 같은 주소에서 페이지 파일만 나눈다. 라우트가 가리키는 페이지 파일은 공용 `useIsDesktop()`(`shared/lib/hooks/useIsDesktop`, 기준 `DESKTOP_MEDIA_QUERY`)으로 데스크탑 화면과 휴대폰 화면 가운데 하나를 한 번만 고르고, 데이터·상태는 공용 훅으로, 카드·필터·메뉴 같은 조각은 공용 컴포넌트로 함께 쓴다. 각 화면과 조각 안에서는 1024px 미디어 쿼리나 `isDesktop` 분기를 쓰지 않고, 화면마다 다른 모양은 그 화면 파일의 CSS나 조각의 속성(예: `RecentRooms`의 `inSideColumn`, `HomeFooter`의 `alignStart`)으로 정한다. 태블릿은 휴대폰 화면을 그대로 쓰고 CSS(768px 미디어 쿼리)로 폭·글자만 키운다. 데스크탑 화면 CSS가 공용 CSS를 덮어쓸 때는 화면 루트 클래스(`.root`) 아래로 한정해 불러오는 순서와 상관없이 이기게 한다.

| 주소          | 고르는 파일                            | 데스크탑                                                  | 휴대폰·태블릿                             | 함께 쓰는 것                                                                                                              |
| ------------- | -------------------------------------- | --------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `/`           | `design-home/DesignHomePage`           | `desktop/HomeDesktopPage`                                 | `mobile/HomeMobilePage`                   | `ui/HomeFeatures`·`QuickMenu`·`RecentRooms`·`HomeFooter`                                                                  |
| `/properties` | `design-records/DesignRecordsPage`     | `desktop/RecordsDesktopPage`                              | `mobile/RecordsMobilePage`                | `hooks/useRecords`, `ui/record-list`·`record-districts`·`records-map`·`record-notice`                                     |
| `/map`        | `map/MapPage`                          | `desktop/MapDesktopPage`                                  | `mobile/MapMobilePage`                    | `hooks/useMapPage`, `ui/map-stage`·`map-property-list`(바텀시트 `map-property-sheet`, 데스크탑 목록 `map-property-panel`) |
| `/compare`    | `property-compare/PropertyComparePage` | `desktop/CompareDesktopPage`(표 `ui/compare-table`, 필터) | `mobile/CompareMobilePage`(이어진 리스트) | `hooks/usePropertyComparison`, `ui/compare-load-state`·`compare-empty`·`compare-action-bar`                               |

지도 검색창처럼 데스크탑 헤더로 옮겨 그리는 요소는 화면 너비가 아니라 헤더 자리가 있는지(`useHasDesktopHeaderSlot`)로 모양을 정한다. 앱 공용 틀(`PropertyAppLayout`)과 아직 나누지 않은 동네 찾기 지도는 미디어 쿼리를 그대로 쓴다.

시안 이미지는 저장소 루트가 아닌 프론트엔드 폴더 안에서 관리한다. 화면 한 곳에서만 쓰는 이미지는 해당 페이지의 `assets/`에, 아직 화면에 붙이지 않은 홈·지도·안내 아이콘과 동네 순위(1~5위) 이미지는 `shared/assets/illustrations/`에 192px WebP로 둔다. 순위 이미지는 동네 찾기 결과의 TOP5 카드(`RankedCard`)에서 숫자 대신 쓴다. 비교할 매물 선택(`/compare`)은 매물마다 떨어진 카드 대신 한 상자 안에 얇은 구분선으로 이어진 리스트로 두고, 선택한 매물은 옅은 파란 바탕과 파란 체크로 표시한다. `기록 비교 PDF` 안내 카드는 없앴다. 데스크탑에서는 화면 위 `비교할 매물 선택` 헤더를 두지 않고(공용 헤더가 있다), 리스트 바로 위 줄 왼쪽에 선택 개수, 오른쪽에 가로 필터(매물 이름 검색, 월세 전체·50만·70만·100만 이하, 체크리스트 전체·시작함·시작 전, 결과 개수)를 둔다. 필터는 매물 표에 보일 매물만 좁히고 이미 고른 매물 선택은 그대로 둔다(`lib/compareFilters`). PDF 받기 버튼은 모든 화면에서 아래에 고정한다. 표는 관리 화면처럼 회색 머리글 줄(매물·보증금 / 월세·발견 경로·체크 진행)과 짝수 줄 줄무늬를 두고, 매물 한 줄을 체크·작은 사진·각 칸 값으로 나란히 놓는다(발견 경로가 없으면 `—`). 데스크탑(1024px 이상) 홈도 홈 전용 헤더 대신 다른 화면과 같은 공용 `DesktopHeader`(로고·주요 화면 메뉴·마이페이지)를 쓴다. 홈의 최근 기록한 방은 매물 주소(`/properties/:propertyId`)로 간다. 데스크탑은 그 주소에서 본 방 기록 화면이 그 매물을 고른 채로 열려 왼쪽에 상세를 보여 주고, 휴대폰·태블릿은 상세 화면을 연다. 본 방 기록 지도도 동네 찾기 지도와 같은 네이버 사용자 지정 스타일(`features/map/lib/mapStyle`의 `SERVICE_MAP_STYLE_ID`)을 쓴다. 기록 리스트와 인프라 지도 매물 목록은 불러오는 동안 실제 줄 모양의 스켈레톤을 보여 준다. 데스크탑 인프라 지도는 바텀시트 대신 기록 화면처럼 왼쪽 28rem 칸에 매물 목록을 늘 펼쳐 두고 지도를 오른쪽에 두며, 주소 검색 결과도 그 왼쪽 칸에 띄운다. 매물 상세는 화면마다 주소를 따로 둔다. 기록 화면에서 연 매물은 `/properties/:propertyId`, 인프라 지도 목록에서 연 매물은 `/map/:propertyId`이며, 상세 내용은 같은 `PropertyDetailPage`를 쓴다. 데스크탑 `/map/:propertyId`는 지도를 떠나지 않고 왼쪽 칸에 상세를 열고 뒤로가기로 `/map` 목록에 돌아온다. 휴대폰·태블릿 `/map/:propertyId`는 지도로 돌아가는 상세 화면을 연다(주소로 바로 들어와도 지도로 돌아간다). 기록 리스트 위의 `모든 기록 · N곳` 줄은 화면에서 빼고 화면 낭독기용 제목만 남기며, 그 자리에 `최근순`·`월세`·`체크 진행` 필터 칩과 `필터 준비 중` 표시를 둔다(아직 기능 구현 전이라 칩은 누를 수 없게 막아 둔다).

공용 `TextField`의 기본 모양은 `filled`(회색 채움형)다. 로그인 화면에서 만든 모양을 공용 기본값으로 올려 매물 등록·상세 수정 시트·체크리스트 편집 등 모든 입력칸에 쓴다. 카드형 홈의 회색 면(`--color-card-surface`)에 12px 모서리를 쓰고 테두리는 두지 않으며, 기본 높이 48px·글자 15px, `fieldSize="large"`는 높이 52px·글자 16px이다. 라벨은 칸 위에 15px 중간 굵기로 둔다. 포커스하면 칸 안쪽에 노란 선(`--color-brand-yellow`)을 두르고 커서는 파란색(`--color-brand-blue`)으로 둔다. 오류면 빨간 선을 두르고, 칸 아래에 빨간 원형 느낌표와 함께 오류 문구를 보여 주며 화면 낭독기에 바로 알린다(`role="alert"`). 채움형은 라벨을 칸 위에 고정하므로 `floatingLabel`을 무시하고, 예전 밑줄 모양(`underline`)·네모 테두리(`box`)는 `variant`로 고르면 그대로 쓸 수 있다.

체크 상태 색은 `app/styles/tokens.css`의 `--color-check-*` 토큰에서 괜찮음을 브랜드 파랑(`--color-brand-blue`, 글자 #3f6fc4), 주의를 빨강(#ef7b7b, 글자 #d14d4d), 미확인을 회색(#c6c6c6)으로 바꿔, 기록 리스트의 진행 막대와 체크리스트 상태 선택에 함께 쓴다. 사진이 없는 매물의 대체 이미지는 비교할 매물 선택과 인프라 지도 매물 카드에서도 새 로고(`shared/assets/jachwi-sunbae-goose.webp`)를 쓴다. 데스크탑 공용 헤더는 격자 대신 가로 줄로 배치해, 가운데 검색창이 있는 지도 화면과 없는 화면을 오가도 메뉴·마이페이지 위치가 바뀌지 않는다.

태블릿·데스크탑에서는 지도가 아닌 앱 화면(체크리스트·방 비교·마이·매물 화면 등, `PropertyAppLayout` 아래 화면)이 열려 있는 동안 기준 글자 크기(rem)를 태블릿 112.5%, 데스크탑 125%로 올려 휴대폰 기준으로 잡힌 글자와 여백을 같은 비율로 키운다(`html:has(...)`). 홈·기록 화면·지도 화면은 각자 크기를 따로 잡으므로 바꾸지 않고, 공용 데스크탑 헤더는 글자 크기를 16px로 고정하고 안쪽 크기를 em으로 잡아 어느 화면에서나 같은 크기로 보인다.

공용 `Button`의 `primary`는 검은 바탕·노란 글자에서 파란 바탕(`--color-brand-blue`)·흰 글자로 바꿨다. 모든 버튼은 12px 모서리와 700 굵기를 쓰고, 색이 바뀔 때 0.18초 동안 부드럽게 바뀐다. 로그인처럼 화면의 주 행동 버튼은 `size="large"`(높이 52px·글자 18px)로 쓴다.
