# Maze 웹사이트 사용성 테스트

## 설치 범위

`frontend/index.html`의 공통 head에 Maze 팀 전용 공개 스니펫을 설치한다. 정확히
`https://www.jachwi-sunbae.kr`에서만 비동기 로더를 실행한다. dev·localhost·Storybook은
대상이 아니다. React 라우트별로 다시 설치하지 않는다. PostHog 설정과 인증 흐름은 변경하지 않는다.

스니펫의 팀 식별 키는 브라우저에 노출되는 공개 설치 값이며 서버 비밀 키가 아니다.
Maze가 안내한 스니펫의 저장소 예외 처리와 nonce 전달을 유지한다. 별도 npm 의존성은 없다.

## 배포 후 연결 확인

1. 운영 배포에 이 변경을 포함한다. develop 병합만으로 운영에 반영되지는 않는다.
2. [Maze 팀 설정](https://app.maze.co/team?tab=connected_websites)에서 자취선배 사이트의 설치 단계를 이어서 Verify한다.
3. Website Test를 만들고 시작 URL을 지정한다. 첫 진입부터 확인하려면 `/`(자동 로그인 뒤 홈), 사용 방법부터 확인하려면 `/guide`를 사용한다.
4. 게시 전 미리보기에서 동일 탭 안의 로그인·탐색·등록 흐름을 직접 수행하고 결과의 클릭·경로 수집을 확인한다.

코드를 추가했다고 연결 검증이나 사용성 테스트가 완료되는 것은 아니다. 운영 배포 전에는
Verify 성공으로 기록하지 않는다. 일반 방문자 대상 in-product prompt, Clips와 화면 녹화는
이 변경에서 생성하거나 활성화하지 않는다. 별도 동의 팝업도 추가하지 않는다.

## 테스트 설계와 데이터 취급

- 동네 찾기, 월세 거래 내역 확인, 매물 기록 과제를 각각 만들고 버튼 이름이나 클릭 순서는 알려주지 않는다.
- 운영 서비스에서 실제 데이터가 생성·수정되므로 테스트 전용 계정을 사용하고 삭제 범위를 미리 정한다.
- 로그인은 우회하지 않는다. 참가자는 테스트 창 안에서 로그인하며 외부 인증 페이지의 행동은 수집되지 않을 수 있다.
- 입력·개인정보의 스크린샷 익명화 옵션을 확인한다. Clips 녹화에는 같은 익명화가 적용되지 않으므로 임의로 켜지 않는다.
- 설치 자체가 모든 일반 방문자를 상시 녹화한다는 뜻은 아니다. 과제에 참여한 사용자의 결과를 Maze에서 분석한다.
- 별도 팝업 미추가가 개인정보 고지·동의 의무 면제를 의미하지는 않는다. 실제 수집 항목에 맞춰 기존 개인정보 안내를 검토한다.
- PostHog에서 테스트 트래픽을 제외하려면 참가 기기별 기존 `analytics_test=1` 표시를 사용한다. Maze 설치가 자동으로 테스트 사용자를 제외하지 않는다.

## 중단과 문제 확인

Maze 연결을 제거하려면 공통 HTML의 Maze script 블록을 제거하고 운영에 재배포한다.
사이트 로딩을 막지 않는 비동기 로딩이며, 실패 시 Maze 테스트 기능이 사용할 수 없는지 별도로 확인한다.
CSP 또는 광고 차단으로 막히면 브라우저 콘솔을 확인한다. CSP를 통째로 해제하지 않고 공식 문서의
필요 도메인을 검토한다. 이 변경은 CDN·서버 보안 정책을 변경하지 않는다.
