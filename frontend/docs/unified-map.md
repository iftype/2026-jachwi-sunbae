# 통합 지도

회원 지도는 `/properties`와 `/neighborhoods`를 같은 `UnifiedMapPage`에서 연다. 데스크톱은 왼쪽 네비 레일로, 휴대폰과 앱은 위쪽 검색 영역의 모드 버튼으로 화면을 옮긴다. `/landing`과 공개 탐색 `/explore`는 별도 진입점이다.

## 화면과 이동

- 데스크톱의 인증 후 `/`는 `/properties`로 이동한다. 휴대폰과 앱의 홈은 유지한다.
- 데스크톱은 맨 왼쪽에 폭 76px의 네비 레일(`NavRail`)을 둔다. 칸은 `본 방 기록하기`, 내 기록, 동네 찾기, 체크리스트, 방 비교, 저렴한 한 끼, 마이, 사용방법이고(`navRailItems`), 사용방법은 맨 아래에 붙인다. 지도 밖 화면(체크리스트, 방 비교, 저렴한 한 끼, 사용방법)도 같은 레일을 쓴다(`PropertyAppDesktopLayout`, `DesktopRailShell`). 코드를 받는 동안 뼈대도 같은 폭의 자리 표시를 둔다.
- 목록 패널은 지도에 붙여 두고 떠 있게 하지 않는다. 상세는 지도 칸을 늘리지 않고 지도 왼쪽 위에 얹으며(`ListDetailLayout`), 접는 버튼은 `<` 화살표다.
- 기록의 주소 검색은 목록 상단에 둔다. 동네 찾기는 검색 화면을 거치지 않고 지도로 바로 열고, 데스크탑은 왼쪽 조건 카드에서 출퇴근 장소(`지도에서 선택`), 통근 시간과 환승 횟수를 고른다. 이미 검색한 뒤에는 조건을 바꿨을 때만 `다시 검색`을 보인다. 왼쪽 위 검색은 지도를 그 주소로 옮기기만 한다(`moveMapTo`). 월세는 결과 지도 안 슬라이더로 바꾸며 검색한 뒤에도 받아 둔 결과에서 바로 적용한다. 찾은 동네는 지도 위 뱃지 줄로 보고, 줄 앞의 `다시 뽑기` 칩으로 출퇴근 장소를 다시 고른다.
- 직접 매물과 동네 상세 URL로 들어올 수 있다. 모드 버튼은 각 모드에서 마지막으로 열었던 URL로 이동하고 브라우저 뒤로가기도 처리한다.
- 휴대폰의 지도와 리스트 전환, 매물 요약 시트, 동네 정보 시트와 상세 화면의 자체 내비게이션은 유지한다. 모드 버튼 영역과 시트는 안전 영역을 비운다.

## 동네 북마크

동네 찾기 결과에서 동을 누르면 뜨는 요약 마커의 `북마크하기`로 행정동을 북마크하고, 내 기록 지도의 `찜한 동네` 버튼으로 북마크한 동네의 경계를 칠한다. 찜한 동네가 있으면 기본으로 켜지고(켜고 끈 값을 고른 뒤에는 그 값을 따른다), 없으면 버튼이 비활성이다. 칠한 영역을 누르면 그 자리의 카드에서 찜을 해제하고, 영역 아래에 기록이나 메모 마커가 있으면 그 말풍선이 먼저 열린다. 동네 찾기에서 이 버튼을 켜 두면 출퇴근 장소 핀만 남기고 주변 마커를 걷는다. API 클라이언트는 `features/map/api/adminDongBookmarkApi.ts`, 낙관적 갱신은 `useAdminDongBookmarks`, 경계 변환은 `useBookmarkedRegions`가 맡는다. 개발용 MSW 목업은 `app/mocks/handlers/adminDongBookmarkHandlers.ts`다. 서버 API는 백엔드 PR #712가 병합된 뒤에 동작한다.

## 상태와 지도 수명

`SharedMapCanvasProvider`가 실제 `MapCanvasSurface`와 Naver SDK 인스턴스를 소유한다. 기록과 동네 찾기는 `MapCanvas shared` 슬롯에 활성 모드의 지도 설정만 전달한다. 같은 포털 컨테이너를 활성 슬롯으로 옮겨 모드와 화면 폭이 바뀌어도 실제 지도를 다시 마운트하지 않는다. 매물 상세 안의 작은 주변 지도는 공유 슬롯에 참여하지 않는다.

두 모드의 화면 상태는 전환 중에도 유지한다. 기록 데이터와 선택, 동네 필터, 거리 메모는 공통 Hook에 두고 데스크톱과 휴대폰 화면이 함께 사용한다. 목적지 선택 지도와 결과 지도의 시점은 각각 기억한다. 패널이 가리는 공간은 매물 초점 이동과 동네 및 경로 fit 계산에 반영한다.

동네 찾기의 편집 중 목적지와 조건은 제출한 검색과 분리한다. 입력하거나 통근 조건을 고르는 동안 기존 통근 결과를 다시 요청하거나 저장된 검색을 지우지 않는다. `이전 결과 보기`는 제출한 조건과 결과로 돌아간다. 제출할 때 새 조건으로 조회하며, 같은 조건으로 제출해도 다시 조회한다. 월세는 받은 결과에서 거른다. 주소 응답은 위치 선택의 요청 순서로 검증하고 통근 결과는 조건별 Query 키와 AbortSignal로 분리한다. 오류의 `다시 시도`는 같은 검색을 재시도하고, 조건 변경도 제공한다.

## 지도 조작

일반 상태에서는 지도 이동과 확대를 우선한다. `기록 위치 선택` 또는 `지도에서 목적지 선택`을 켠 뒤 탭해야 새 위치를 고른다. 기존 매물과 메모 마커, 패널과 목록 조작은 그대로 사용할 수 있다. 취소 버튼과 Escape로 위치 선택을 끈다.

`mapTapGuard`는 포인터가 8px 넘게 움직이거나 둘 이상 눌리면 위치 선택을 막는다. 취소, 드래그와 확대 종료 직후 SDK가 보내는 클릭도 400ms 동안 거른다. 이벤트를 관찰하므로 지도 전체의 기본 동작을 막지 않는다. 목록과 상세 스크롤은 지도 DOM의 바깥에서 처리한다.

## 검증

- `SharedMapCanvas.test.tsx`: 모드와 반응형 슬롯 교체 시 실제 지도와 DOM 수명 유지
- `AppRoutes.test.tsx`: 데스크톱 홈 이동과 모드별 URL, 같은 지도 DOM 유지
- `NeighborhoodPreviewPage.test.tsx`: 제출 전 재조회 방지, 이전 결과 복원, 새 조건 제출, 늦은 주소 응답 무시
- `mapTapGuard.test.ts`: 탭, 드래그, 핀치와 취소 구분
- 기록, 상세, 체크리스트와 지도 기능의 기존 통합 테스트

실제 지도 SDK의 드래그, 핀치와 WebView 동작은 jsdom으로 검증할 수 없다. 브라우저에서는 `npm run dev:mock`과 로컬 Naver 설정으로 데스크톱, 휴대폰 터치와 네이티브 브리지 문맥을 확인한다. 실제 iOS와 Android 기기 검증은 별도로 수행한다.
