# 방문자·리텐션·사용성 검증 기준

## 무엇을 확인하려는가

방문자 증가가 실제 기록 사용과 재사용으로 이어지는지 확인한다. 수치 목표는 아직 정하지 않는다. 변경 배포 후 최소 2주간 기준선을 확보하고, 팀에서 목표치를 정한다. 데이터 부족을 실패로 판단하지 않는다.

| 목표        | 질문                                            | 지표·단위                                                     | 해석 주의                                                                                           |
| ----------- | ----------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 방문자 증가 | 얼마나 많은 사람이 들어오는가? 어디에서 오는가? | 페이지뷰의 일별 고유 사용자, 유입 도메인별 고유 사용자        | 비로그인 포함. 페이지뷰 건수와 사람 수는 다르다. 일별 사용자 수를 더하면 기간 고유 사용자가 아니다. |
| 시작 전환   | 소개 페이지를 보고 시작하는가?                  | `landing_cta_clicked`를 목적지별 사용자 수로 비교             | 앱스토어 클릭은 설치가 아니다. 클릭률이 필요하면 랜딩 방문자를 분모로 한 퍼널을 사용한다.           |
| 실제 사용   | 방문 이후 집에 관한 정보를 기록하는가?          | 체크리스트 확인 또는 메모 저장을 한 주간 고유 사용자          | PostHog Action `매물 기록 행동`으로 OR 결합한다. 두 기능을 쓴 사람도 한 명이다.                     |
| 리텐션      | 기록한 사람이 다음 주에도 기록하는가?           | 첫 기록 주의 코호트 → 다음 주 기록 재사용 비율                | W1·W2 우선, W4는 관찰이 끝난 코호트만 판단한다. 아직 오지 않은 기간은 0% 이탈이 아니다.             |
| 사용성      | 등록을 시작한 사람이 실제로 저장하는가?         | 같은 세션의 등록 시작 → 제출 → 서버 저장 성공, 전환 소요 시간 | 1시간 전환 창. 입력 단계가 다른 지도 경로도 포함한다. 다시 시도하면 요청 수가 늘 수 있다.           |

활성화 후보는 **매물을 등록한 뒤 실제로 체크리스트나 메모를 기록하는 것**이다. 아직 리텐션과의 관계가 검증된 활성화 지표는 아니다. 충분한 저장 성공·기록 데이터가 쌓이면 등록 후 7일 이내 첫 기록과 이후 재사용을 비교한다. 파생 지표를 위한 `activated` 이벤트를 중복 생성하지 않는다.

## 이벤트의 정확한 의미

모든 이벤트의 공통 속성은 `environment`, `app_version`, `platform`이다. 익명 여부는 SDK의 `$is_identified`를 사용하며 별도 로그인 상태 속성을 중복 추가하지 않는다.

| 이벤트                             | 발생 시점                                 | 추가 속성                                                    | 성공으로 해석해도 되는가?                                                    |
| ---------------------------------- | ----------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `$pageview`                        | 경로 변경                                 | `path`                                                       | 방문이지 기능 사용은 아니다.                                                 |
| `landing_cta_clicked`              | 브랜드 링크 또는 시작 버튼 클릭           | `destination: web/app_store`, `placement: brand/actions`     | 이동 의도만 확인한다. 설치·로그인 성공이 아니다.                             |
| `property_creation_started`        | 등록 폼 진입, StrictMode 중복 제외        | `entrypoint: form/map`                                       | 아직 등록하지 않았다.                                                        |
| `property_creation_submitted`      | API 저장 요청 시작                        | `entrypoint`                                                 | 저장 성공이 아니다.                                                          |
| `property_created`                 | 매물 생성 API 성공                        | `entrypoint`, `property_id`, 알고 있을 때만 `first_property` | 서버 저장 성공이다. 목록 캐시가 없으면 첫 매물 여부는 모른다.                |
| `property_creation_failed`         | 매물 생성 API 실패                        | `entrypoint`, `error_kind: request`                          | 실패다.                                                                      |
| `checklist_item_checked`           | 확인 상태 변경 API 성공, 미확인 상태 제외 | 기존 매물·항목 ID, `status`                                  | 기록 행동이다. 반복 변경 수가 완료 항목 수는 아니다.                         |
| `property_memo_saved`              | 메모 저장 API 성공                        | `property_id`                                                | 저장 행동이다. 빈 메모 저장·기존 내용 수정도 포함하며 새 메모 개수는 아니다. |
| `property_memo_save_failed`        | 메모 저장 API 실패                        | `property_id`, `error_kind: request`                         | 실패다.                                                                      |
| `property_comparison_pdf_exported` | PDF 내보내기 처리 완료                    | 기존 비교 속성                                               | 비교 결과 활용의 보조 지표다.                                                |

`checklist_created`는 사용자 정의 체크리스트 생성이다. 매물에 기본 체크리스트가 연결되는 것 또는 체크리스트 사용 전체를 의미하지 않는다. `property_detail_viewed`는 성공적으로 열린 상세 화면의 조회이며 기록 재사용과 구분한다.

지도 경로에 주소 입력 완료 이벤트를 가짜로 보내지 않는다. 공통 등록 퍼널은 주소 단계 없이 구성하고, 필요할 때 `entrypoint`로 비교한다. 위치 확인 화면의 등록 초안 저장은 폼 진입 경로로 취급한다.

## PostHog에서 보는 방법

[사용자 행동 대시보드](https://us.posthog.com/project/579863/dashboard/2149589)를 사용한다. 기본 조회 기간은 56일, 운영 환경이며 내부/테스트 코호트를 제외한다. 개발 확인은 대시보드의 `environment`를 `development`로 바꾼다. 카드 내부에는 운영 환경을 고정하지 않아 개발 필터와 충돌하지 않게 한다. 카드만 단독으로 열면 환경을 직접 선택해야 한다.

설정의 주요 측정 계약과 원격 카드 ID는 [대시보드 정의 기록](analytics-dashboard.json)에 남긴다. 이 파일은 SDK 실행 설정이나 자동 배포 파일이 아니다. 원격 설정 변경은 PostHog에서 별도로 적용하며, 변경 후 단독 인사이트와 대시보드 쿼리를 대조한다. 프로젝트 날짜 집계는 현재 UTC 기준이므로 한국 시간의 날짜와 다를 수 있다.

- 로그인 퍼널은 성공에서 끝난다. 실패는 별도 추이로 본다.
- 로그인 후 등록 퍼널은 **그 세션에 로그인한 사람만** 포함한다. 로그인 유지 사용자까지 포함한 전체 등록 흐름은 공통 등록 퍼널에서 본다.
- 기능별 사용자 수는 항목끼리 합산하지 않는다. 오류·반복 클릭은 불만의 확정 증거가 아니며 리플레이로 맥락을 확인한다.
- UTM은 캠페인 링크에 붙여 실제 수신을 확인한다. 유입 도메인은 페이지 기준 보조 분석이며 최초 유입/캠페인 기여도와 동일하지 않다.
- 리텐션에는 코호트 크기와 관찰 기간을 함께 기록한다. 집을 구하는 동안의 단기 재사용이 우선이며, 집을 구한 뒤 장기 재방문까지 현재 기능의 성공 조건으로 가정하지 않는다.

## 검증과 한계

자동화 테스트는 SDK 수명주기, 공통 속성, 성공/실패 구분, 지도/폼 경로, StrictMode 중복, 입력 원문 미전송을 확인한다. SDK 호출/큐 접수는 실제 서버 수신 완료가 아니다.

1. dev 배포 버전 확인 후 비로그인 방문 → 랜딩 클릭 → 로그인 → 폼/지도 등록 성공·실패 → 체크리스트 확인 → 메모 저장 성공·실패 → 로그아웃 → 재방문을 확인한다.
2. 개발자 도구의 수집 요청과 PostHog `environment=development`, 해당 `app_version`의 이벤트를 대조한다. 시작·요청·성공이 각각 맞는 시점에 한 번 들어오는지 확인한다.
3. 주소·금액·메모 원문이 새 속성에 없는지 확인하고, 로그아웃 뒤 환경·버전이 유지되는지 확인한다.
4. 운영 배포 후 운영 이벤트도 같은 기준으로 확인한다. W1은 최소 한 주, W2는 두 주 관찰 이후 평가한다.

최근 데이터에는 운영 호스트에서 발생했지만 환경/버전 속성이 빠진 과거 이벤트가 있다. 새 코드는 이를 소급 복구하지 않는다. 기존 제출 이벤트를 저장 성공으로 변환하거나 과거 기록량을 추정하지 않는다. 새로운 성공·메모·랜딩 이벤트의 빈 차트는 배포 전 미수집일 수 있으며 사용자가 없다는 뜻은 아니다.

신규 기능을 추가하면 필요한 경우에만 노출/시작/성공/실패를 정의하고 기존 `app_version`으로 전후를 구분한다. 모든 클릭이나 모든 상태 전환을 수집하지 않는다. 닉네임 식별·리플레이 마스킹 정책은 유지하고 주소·금액·메모 원문을 추가하지 않는다.

### 이번 변경의 확인 결과 (2026-10-08, 한국 시간)

- Node 22.23.1에서 전체 50개 파일·248개 테스트, 린트·포맷·타입 검사·프로덕션 빌드 통과.
- PostHog 카드 11개의 단독 저장 정의를 조회하여 이벤트/액션·56일 기간·환경 고정 없음·기록 재사용 정의를 대조했다.
- 운영 대시보드 전체 쿼리와 개발 환경의 방문·로그인·기록·리텐션 쿼리를 재계산해 실행 오류가 없음을 확인했다. 대시보드 화면의 제목·조회 조건·카드 배치도 확인했다.
- 새 코드의 dev/prod 배포 후 실제 이벤트 수신, W1·W2 리텐션 성과, 활성화 후보와 리텐션의 관계는 아직 검증하지 않았다. 기존 데이터의 빈 결과를 제품 성과로 결론내리지 않는다.
