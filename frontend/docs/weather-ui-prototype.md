# 생활 날씨 UI 프로토타입

날씨 정보의 구성, 화면 배치와 알림 흐름을 프론트엔드 개발자와 논의하기 위한 시연이다. 정식 기능 구현이 아니며 실제 날씨·GPS·푸시를 사용하지 않는다.

- 작업 이슈: [#441](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/441)
- 기준: [#431](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/431), [PR #432](https://github.com/woowacourse-teams/2026-jachwi-sunbae/pull/432)의 `fc812f9`, [제품 명세](../../docs/product/specs/weather.md)
- 브랜치: `431/feat-weather-collection`에서 분기한 `prototype/weather-ui-flow`. PR·병합·배포 없이 시연한다.

## 실행

저장소에서 Node.js `frontend/.nvmrc` 버전을 사용한다. 새 환경변수 파일이나 백엔드 실행은 필요 없다.

```bash
cd frontend
npm ci
npm run dev:mock
```

[마이페이지](http://localhost:3000/me)를 연다. 기존 익명 인증은 기존 MSW가 처리한다.

## 화면과 시연

| 경로                                     | 시연 내용                                                        |
| ---------------------------------------- | ---------------------------------------------------------------- |
| `/me`                                    | 생활 날씨 위젯: 알림 꺼짐 안내 또는 날씨 요약, 카드 안 알림 받기 |
| `/weather`                               | 오늘·내일 전환, 00–23시 가로 스크롤, 기온·강수·습도·바람         |
| `/weather/settings`                      | 알림 받기, 고정 오전 7시·오후 10시 안내, 알림 미리보기           |
| `/weather/notifications/:notificationId` | 알림 미리보기 배너를 누르면 열리는 알림 당시 제목·본문·안내 목록 |

1. `/me`의 생활 날씨 카드는 알림이 꺼져 있으면 날씨 대신 알림 꺼짐 아이콘과 안내를 보인다. 카드를 눌러 상세로 이동하지 않는다. 마이는 데스크탑·휴대폰 컴포넌트를 나누고, 홈처럼 흰 바탕에 회색 카드를 두며 본문 폭(휴대폰 45rem·데스크탑 64rem)을 홈과 맞춘다. 제목은 다른 화면처럼 상단 바 아래에 두고 데스크탑에는 뒤로 가기를 두지 않는다. 카드는 화면이 넓어져도 24rem(데스크탑 26rem)까지만 늘이고 생활 날씨 카드와 계정 삭제 안내만 둔다.
2. **알림 받기**를 켜면 알림 권한 → 위치 권한 순서로 OS가 직접 묻는다. 웹은 별도 안내 창을 띄우지 않고 결과만 반영하며, 시연에서는 아직 묻지 않은 권한을 허용한 것으로 처리한다. 켜지면 날씨 요약을 보이며, 켜고 끌 때 웹 화면에 별도 토스트는 띄우지 않는다. 카드는 켜짐·꺼짐 모두 같은 높이를 유지한다.
3. 받을 수 없는 상태는 토글 아래에 알린다. 기기 알림 또는 위치 권한 거부는 **설정 열기**를, 웹 브라우저 접속은 토글을 막고 앱 안내를 표시한다. 현재 위치를 찾지 못하면 마지막 저장 위치를 쓰고 `마지막 위치 기준`으로 표시한다.
4. `/weather`에서 오늘·내일 예보를 비교한다. 오늘은 한국 시간의 해당 시각, 내일은 12시를 대표로 표시한다. 03시 강수량 등 일부 선택 요소는 결측이고, 정상 `0`과 구별한다.
5. 알림 설정의 **알림 미리보기**에서 발송 시간을 고르면 화면 안 배너를 만든다. 배너를 눌러 저장 당시 내용을 확인한다. 알림이 꺼져 있어도 볼 수 있으며, 위치나 필수 예보가 없으면 만들 수 없다.
6. `/weather`와 알림 설정의 **상황 바꿔 보기**에서 날씨 상황·위치 거부·접속 환경·기기 알림 권한·현재 위치 실패를 바꾼다. 날씨 선택은 서울 시청 위치도 함께 선택한다. **처음 상태로 되돌리기** 또는 새로고침은 위치·권한·설정·알림을 초기화한다.

## Mock 범위와 미연결 기능

- `src/features/weather/model/weather.ts`는 현재 응답 DTO를, `weatherFixtures.ts`는 `code/message/data` 형태의 예보와 알림 샘플을 담는다. 화면 상태는 `WeatherPrototypeProvider`의 메모리에만 둔다. 시작 날짜는 앱을 연 시점의 한국 날짜로 고정하고 예보 시각에 `+09:00`을 사용한다.
- 알림은 실제 `LifeWeatherRules`의 눈·비·추위/동파·일교차·빨래 조건과 문구를 따른다. 맑은 날에는 생활 안내 없이 대상 시간대의 기온 범위를 표시한다. 공식 기상특보가 아니다.
- 날씨·위치·설정·기기·알림 상세 API는 호출하지 않는다. 기상청·DB·Firebase·OS 권한·실제 알림 스케줄도 연결하지 않는다. 알림함·목록·미리보기 서버 API는 만들지 않는다.
- 실제 연결 시 조회 DTO, 위치 저장, 수신 동의, 기기 등록, 푸시 클릭의 알림 ID 전달을 연결해야 한다. 실제 발송에는 수신 동의·저장 위치·등록 기기·발송 가능한 예보가 필요하다.
- 모바일 WebView의 경로 이동과 상단 내비게이션만 고려했다. 네이티브 코드·탭바·브리지는 수정하지 않았다.

## 함께 결정할 UX

- 요약 카드의 최종 위치: 마이페이지, 홈 또는 다른 화면
- 위치 사용 안내 시점과 거부 후 재진입 방식, 마지막 저장 위치의 표현
- 시간별 예보의 스크롤 방식과 추가 정보의 우선순위
- 수신 동의와 실제 기기 권한·등록 상태를 구분하는 안내
- 푸시 클릭 이후 당시 알림과 새 예보를 함께 탐색하는 방식
