# 생활 날씨 카드

마이 화면의 생활 날씨 카드와 알림 받기 토글이다. 토글은 생활 날씨와 배달 할인 알림을 함께 켜고 끄는 공통 알림 설정이다([알림 명세](../../docs/product/specs/notifications.md)). 날씨 조회·알림 위치·수신 동의는 서버 API([PR #432](https://github.com/woowacourse-teams/2026-jachwi-sunbae/pull/432))를 쓰고, 앱 푸시 기기는 기존 모바일 2.1.1(8) 브리지로 등록한다. 실제 Dev·Prod 수신은 별도 검증이 필요하다.

- 작업 이슈: [#447](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/447) (시연 화면 [#441](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/441)에서 이어짐)
- 명세: [생활 날씨](../../docs/product/specs/weather.md)

## 실행

```bash
cd frontend
npm ci
# 개발 서버 API로 확인
DEV_API_PROXY_TARGET=https://dev-api.jachwi-sunbae.kr npm run dev
# 서버 없이 MSW 목으로 확인
npm run dev:mock
```

[마이페이지](http://localhost:3000/me)를 연다. 위치는 브라우저(앱은 WebView)의 위치 권한으로 구한다.

## 동작

1. 마이는 옅은 회색(`#eff1f5`) 바탕에 흰 카드를 올리고, [계정 연결](oauth-account-linking.md), 서비스 설정(생활 날씨 미리보기와 알림), 내 도구, 개인정보 처리방침과 회원 탈퇴 줄을 순서대로 둔다. 서비스 설정 제목은 읽기 도구에만 알린다. 내 도구는 체크리스트, 저렴한 한 끼, 사용방법 그림 타일(`ShortcutTile`, 그림과 이름을 감싼 흰 카드)을 한 줄 4칸으로 둔다. 개인정보 처리방침과 회원 탈퇴는 설명 줄 없이 회색 글자와 끝 화살표만 둔다. 줄 끝 화살표와 줄 앞 아이콘 크기는 SEED 목록 규칙(화살표 20px 회색, 아이콘 24px)을 따라 `MyPage.styles`의 변수로 맞춘다. 데스크탑은 26rem 한 열을 `zoom: 0.8`로 줄여 휴대폰과 같은 크기로 보이고, 화면 아래에 홈과 같은 푸터를 둔다. 계정 연결 카드의 제공자 버튼은 너비가 충분하면 한 줄에 배치하며, 앱 WebView에서는 네이티브 인증을 지원하는 제공자만 표시한다. 완전 삭제 메일 요청은 개인정보 처리방침의 삭제 요청 안내에서 받으며, 로그인한 상태면 메일에 회원 번호를 미리 적는다.
2. 알림이 꺼져 있으면 날씨 대신 `알림이 꺼져 있어요` 한 줄과 토글만 보이고(동네 이름 줄과 기온 줄은 두지 않는다), 켜져 있으면 현재 위치의 현재 시각 예보와 오늘 최저·최고 기온을 보인다. 위치 이름은 역지오코딩 결과의 구·동이다.
3. **알림 받기**를 켜면 현재 위치를 구하고 앱 `enable`·`token`으로 권한과 토큰을 확인한다. 위치(구한 경우)·기기를 등록한 뒤 `PUT /api/members/me/notification-settings`로 수신 동의를 켠다. 위치를 하나도 구하지 못해도 켜며, 이때 서버는 날씨 알림만 건너뛰고 배달 할인 알림은 보낸다. 카드에는 `날씨는 위치를 확인한 뒤 알려 드려요`와 배달 할인 알림은 받는다는 안내를 보인다. 위치를 기다리는 동안에는 300ms 뒤 토글 옆에 진행 표시를 보이고, 12초(`WEATHER_LOCATION_DEADLINE_MS`) 안에 답이 없으면 위치를 잠깐 못 잡은 것으로 보고 위치 없이 켠다. iOS는 위치를 잠깐 못 잡으면(`kCLErrorLocationUnknown`) 웹에 실패를 알리지 않고 계속 찾기 때문이다.
4. 알림을 켜 둔 채 마이를 열 때마다 현재 위치를 다시 저장한다. 서버는 마지막으로 저장한 위치로 알림을 보낸다. 현재 위치를 못 잡으면 이 기기에 남긴 마지막 위치로 날씨를 보이고 `마지막 위치 기준`으로 표시한다.
5. 위치 권한 거부, 위치 확인 실패(일시 실패와 시간 초과 포함), 저장 실패는 토글 아래에 알린다. 웹 브라우저 접속(알림은 앱에서만 받음)은 문제가 아니라 사실이라 카드 밖 아래에 검은 글자로 적는다. 앱 여부는 `window.__JACHWI_NATIVE_APP__` 또는 앱 User-Agent로 판단한다.
6. 알림을 켰지만 앱에서 위치 권한을 거부해 날씨용 위치가 없으면 **설정 열기** 버튼을 보이고, 앱 브리지 `settings`로 시스템 설정을 연다. 브라우저에서는 문구만 보인다.
7. dev 서버(`appEnvironment`가 `development`)의 앱에서 알림이 켜져 있으면 **푸시 알림 테스트** 버튼을 보인다. 누르면 5초 기다렸다가, 또는 그사이 홈 화면으로 나가는 순간 `POST /api/members/me/weather-notifications/test`로 내 기기에 테스트 알림을 보낸다. 앱이 켜져 있으면 시스템 배너 대신 앱 안 안내창이 뜨기 때문이다. 이 API는 운영 서버에 없고 운영 웹에서는 버튼을 보이지 않는다.

## 기기 연결과 실패 처리

- `PUT /api/members/me/notification-devices/current`에 origin별 설치 ID·32바이트 난수 비밀키와 토큰을 보낸다. 토큰은 영구 저장·로그·분석·Query 캐시에 넣지 않는다.
- 앱의 회원 화면 전체에서 로그인·재진입·네트워크 복구·토큰 갱신을 동기화한다. 새 회원의 동의는 이전하지 않으며 비동기 작업 중 회원이 바뀌면 이전 요청을 거절한다.
- OFF는 서버 동의를 먼저 끈 뒤 기기를 해제한다. 정리 실패는 OFF를 유지하며 재시도를 안내한다. OS 권한 철회도 서버 OFF로 반영한다.
- 브리지 없는 앱과 웹에서는 새 수신 동의를 켜지 않는다. 기존 서버 동의가 ON인 경우 OFF는 가능하다. ON 요청에는 현재 위치 또는 마지막 위치가 있으면 서버에 저장한다.
- 네이티브 코드·스토어 재제출 없이 연결한다. Debug 앱과 Staging(dev TestFlight) 앱은 dev 웹, 스토어 앱은 운영 웹을 연다. 앱 토큰의 Firebase 프로젝트와 서버의 `weather.notification.firebase-project-id`가 같아야 발송된다.
