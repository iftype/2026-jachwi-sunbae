# 지도 교통 조회와 매물 주변 집계

교통은 `GET /api/maps/bus-stops`로 조회한다. 반경은 500m·1km·2km이며 `count`와 `busStops`를 사용한다. 정류장 ID는 `nodeId`다. nearby 요청 카테고리와 응답 counts에는 TRANSPORT가 없다.

- 일반 지도: 교통 필터 선택 시 정류장을 조회하며, 교통만 선택하면 nearby는 요청하지 않는다.
- 일반 지도 첫 진입에서 현재 위치를 받으면 해당 좌표의 500m 반경을 활성화한다. 위치를 받지 못하면 반경은 미선택·비활성 상태를 유지한다. 기본 확대 수준은 500m 반경에 맞춘 5이며 이전 지도 상태로 복귀할 때는 저장한 확대 수준을 유지한다.
- 매물 주변 분석: 매물 좌표가 있으면 최초 진입 및 반경 변경 시 nearby와 bus-stops를 함께 조회한다. 카테고리 미선택이어도 모든 집계가 표시된다.
- 동네 주변 분석(`/explore/nearby`, `/neighborhoods/nearby`): 쿼리로 받은 동네 중심 좌표로 같은 조회를 한다. nearby·bus-stops는 다른 업무 API처럼 Access Token으로 요청하며, 토큰이 없으면 API 클라이언트가 먼저 자동 로그인한다. 처음에는 교통·중개업소를 선택한 상태로 연다.
- 매물 주변 분석의 카테고리 선택은 마커·목록 표시만 제어한다. 교통을 숨겨도 교통 개수는 유지한다.
- 매물 주변 분석은 두 조회가 완료된 뒤 개수를 표시한다. 로딩이나 실패를 실제 0개로 안내하지 않으며, 재시도는 두 조회를 갱신한다.
- 좌표·반경별 조회 캐시를 공유하므로 같은 조건의 필터 토글로 정류장을 다시 요청하지 않는다.

공유 조회 Hook `useNearbyFacilities`의 `loadAllCategories` 옵션은 매물 주변 분석에서만 활성화한다. 각 화면은 응답을 합친 뒤 선택 카테고리에 맞는 시설만 표시한다. API 응답 형식은 변경하지 않는다.

`test/pages/nearby-analysis/hooks/useNearbyAnalysis.test.tsx`에서 초기 교통 집계·마커 토글·반경 변경·로딩·실패와 재시도·좌표 없는 진입을 확인한다. 일반 지도의 교통 단독 조회는 기존 `useMapNearby.test.tsx`로 검증한다.
