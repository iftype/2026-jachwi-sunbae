# DL-001 화면 금액이 입력값과 다르면 코드가 FAIL로 판정한다

## 코드·AI 판단

상세 화면에 `500만원 / 5만원`이 보였다. 코드는 화면에서 `500만원`과 `50만원`을 찾지 못하자 금액 표기를 해석할 수 없다고 보고 E2를 `NEEDS_REVIEW`로 넘겼다.

AI는 E2 판정 초안으로 `FAIL`을 냈다. 표기 형식은 같고 금액만 다르므로 해석이 갈릴 여지가 없으며, 코드의 판정이 지나치게 보수적이라고 지적했다(EV1, EV2).

## 사람 판단

AI 판정 초안을 수용한다. `N만원 / N만원` 형식은 코드가 해석할 수 있으므로, 금액이 다르면 `AC-PROP-003` 위반이 분명하다. `NEEDS_REVIEW`는 표기 형식을 해석할 수 없을 때만 쓴다.

## 바꾼 것

- `qa/tests/F02-S01-property-create.spec.ts`: 화면에서 보증금과 월세 쌍(`500만원 / 50만원`, `보증금 500만원 / 월세 50만원`)을 읽는다. 값이 다르면 `FAIL`, 쌍을 찾지 못하면 `NEEDS_REVIEW`로 판정한다. E2, E3, E4에 같은 규칙을 쓴다.
- F02-S01 판정 메모에 같은 규칙을 적었다.

## 다음 실행에서 달라지는 점

같은 결함을 주입해 다시 실행한 `F02-S01-261007-111111`에서 E2가 AI 판정 초안 없이 코드 판정 `FAIL`로 나왔다. 해석이 필요 없는 실패는 AI 분석을 기다리지 않고 바로 최종 판정에 반영된다.
