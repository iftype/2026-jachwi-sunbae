## 사람 판단

- Haiku 분석은 기각한다. 원인 가설이 Evidence와 맞지 않고, 실제 결함인 기본 주소를 정상이라고 판단했다.
- Sonnet 분석은 원인 가설, E2 판정 초안, 기타 관찰 두 건이 Opus와 같았고 비용은 약 절반이다. 근거 칸 형식 위반은 모델 능력보다 출력 형식이 모호했던 문제로 보고, JSON Schema에 ID 형식 제약을 걸어 해결했다.
- 개발 작업에 쓰는 Opus 사용량을 QA 분석이 나눠 쓰지 않도록 QA 분석 기본 모델을 Sonnet으로 고정한다.
- 기타 관찰의 판정 제안은 같은 모델에서도 실행마다 달랐다(체크 집계: `SPEC_GAP`·LOW → `CONFIRMED_BUG`·MEDIUM). 판정 제안은 초안으로만 쓰고 사람이 확정한다.

## 바꾼 것

- `qa/src/ai-analysis.ts`: 기본 모델을 `claude-sonnet-5-5`로 고정했다. Claude Code 기본 모델이 바뀌어도 분석 기준이 흔들리지 않도록 별칭 대신 모델 ID를 쓴다. `QA_AI_MODEL`은 모델 비교 실험에만 쓴다.
- 근거 칸에는 명세 ID 형식(`AC-PROP-003`), Evidence 칸에는 Evidence ID 형식(`EV1`, `EV+2`)만 허용하도록 JSON Schema에 제약을 걸었다.
- 인용 검증이 근거 칸에 문장을 쓴 경우도 적발하도록 강화했다(`validateAnalysis`).
- 기타 관찰과 Expected 판정 초안마다 판정 제안, 심각도 제안, 확인 방법을 받도록 출력 형식을 늘렸다. Opus 분석은 이 변경 전에 실행했다.
