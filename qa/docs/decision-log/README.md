# 판단 기록

- 상태: v0.1 / 작성일: 2026-10-06

사람이 코드나 AI의 판정을 바꾼 이유와, 그 결과 QA 기준을 어떻게 바꿨는지 남긴다.  
같은 오판이 반복되지 않게 하고 AI 분석의 품질을 개선하는 근거로 쓴다.

## 언제 쓰는가

- Run Report의 사람 판정에서 AI 판단이 `수정` 또는 `기각`일 때
- 사람 판정이 `NOT_A_BUG`이거나 `TEST_ISSUE`일 때
- 판정 기준, Scenario, Run Report 형식, AI 분석 방식을 바꾸는 결정을 내렸을 때

## 파일 이름

`DL-<세 자리 번호>-<영문 요약>.md`. 예: `DL-001-amount-format.md`

## 작성 형식

```markdown
# DL-000 제목

| 항목 | 내용 |
| --- | --- |
| 일시·판정자 | |
| 관련 Run | Run ID |
| 관련 Scenario | Scenario ID |

## 코드·AI 판단

어떤 판정과 근거를 냈는지

## 사람 판단

어떻게 판정했고 근거는 무엇인지(명세 ID, Evidence ID)

## 바꾼 것

Scenario, Run Report 형식, AI 분석 방식, 자동화 코드 중 무엇을 어떻게 바꿨는지. 바꾸지 않았다면 이유

## 다음 실행에서 달라지는 점

같은 상황이 다시 나오면 어떻게 판정되는지
```
