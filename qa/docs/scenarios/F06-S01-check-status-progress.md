# F06-S01 체크 상태 저장과 진행 현황 집계

| 항목      | 내용                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------- |
| Flow      | [F06 매물 체크 기록](../user-flows/F06-property-check.md)                                                           |
| 근거      | `AC-CHECK-007`, `REQ-PROGRESS-001`, `REQ-PROGRESS-003` ~ `REQ-PROGRESS-006`, `POL-PROGRESS-001`, `POL-PROGRESS-002` |
| 상태      | 자동화                                                                                                              |
| 실행 방식 | 수동, 자동(`qa/tests/F06-S01-check-status-progress.spec.ts`)                                                        |

## 목적

현장 체크리스트 항목의 상태를 고르면 바로 저장되고, 진행 현황이 명세의 집계 규칙대로 계산되어 체크리스트, 매물 상세, 매물 목록에 같은 값으로 보이는지 확인한다.

## 사전 조건

- DEV 프론트엔드와 API에 접속할 수 있다.
- 새 닉네임 `qa-{runId}`로 비밀번호 없이 시작해 빈 매물 목록에 있다.
- [F02-S01](F02-S01-property-create.md)과 같은 방법으로 매물 `F06-S01 {runId}`(보증금 500, 월세 50)를 등록했다. 등록하지 못하면 `BLOCKED`다.
- 등록한 매물의 현장 체크리스트 항목이 3개 이상이다. 항목 수를 N이라 한다. 3개 미만이면 `BLOCKED`다.

## 테스트 데이터

| 항목 순서 | 조작                             | 최종 상태 |
| --------- | -------------------------------- | --------- |
| 1번째     | 괜찮음 선택                      | 괜찮음    |
| 2번째     | 주의 선택                        | 주의      |
| 3번째     | 괜찮음 선택 후 미확인으로 되돌림 | 미확인    |
| 나머지    | 조작하지 않음                    | 미확인    |

기대 집계는 전체 N, 완료 2, 괜찮음 1, 주의 1, 미확인 N−2, 진행률 floor(200 ÷ N)%다. N이 4이면 진행률은 50%다.

## 단계

1. 등록한 매물의 상세에서 현장 체크리스트를 열고 항목 수 N을 기록한다.
2. 테스트 데이터대로 1~3번째 항목의 상태를 고른다. 저장 버튼은 누르지 않는다.
3. 체크리스트의 진행 현황을 확인한다.
4. 새로고침하고 항목 상태와 진행 현황을 다시 확인한다.
5. 매물 상세로 돌아가 체크리스트 집계를 확인한다.
6. 매물 목록으로 이동해 매물 카드의 체크리스트 집계를 확인한다.

## 판정 메모

- 화면마다 어떤 집계 값을 보여줄지(상태별 수, 완료/전체, 진행률)는 명세가 정하지 않았다. E3~E5는 화면에 보이는 값이 기대 집계와 다를 때만 `FAIL`이다.
- E6은 세 화면(체크리스트, 매물 상세, 매물 목록) 어디에서든 `숫자%` 형식의 진행률을 찾으면 코드가 판정한다. 찾지 못하면 다른 방식(막대 등)으로 표시했을 수 있으므로 `NEEDS_REVIEW`로 넘겨 AI가 화면을 해석한다.
- 테스트 데이터는 진행률의 내림과 반올림 차이를 드러내도록 설계하지 않았다. 기대 진행률은 명세의 식(`POL-PROGRESS-002`)으로 계산한다.
- 이 Scenario에서 판정하지 않는 것: 계약 전 단계, 두 단계를 합친 집계, 항목 메모 저장, 양식 교체.
