# F03-S01 다른 회원의 매물 접근

| 항목      | 내용                                                                |
| --------- | ------------------------------------------------------------------- |
| Flow      | [F03 매물 정보 관리](../user-flows/F03-property-management.md)      |
| 근거      | `AC-PROP-010`, `AC-AUTH-005`, `REQ-AUTH-007`, `POL-AUTH-003`        |
| 상태      | 자동화                                                              |
| 실행 방식 | 수동, 자동(`qa/tests/F03-S01-property-access-other-member.spec.ts`) |

## 목적

다른 회원의 매물 ID를 알아도 그 매물을 조회, 수정, 삭제할 수 없고, 인증 없이도 조회할 수 없는지 확인한다. 화면에서는 다른 회원의 매물로 가는 길이 없으므로 API를 직접 호출한다.

## 사전 조건

- DEV 프론트엔드와 API에 접속할 수 있다.
- 서로 다른 회원 두 명을 준비한다. 두 회원 모두 비밀번호 없이 새 닉네임으로 시작한다. 같은 닉네임이면 같은 회원이므로(`REQ-AUTH-003`) 닉네임을 다르게 한다.
  - 주인 회원: `qa-{runId}`. 화면에서 시작한다.
  - 다른 회원: `qa-{runId}-b`. API(`POST /api/auth/nickname`)로 시작한다.
- 주인 회원이 [F02-S01](F02-S01-property-create.md)과 같은 방법으로 매물 `F03-S01 {runId}`(보증금 500, 월세 50)를 등록했다. 등록하지 못하면 `BLOCKED`다.

## 테스트 데이터

| 항목           | 값                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------ |
| 대상 매물      | 주인 회원이 등록한 매물. 이름 `F03-S01 {runId}`                                                                    |
| 수정 시도 내용 | 이름 `F03-S01 {runId} 변경 시도`, 보증금 123만원, 월세 12만원. 입력 형식 오류로 거부되지 않도록 올바른 값을 보낸다 |
| 노출 확인 기준 | 응답 본문에 대상 매물의 이름이 있으면 내용이 노출된 것으로 본다                                                    |

## 단계

1. 주인 회원으로 매물을 등록하고, 등록한 매물의 상세 정보를 기록한다.
2. 다른 회원으로 대상 매물의 상세 조회를 요청한다.
3. 다른 회원으로 대상 매물의 기본 정보 수정을 요청한다.
4. 다른 회원으로 대상 매물의 삭제를 요청한다.
5. 인증 정보 없이 대상 매물의 상세 조회를 요청한다.
6. 주인 회원으로 대상 매물의 상세와 목록을 다시 조회해 1단계와 비교한다.

## 판정 메모

- 상태 코드가 명세(`REQ-AUTH-007`)와 다르면 내용이 노출되지 않았더라도 `FAIL`이다. 예: 다른 회원의 자원에 403을 돌려주면 자원이 있다는 사실이 드러난다.
- 매물 정보가 같은지는 이름, 보증금, 월세, 주소, 좌표, 수정 시각으로 비교한다.
- 요청과 응답 Evidence에는 인증 토큰을 남기지 않는다.
- 이 Scenario에서 판정하지 않는 것: 메모, 사진, 체크리스트 같은 매물 하위 자원, 비밀번호로 보호된 회원, 같은 닉네임을 공유하는 경우.
