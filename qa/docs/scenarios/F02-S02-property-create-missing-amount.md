# F02-S02 보증금·월세 누락 등록

| 항목      | 내용                                                                  |
| --------- | --------------------------------------------------------------------- |
| Flow      | [F02 후보 매물 등록](../user-flows/F02-property-create.md)            |
| 근거      | `AC-PROP-002`, `POL-PROP-002`                                         |
| 상태      | 자동화                                                                |
| 실행 방식 | 수동, 자동(`qa/tests/F02-S02-property-create-missing-amount.spec.ts`) |

## 목적

보증금이나 월세를 비운 채 진행하거나 등록하면 저장되지 않고, 사용자가 어떤 값이 빠졌는지 알 수 있는지 확인한다. 비운 값이 0으로 바뀌어 저장되지 않고, 0을 직접 입력한 경우와 구분되는지도 함께 본다.

## 사전 조건

- DEV 프론트엔드와 API에 접속할 수 있다.
- 새 닉네임 `qa-{runId}`로 비밀번호 없이 시작해 빈 매물 목록에 있다.

## 테스트 데이터

| 경우 | 상황                                     | 보증금     | 월세 | 이름              |
| ---- | ---------------------------------------- | ---------- | ---- | ----------------- |
| A    | 보증금을 비운 채 다음 단계로 진행        | 비움       | -    | -                 |
| B    | 월세를 비운 채 다음 단계로 진행          | `0`        | 비움 | -                 |
| C    | 모든 값을 입력한 뒤 보증금을 지우고 등록 | `0` → 지움 | `50` | `F02-S02 {runId}` |

## 단계

1. 매물 목록에서 매물 등록 화면으로 이동한다.
2. 보증금을 비운 채 다음 단계로 진행을 시도한다. (경우 A)
3. 보증금에 `0`을 입력하고 다음 단계로 진행한다.
4. 월세를 비운 채 다음 단계로 진행을 시도한다. (경우 B)
5. 월세에 `50`을 입력하고, 주소는 고르지 않고 다음 단계로 진행한 뒤 매물 이름을 입력한다.
6. 보증금 입력란을 지우고 등록을 시도한다. (경우 C)
7. 매물 목록으로 이동한다.

## 판정 메모

- 등록 화면은 단계마다 값을 확인한다. 화면에서 막든 서버가 거부하든 저장되지 않으면 E1은 `PASS`다. API를 직접 호출하는 검증은 이 Scenario의 범위가 아니다.
- 안내 문구와 위치는 명세가 정하지 않았다. E2는 빠진 값의 입력란이 오류 상태로 표시되고 안내 문구가 그 입력란에 연결되어 있으면 코드가 `PASS`로 판정한다. 그런 표시를 찾지 못하면 다른 방식(알림 등)으로 안내했을 수 있으므로 `NEEDS_REVIEW`로 넘겨 AI가 화면을 해석한다. 빠진 값을 전혀 알 수 없으면 `FAIL`이다.
- 여러 경우를 하나의 Expected로 판정하고, 실제 결과에 경우별 결과를 함께 쓴다. 한 경우라도 기대와 다르면 그 Expected는 `FAIL`이다.
- 이 Scenario에서 판정하지 않는 것: 이름 누락, 금액 형식 오류.
