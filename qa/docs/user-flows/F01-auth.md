# F01 닉네임으로 시작·복귀

| 항목        | 내용                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| 사용자 목적 | 외부 계정 없이 닉네임으로 기록 공간을 만들거나 이전 기록으로 돌아간다. 필요하면 비밀번호로 보호한다. |
| 진입점      | 시작(로그인) 화면, 로그아웃 후, 미인증 상태로 개인 화면에 접근했을 때                                |
| 선행 Flow   | 없음. 모든 Flow의 사전 조건이다.                                                                     |
| 관련 명세   | [인증](../../../docs/product/specs/authentication.md)                                                |

## 핵심 흐름

1. 시작 화면에서 비밀번호 없는 닉네임은 같은 닉네임을 아는 사람과 기록을 공유한다는 안내를 확인한다.
2. 닉네임과 선택 비밀번호를 입력해 시작한다.
3. 처음 쓰는 닉네임이면 새 회원으로, 기존 닉네임이면 그 회원의 기록으로 매물 목록에 들어간다.
4. 마이페이지에서 닉네임과 비밀번호 보호 여부를 확인한다.
5. 로그아웃하면 로그인 화면으로 돌아가고, 이전 회원의 화면 데이터가 남지 않는다.

갈래: 보호된 닉네임에 틀린 비밀번호로 시작 실패, 같은 닉네임의 비밀번호 없는 회원과 보호 회원 분리, 다른 회원 자원 접근 차단.

## 관련 요구사항

| ID             | 확인할 점                                                 |
| -------------- | --------------------------------------------------------- |
| `REQ-AUTH-001` | 닉네임과 선택 비밀번호로 시작                             |
| `REQ-AUTH-002` | 새 닉네임은 회원 생성, 기존 닉네임은 기록 복귀            |
| `REQ-AUTH-003` | 비밀번호 없는 닉네임의 기록 공유와 안내                   |
| `REQ-AUTH-004` | 보호된 닉네임은 올바른 비밀번호로만 접근                  |
| `REQ-AUTH-005` | 로그인 후 매물 목록 이동, 마이페이지 표시                 |
| `REQ-AUTH-006` | 로그아웃 후 개인 데이터 접근 종료                         |
| `REQ-AUTH-007` | 다른 회원 자원 접근 차단(미인증 401, 타인 자원 404)       |
| `REQ-AUTH-008` | 로그인 실패 안내, 실패를 회원 생성·성공으로 처리하지 않음 |

## 관련 인수 기준

`AC-AUTH-001` ~ `AC-AUTH-010`

## Scenario

아직 작성하지 않았다. 다른 Flow의 Scenario는 사전 조건으로 이 Flow의 "새 닉네임, 비밀번호 없이 시작"을 사용한다.

## QA 메모

- `REQ-AUTH-007`은 모든 자원에 걸친다. 매물·사진의 권한 확인은 각 Flow의 인수 기준(`AC-PROP-010`, `AC-PHOTO-008`)에서도 함께 본다.
- 로그인 유지·만료 동작은 [미정 영역](../source-of-truth.md#4-미정-영역)이다.
