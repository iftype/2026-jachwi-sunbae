# F04 사진 기록 관리

| 항목        | 내용                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| 사용자 목적 | 집의 실제 모습을 사진으로 남기고, 대표 사진으로 후보를 구분한다.                                               |
| 진입점      | 매물 상세의 사진 영역                                                                                          |
| 선행 Flow   | F02                                                                                                            |
| 관련 명세   | [사진](../../../docs/product/specs/photo.md), [공통 삭제 정책](../../../docs/product/README.md#공통-삭제-정책) |

## 핵심 흐름

1. 매물에 사진 여러 장을 업로드한다.
2. 사진별 업로드 결과를 확인하고, 실패한 사진만 다시 시도한다.
3. 첫 사진이 대표로 지정된다. 필요하면 다른 사진을 대표로 바꾼다.
4. 매물 목록·상세에서 대표 사진을 확인한다. 사진이 없으면 기본 이미지가 보인다.
5. 사진을 삭제한다. 대표 사진을 지우면 남은 첫 사진이 대표가 된다.

## 관련 요구사항

| ID              | 확인할 점                                 |
| --------------- | ----------------------------------------- |
| `REQ-PHOTO-001` | 자신의 매물 사진 업로드·조회·삭제         |
| `REQ-PHOTO-002` | 첫 사진 자동 대표, 대표 직접 지정         |
| `REQ-PHOTO-003` | 목록·상세의 대표 사진, 없으면 기본 이미지 |
| `REQ-PHOTO-004` | 사진별 업로드 결과와 실패분 재시도        |
| `REQ-PHOTO-005` | 재진입 후 사진 조회                       |
| `REQ-PHOTO-006` | 대표 삭제 시 남은 첫 사진을 대표로 지정   |

## 관련 인수 기준

`AC-PHOTO-001` ~ `AC-PHOTO-011`

## Scenario

아직 작성하지 않았다.

## QA 메모

- `AC-PHOTO-009`, `AC-PHOTO-010`은 저장 실패를 일부러 만들어야 한다. DEV에서 재현할 방법이 정해지기 전까지 우선순위를 낮춘다.
- 사진의 논리 삭제 후 실제 파일이 남는지는 화면만으로 확인할 수 없다. 서버·저장소 Evidence가 필요하다.
