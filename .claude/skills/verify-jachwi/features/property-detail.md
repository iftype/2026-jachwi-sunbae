# 매물 상세

기록한 방 하나의 정보, 사진, 메모, 체크리스트를 보고 고치는 화면이다. 데스크탑은 지도 왼쪽 옆에 `선택한 매물 상세` 패널로 열린다. 상태: 검증됨(2026-11-22, 데스크탑 1440x900, 실제 네이버 지도, 실제 매물 생성과 수정과 삭제까지). iPhone(WebKit) 검증됨(2026-11-25, 정보 탭과 사진 크게 보기).

## Sub-features

- `detail-open` 리스트 카드나 지도 마커로 연다. 주소는 `/properties/<id>`.
- `detail-create` 지도 빈 곳 `본 방 기록하기`로 새 매물을 만든다.
- `detail-info-edit` `매물 이름`, `보증금 / 월세`(입력칸 `보증금 (만원)`, `월세 (만원)`), `주소`를 항목별로 고친다. 부가 정보(입주 가능일, 관리비, 관리비 포함 공과금, 방 옵션, 방문 일정, 확인한 곳)도 같은 방식이다.
- `detail-nearby` 기본 정보 아래 주변 지수(`교통`, `편의점`, `병원`, `중개업소` 개수와 거리). 누르면 지도에 해당 시설이 켜진다.
- `detail-tabs` 탭 `정보`, `체크리스트`(주소가 `?tab=checklist`로 바뀐다).
- `detail-navigate` `이전 매물`, `다음 매물`, `목록으로 돌아가기`, `상세 접기`.
- `detail-photos`, `detail-memo`, `detail-edit` 사진(`/properties/:id/photos`), 메모(`/memo`), 편집(`/edit`).
- `detail-delete` 홈 리스트 카드의 `<매물 이름> 메뉴` 안 `<매물 이름> 삭제`.

## How to get to it (user POV)

- 홈 리스트의 카드 링크나 지도 마커.
- 주소창 `/properties/<id>`. 샘플은 `/properties/-1`.
- 새 매물은 홈 지도 빈 곳 `본 방 기록하기` 직후 자동으로 열린다.

## Driving it with Chrome DevTools MCP

Preconditions: doctor 통과, 새 `isolatedContext`(새 익명 회원), 네이버 키가 있는 `.env.local`.

- **샘플 열기.** 홈에서 마커 `(미리보기) 코엑스 근처`를 누르거나 `new_page http://localhost:3217/properties/-1`. `선택한 매물 상세`, 제목, `기본 정보` 아래 `보증금 / 월세 3,000만원 / 55만원, 수정`, `주소 서울 강남구 영동대로 513, 수정` 버튼이 보인다. 샘플의 수정은 서버로 가지 않는다(아래 함정).
- **새 매물 만들기.** [지도](./map.md)의 좌표 클릭으로 빈 곳을 누르고 메뉴 `이 위치에서`의 `본 방 기록하기`를 누른다. `POST /api/properties` 201이고 주소가 `/properties/<새 id>`로 바뀌며 `매물 이름` 입력칸이 포커스된 채 열린다. 이름은 `새 매물`이다.
- **이름 고치기.** 입력칸에 `fill`하고 `Enter`. `PUT /api/properties/<id>` 200.
- **가격 고치기.** `보증금 / 월세 비어 있음, 수정` 버튼을 누르면 `보증금 (만원)`, `월세 (만원)` 입력칸이 열린다. 둘을 `fill`하고 `Enter`. 리스트 카드가 `보증금 1,000만원 / 월세 60만원`으로 바뀐다.
- **증명.** `reload` 뒤 `wait_for`로 `선택한 매물 상세`를 기다려 값이 남았는지 스냅샷으로 본다. 요청은 `PUT` 200. 상태 줄 `매물을 기록했어요. 항목을 눌러 정보를 채워 주세요.`가 새 매물 직후에 한 번 나온다.
- **지우기.** 홈 `<매물 이름> 메뉴` -> `<매물 이름> 삭제`. 확인 창 없이 바로 `DELETE /api/properties/<id>` 204, 샘플이 다시 나온다.

## iPhone(WebKit) 경로

- 실행(`qa`): `npm run test:iphone`이 운영 빌드를 한 번 하고 `serve.mjs --api mock --delay 300`으로 띄워 iPhone 경로 전부를 돈다. 이 기능만은 `npm run test:iphone -- property-detail`. 지도 키(`frontend/.env.local`의 `NAVER_MAP_CLIENT_ID`)가 있으면 실제 SDK, 없으면 `map-sdk-stub.mjs`다. 코드는 `qa/tests/iphone/property-detail.spec.ts`.
- 경로:
  1. `/`를 열고 `하단 탭`의 `내 기록, 리스트로 보기`를 누른 뒤 `모든 기록`의 `신림역 원룸`을 누른다. 주소가 `/properties/10`이다.
  2. 끝 상태(정보 탭): 제목 `신림역 원룸`, 탭 `정보`가 선택됨, `매물 기본 정보`에 `보증금 / 월세 1,000만원 / 55만원`, `주소 서울 관악구 신림로 12길 3`.
  3. `신림역 원룸 대표 사진 크게 보기`를 누르면 대화상자 `신림역 원룸 사진 크게 보기`가 `1 / 2`로 열린다. `다음 사진`으로 `2 / 2`가 되고, `사진 크게 보기 닫기`로 닫힌다. 상세 화면에는 하단 탭이 없다.
- 경로 끝마다 우리 출처(`QA_BASE_URL`)의 콘솔 오류와 실패한 요청(4xx, 5xx, 끊김)이 0인지 본다. 스크린샷은 `qa/runs/iphone/shots/`의 `property-detail-photo-viewer.png`, `property-detail-info.png`, 결과 요약은 `qa/runs/iphone/summary.md`다.

## Gotchas

- `/properties/-1`은 클라이언트 미리보기다. 이름을 고쳐도 PUT이 없고 이름은 그대로이며, 홈 위쪽에 `<이름> 기록를 고치던 중이었어요 이어서 보기` 배너만 생긴다(브라우저에 임시 저장). 저장 검증은 반드시 실제 매물로 한다.
- 방을 하나라도 등록하면 샘플이 사라지고, 지우면 다시 나온다.
- 지도에서 강변처럼 주소가 없는 곳을 누르면 `GET /api/maps/reverse-geocode`가 404이고 카드에 `지원하지 않는 주소입니다`, 주소는 `비어 있음`, 동네 묶음은 `주소 미등록`이 된다. 결함이 아니다. 주소가 있는 곳을 누르려면 먼저 주소 검색으로 지도를 옮긴다.
- 새 매물은 이름이 `새 매물`이라 검증용으로 알아보려면 이름을 바꿔 둔다(`검증용 새 매물`). 증거 이름 규칙으로 `검증용`을 앞에 붙인다.
- 같은 화면을 다시 열 때마다 `POST /api/auth/login`이 또 나가도 같은 회원이다. 매물이 남아 있으면 그 회원이다.
- dev API 모드(기본은 mock이라 남지 않는다)에서 이 기능을 돌리면 dev DB에 매물이 생긴다. 끝나면 삭제 경로로 지운다. 익명 회원은 남는다.
- 휴대폰은 다른 컴포넌트다. 이 문서는 데스크탑만 돌렸다.
- 증거 위치: `qa/runs/verify-jachwi/property-detail-20261122/`.
- iPhone 경로는 Playwright의 WebKit 엔진(리눅스 WPE 빌드)에 iPhone 15 기기 설정(화면 393x659, 터치, 모바일 UA, 배율 3)을 준 것이다. iOS 실기기의 Safari가 아니다. 주소창과 홈 표시줄이 줄이는 높이, 안전 영역(`safe-area-inset`), 키보드가 올라올 때의 화면 높이 변화, 관성 스크롤은 재현하지 않는다.
- 손가락 제스처는 흉내다. 탭은 터치 탭이지만 끌기(시트 손잡이)는 마우스 포인터 끌기로 낸다(`qa/src/iphone.ts`의 `dragBy`). 앱이 Pointer Events로 받아 같은 코드를 지나지만 실제 터치 이벤트 순서와 다를 수 있다. 핀치 확대와 지도 끌기는 하지 않는다(마우스 끌기로는 지도가 움직이지 않았다).
