# 위치 선택

좌표가 없는 매물의 위치를 지도에서 골라 저장하는 화면(`/map/select-location`)이다. 상태: 검증됨(2026-11-25, iPhone(WebKit)). 데스크탑은 이 화면으로 가지 않고 옆 지도에서 고른다(그 동작을 검증함).

## Sub-features

- `select-search` 영역 `매물 위치 선택 지도` 위 `주소 검색`(자리 표시 `주소로 위치 찾기`). 결과를 고르면 지도가 그 자리로 간다.
- `select-map` 지도를 눌러 자리를 바꾼다. `내 현재 위치로 이동`.
- `select-confirm` 아래 시트의 주소와 `이 위치로 저장`. 저장하면 들어온 화면(`returnTo`)으로 돌아간다.

## How to get to it (user POV)

- 휴대폰: 좌표가 없는 매물 상세에서 `주소 <주소>, 수정`을 누르고 `지도에서 고르기`. 좌표가 있는 매물은 상세 안에서 바로 고친다(이 화면으로 가지 않는다).
- 휴대폰과 데스크탑: 매물 편집(`/properties/:id/edit`)의 `지도에서 위치 선택`. 편집은 좌표 없는 매물의 주변 분석 `위치 등록하기`에서만 들어간다(코드 기준, 화면으로 돌리지 않았다).
- 데스크탑 매물 상세는 `지도에서 고르기`를 누르면 옆 본 방 기록 지도가 `지도를 눌러 새 위치를 고르세요.` 상태가 된다.
- 돌아갈 곳(`returnTo`) 없이 주소로 바로 들어오면 홈으로 보낸다.

## 데스크탑과 iPhone(WebKit) 경로

- 실행(`qa`): `npm run test:iphone -- --device all map-select-location`. 코드는 `qa/tests/<desktop|iphone>/map-select-location.spec.ts`.
- 목 매물은 모두 좌표가 있어, 경로가 매물 11(`망원동 투룸`)의 상세 응답에서만 좌표를 비운다(`page.route`, 앱 코드는 그대로). 예전에 주소만 저장된 기록과 같은 모양이다.
- iPhone:
  1. `/properties/11`에서 `주소 서울 마포구 월드컵로 10길 12, 수정`을 누르고 `지도에서 고르기`를 누르면 주소가 `/map/select-location`이다.
  2. `주소 검색`에 `세종대로`를 넣어 결과 `서울 중구 세종대로 110`을 고르면 시트에 그 주소가 나온다.
  3. 좌표 비우기를 멈추고 `이 위치로 저장`을 누르면 저장 요청(GET이 아닌 `/api/properties/11`)이 성공하고 `/properties/11`로 돌아와 `주소 서울 중구 세종대로 110, 수정`이 보인다.
- 데스크탑: 같은 1번 뒤 상태 `지도를 눌러 새 위치를 고르세요.`가 보이고 주소는 `/properties/11` 그대로다. Esc로 이 상태를 끈다([머지로 생기는 동작](./merge-behaviors.md)).

## Gotchas

- 저장한 뒤에는 실제로 좌표가 생기므로 좌표 비우기를 그 전에 멈춘다. 계속 비우면 상세가 주변 시설 요청을 냈다가 스스로 취소한다.
- 목 서버는 한 번 띄우는 동안 상태를 기억한다. 매물 10은 매물 상세 경로가 주소를 보므로 이 경로는 매물 11을 쓴다.
