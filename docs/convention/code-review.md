# 코드 리뷰

## 리뷰 규칙

리뷰는 명령보다 질문과 근거를 중심으로 작성한다.

```text
현재 메서드가 검증과 생성을 함께 담당하고 있어
책임을 분리해 보는 것은 어떨까요?
```

리뷰 코멘트는 다음과 같이 구분한다.

| 태그 | 의미                       |
| ---- | -------------------------- |
| `R:` | 반드시 수정이 필요한 의견  |
| `C:` | 함께 고민할 의견           |
| `Q:` | 구현 의도에 대한 질문      |
| `S:` | 선택적으로 반영할 제안     |
| `P:` | 잘 구현된 부분에 대한 칭찬 |

리뷰이는 모든 코멘트에 답변하며, 반영하지 않을 때는 이유를 남긴다.

## 리뷰 문화

- 사람보다 코드를 대상으로 리뷰한다.
- 리뷰어의 의견을 정답처럼 강요하지 않는다.
- 리뷰이는 무조건 반영하지 않고 자신의 근거를 남긴다.
- 잘한 부분도 함께 언급한다.
- 스타일보다 요구사항과 객체의 책임을 우선한다.
