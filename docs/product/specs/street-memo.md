# 거리 메모 정책

- 대상: 지도 위 동네 정보와 작성자 선호의 작성·조회·삭제 (작성자 본인만 본다)
- 관련 이슈: [#436 거리 메모 기능 구현](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/436), [#567 거리 메모 행정동 저장과 행정동 기준 조회](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/567)
- 구현 범위: 스키마·도메인·JDBC 저장소·서비스와 작성·조회·삭제 API, 본 방 기록 지도의 작성·조회·삭제 화면을 구현했다(동네 찾기 지도에는 메모를 띄우지 않는다). 작성할 때 행정동을 함께 저장하고 작성·영역 조회 응답에 메모마다 행정동 코드를 담는다.

## 1. 목적과 범위

사용자는 지도에서 선택한 위치에 동네 정보와 좋아요·싫어요 선호를 함께 남기고, 자신이 남긴 메모를 다시 확인한다. 거리 메모는 작성자 본인만 보는 개인 기록이다.
예를 들어 편리한 무인 세탁소에는 좋아요, 소음이 심한 골목에는 싫어요를 선택해 메모를 작성한다.

선호는 작성자가 메모를 처음 작성할 때 입력하는 단일 구분값이다.
프론트엔드는 서버가 제공하는 선호값으로 좋아요·싫어요를 구분해 표시한다.
서버는 조회 대상과 본인 삭제 권한을 정하기 위해 회원 ID를 내부적으로 보관하며, 응답에는 작성자 식별 정보를 제공하지 않는다.

### 제공 범위

- 지도에서 선택한 위치에 메모와 좋아요·싫어요 선호를 함께 작성
- 자신이 작성한 메모의 위치·내용·선호 조회
- 메모 위치가 속한 행정동 저장과 응답의 행정동 코드 제공
- 작성자 본인의 메모 삭제
- 다른 회원에게 노출되지 않는 개인 기록

메모 수정, 사진, 카테고리, 다른 회원과의 공유, 반응·투표 집계, 댓글, 북마크, 링크 공유는 이번 범위에 포함하지 않는다.
인증은 기존 익명 인증을 사용하며, 우선 메모의 선호값을 저장하고 조회해 표시하는 데 집중한다.

## 2. 요구사항

### 2.1. 기능 요구사항

- `REQ-STREET-001`: 회원은 지도에서 위치를 선택하고 해당 위치에 메모를 작성할 수 있다.
- `REQ-STREET-002`: 매물을 등록하지 않은 회원도 거리 메모를 작성하고 조회할 수 있다.
- `REQ-STREET-003`: 회원은 자신이 작성한 메모의 위치·내용·선호만 확인할 수 있다. 다른 회원이 작성한 메모는 조회 결과와 화면에 나오지 않는다.
- `REQ-STREET-004`: 조회 응답과 화면에 작성자의 회원 ID·닉네임·프로필 등 식별 정보를 제공하지 않는다.
- `REQ-STREET-005`: 작성자는 자신의 메모를 삭제할 수 있다. 작성·조회 응답의 `isMine`으로 삭제 버튼을 표시한다. 다른 회원은 해당 메모를 삭제할 수 없다.
- `REQ-STREET-006`: 삭제한 메모는 이후 새로 조회하는 지도와 메모 조회 결과에서 제외한다.
- `REQ-STREET-007`: 저장 후 다시 조회하거나 화면에 재진입해도 저장한 위치·내용·선호가 유지된다.
- `REQ-STREET-008`: 작성·조회·삭제 실패를 성공과 구분해 안내한다. 메모 없음과 조회 실패를 구분한다.
- `REQ-STREET-009`: 작성자는 메모 최초 작성 시 좋아요 또는 싫어요 중 하나를 필수로 선택한다.
- `REQ-STREET-010`: 조회 응답은 메모마다 `preference`를 포함한다. 프론트엔드는 이 값으로 좋아요·싫어요를 구분해 표시한다.
- `REQ-STREET-011`: 메모를 작성하면 서버가 메모 위치가 속한 행정동을 찾아 함께 저장한다.
- `REQ-STREET-012`: 작성·조회 응답은 메모마다 저장된 행정동 코드 `adminDongCode`를 포함한다.

## 3. 정책

### 3.1. 회원과 공개 범위

- `POL-STREET-001`: 기존 [익명 인증 정책](authentication.md)을 따른다. 별도의 닉네임·프로필 입력을 요구하지 않는다.
- `POL-STREET-002`: 작성자는 요청의 인증 정보로 결정한다. 클라이언트가 전달한 회원 ID로 다른 회원의 메모를 생성하거나 삭제할 수 없다.
- `POL-STREET-003`: 저장한 메모는 작성자 본인만 조회할 수 있는 개인 데이터다. 다른 회원에게 공개하거나 공유로 전환하는 기능은 제공하지 않는다. 공유 메모로 운영하던 때 작성한 메모도 이제 작성자에게만 보인다.
- `POL-STREET-004`: `member_id`는 조회 대상과 소유권 확인에만 사용하며 응답에 포함하지 않는다. 조회 결과는 본인 메모뿐이라 `isMine`은 늘 `true`이며, 기존 클라이언트 호환을 위해 필드를 유지한다. 프론트엔드는 이 값으로 삭제 버튼을 표시한다. 실제 삭제 권한은 서버에서 별도로 검증하며 클라이언트가 보낸 `isMine`을 신뢰하지 않는다.
- `POL-STREET-005`: 소유권은 회원 ID를 기준으로 판단한다. 인증 정보가 사라져 새 익명 회원이 만들어지면 같은 사람이더라도 이전 메모의 삭제 권한을 자동으로 부여하지 않는다.

### 3.2. 위치와 메모 내용

- `POL-STREET-006`: 하나의 메모는 지도에서 선택한 하나의 위치·내용·선호를 가진다. 매물이나 외부 시설 ID 연결을 필수로 요구하지 않는다.
- `POL-STREET-007`: 위도·경도는 함께 입력하며 각각 -90 이상 90 이하, -180 이상 180 이하를 허용한다. 위치 선택이나 좌표 전달 실패 시 임의의 대체 위치에 메모를 저장하지 않는다.
- `POL-STREET-008`: 메모 내용은 필수이며 `null`을 허용하지 않는다. 빈 문자열·공백만 있는 내용의 처리와 최대 글자 수는 후속 입력 정책에서 결정한다.
- `POL-STREET-009`: 저장하는 좌표는 사용자가 선택한 메모 대상 위치다. 작성자의 현재 위치나 이동 경로를 거리 메모의 별도 데이터로 수집하지 않는다.

### 3.3. 좋아요·싫어요 선호

- `POL-STREET-010`: `preference`는 작성자가 메모 최초 작성 시 입력하는 필수 값이다. 메모당 하나만 저장하며 기본값을 지정하지 않는다.
- `POL-STREET-011`: 대문자 코드 `LIKE`, `DISLIKE`만 허용한다. 누락·`null`·빈 문자열·정의되지 않은 값은 거부한다. 중립·미선택 상태는 저장하지 않는다.
- `POL-STREET-012`: 조회 응답은 저장된 `preference`를 그대로 제공한다. 프론트엔드는 메모 내용에서 선호를 추측하지 않고 코드에 따라 표시한다.

| 저장·응답 코드 | 화면 의미 | 입력 주체   |
| -------------- | --------- | ----------- |
| `LIKE`         | 좋아요    | 메모 작성자 |
| `DISLIKE`      | 싫어요    | 메모 작성자 |

좋아요·싫어요 개수, 다른 회원의 투표 이력이나 반응 변경 기능은 현재 데이터에 포함하지 않는다.

### 3.4. 조회와 삭제

- `POL-STREET-013`: 지도에 보이는 사각형 영역을 기준으로 조회한다. 최소·최대 위도와 최소·최대 경도를 모두 전달하며 영역 경계의 메모도 포함한다. 해당 영역 안에서 인증된 회원이 작성하고 `deleted_at`이 `NULL`인 메모만 조회한다.
- `POL-STREET-014`: 삭제 요청은 인증된 회원 ID와 메모의 `member_id`가 일치하는 경우에만 처리한다. 존재하지 않거나 이미 삭제됐거나 타인이 소유한 메모의 삭제 요청은 기존 자원 접근 정책에 맞춰 `404`로 처리한다.
- `POL-STREET-015`: 삭제는 `deleted_at`에 서버에서 정한 시각을 기록하는 논리 삭제다. `updated_at`도 같은 시각으로 갱신하며 기존 내용·선호·작성 시각을 유지한다. 해당 요청으로 행을 물리 삭제하지 않는다.
- `POL-STREET-016`: 작성·수정 시각은 `BaseTimeEntity`의 공통 필드로 보관한다. 메모 내용과 선호의 수정 기능 제공 여부는 5절에서 별도 결정한다.

### 3.5. 행정동

- `POL-STREET-017`: 작성할 때 서버가 `admin_dongs`의 행정동 경계로 메모 좌표가 속한 행정동 코드를 찾아 함께 저장한다. 클라이언트는 행정동을 보내지 않는다. 단순화한 경계가 겹쳐 두 행정동에 들어가는 좌표는 노선망 적재와 같이 코드가 가장 작은 행정동으로 정한다.
- `POL-STREET-018`: 좌표가 어느 행정동에도 들지 않거나 행정동 경계가 아직 적재되지 않았으면 행정동을 비워 두고 메모는 저장한다. 행정동 경계를 읽는 중 DB 장애가 나면 작성을 실패로 처리한다.
- `POL-STREET-019`: 작성·영역 조회 응답은 메모마다 저장된 `adminDongCode`를 그대로 제공한다. 행정동을 찾지 못했거나 행정동 저장 전에 작성한 메모는 `null`이다. 행정동 기준 조회 API는 따로 두지 않는다.
- `POL-STREET-020`: 행정동 저장 전에 작성된 메모는 행정동을 비워 둔다. 행정동 경계를 다시 적재해도 이미 저장한 메모의 행정동은 바꾸지 않는다. 서버는 행정동 경계를 처음 한 번 읽어 메모리에 두므로, 다시 적재한 경계는 서버를 재시작해야 새 메모에 반영된다.
- `POL-STREET-021`: 본 방 기록 지도는 확대 단계 하나로 화면의 모든 메모 표시를 정하고, 한 단계 안에서 묶음과 낱개를 섞지 않는다. 정수로 반올림한 단계가 5보다 멀면 `adminDongCode`가 같은 메모를 동마다 좋아요, 싫어요 개수 묶음 하나로 메모 평균 좌표에 두고, 코드가 없는 메모는 숨긴다. 5단계부터는 코드가 없는 메모까지 모두 하나씩 둔다. 묶음을 누르면 그 묶음 자리를 가운데 두고 5단계로 확대한다. 화면 거리로 메모를 묶는 방식은 쓰지 않는다.

### 3.6. 저장 데이터와 조회 응답

테이블은 `street_memos`이며 [V6 마이그레이션](../../../backend/src/main/resources/db/migration/V6__create_street_memos.sql)으로 추가하고 [V10 마이그레이션](../../../backend/src/main/resources/db/migration/V10__add_street_memo_admin_dong.sql)으로 행정동 코드를 더한다.
아래 표는 내부 저장 구조다. 응답에서는 작성자 식별 정보를 제외한다.

| 필드              | 저장 타입        | 필수 여부 | 의미                                                                            |
| ----------------- | ---------------- | --------- | ------------------------------------------------------------------------------- |
| `id`              | `BIGINT`         | 필수      | 서버가 생성하는 메모 식별자                                                     |
| `member_id`       | `BIGINT`         | 필수      | 작성자 회원 참조. 조회 대상을 정하고 응답에서는 제외한다.                       |
| `latitude`        | `DECIMAL(10, 7)` | 필수      | 메모 대상 위치의 위도                                                           |
| `longitude`       | `DECIMAL(11, 7)` | 필수      | 메모 대상 위치의 경도                                                           |
| `admin_dong_code` | `VARCHAR(10)`    | 선택      | 작성할 때 찾은 행정동 코드. 찾지 못했거나 행정동 저장 전에 작성한 메모는 `NULL` |
| `memo`            | `TEXT`           | 필수      | 사용자 작성 내용. 최대 입력 길이는 별도 정책으로 정한다.                        |
| `preference`      | `VARCHAR(10)`    | 필수      | 작성 시 선택한 `LIKE` 또는 `DISLIKE`. 기본값 없음.                              |
| `created_at`      | `DATETIME(6)`    | 필수      | 서버에서 기록하는 작성 시각                                                     |
| `updated_at`      | `DATETIME(6)`    | 필수      | 서버에서 기록하는 수정 시각                                                     |
| `deleted_at`      | `DATETIME(6)`    | 선택      | 미삭제 시 `NULL`, 삭제 시 삭제 시각                                             |

현재 스키마는 작성자 외래 키, 좌표 범위·선호값 제약과 `(deleted_at, latitude, longitude)` 영역 조회 인덱스, `(admin_dong_code, deleted_at)` 행정동 인덱스를 둔다. 본인 메모 조회는 작성자 외래 키 인덱스로 회원의 메모를 먼저 좁힌다. `admin_dongs`는 다시 적재할 때 모두 비우고 채우므로 `admin_dong_code`에는 외래 키를 두지 않는다.
주소·장소명·사진·카테고리·공개 범위 필드는 현재 저장하지 않는다.
조회 기준 위치에서 메모까지의 거리가 필요하면 조회 시 계산하며 메모의 고정 데이터로 저장하지 않는다.

응답의 메모 데이터는 본인 여부와 행정동 코드를 포함해 다음 일곱 필드를 제공한다. HTTP 식별자 이름은 API 컨벤션에 맞춰 `streetMemoId`를 사용하며 작성자·시각 필드는 포함하지 않는다.

```json
{
  "streetMemoId": 1,
  "latitude": 37.3948,
  "longitude": 127.1112,
  "memo": "저녁에 배달 오토바이가 많이 다녀요.",
  "adminDongCode": "11680640",
  "preference": "DISLIKE",
  "isMine": true
}
```

`com.jachwisunbae.streetmemo.domain`에서 확정된 불변 조건과 상태 변경 규칙을 관리한다.

| 객체                                                                                                                | 책임                                                                  |
| ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| [StreetMemo](../../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemo.java)                     | 생성·저장 데이터 복원, 작성자 소유권 판단, 논리 삭제와 시간 상태 관리 |
| [StreetMemoLocation](../../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemoLocation.java)     | 필수 위도·경도와 허용 범위 검증                                       |
| [StreetMemoPreference](../../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemoPreference.java) | `LIKE`·`DISLIKE` 구분과 대문자 코드 변환                              |

- 생성할 때 메모 ID와 삭제 시각은 없으며 작성·수정 시각은 전달받은 서버 시각으로 초기화한다.
- 복원할 때 저장된 ID, 내용·선호와 작성·수정·삭제 시각을 유지한다. 작성자 ID와 복원할 메모 ID는 양수여야 한다.
- 시각은 작성·수정·삭제 순서를 지켜야 한다. 삭제 요청의 시각은 마지막 수정 시각과 같거나 이후여야 한다.
- 현재 내용 검증은 `null` 필수 제약을 적용하며 전달받은 공백·줄바꿈을 보존한다. 최대 길이와 빈 문자열·공백만 있는 내용의 처리 정책은 5절에서 결정한다.
- 내용·위치·선호 입력 오류는 각각 `STREET_MEMO_CONTENT_INVALID`, `STREET_MEMO_LOCATION_INVALID`, `STREET_MEMO_PREFERENCE_INVALID`로 구분한다. 이미 삭제됐거나 타인이 소유한 메모의 삭제는 `STREET_MEMO_NOT_FOUND`로 거부한다.
- DB 복원 중 도메인 입력 검증이나 내부 불변식 검증에 실패하면 Repository에서 기존 [예외 컨벤션](../../../backend/docs/conventions/exception-convention.md)에 따라 `DataInconsistencyException`으로 변환한다.

### 3.8. 서비스와 저장소 구현

| 객체                                                                                                                            | 책임                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| [StreetMemoService](../../../backend/src/main/java/com/jachwisunbae/streetmemo/service/StreetMemoService.java)                  | 작성·지도 영역 조회·본인 삭제 유스케이스와 트랜잭션 관리                   |
| [AdminDongFinder](../../../backend/src/main/java/com/jachwisunbae/transit/service/AdminDongFinder.java)                         | 행정동 경계를 처음 한 번 읽어 메모리에 두고 좌표가 속한 행정동 코드를 찾음 |
| [JdbcStreetMemoRepository](../../../backend/src/main/java/com/jachwisunbae/streetmemo/repository/JdbcStreetMemoRepository.java) | 메모 저장, 영역 SQL 조회, 삭제 행 잠금과 논리 삭제, 저장 데이터 복원       |
| [StreetMemoResult](../../../backend/src/main/java/com/jachwisunbae/streetmemo/service/dto/result/StreetMemoResult.java)         | 작성자 식별자를 제외한 메모 ID·위도·경도·내용·선호·본인 여부 전달          |

- 작성·삭제 시 회원 서비스를 통해 현재 유효한 회원인지 확인한다. 작성자는 인증 경계에서 전달받은 회원 ID로 정하고, 시각은 공통 `Clock`에서 얻는다.
- 작성·삭제는 쓰기 트랜잭션, 조회는 읽기 전용 트랜잭션으로 처리한다. 저장에 실패하면 성공 결과를 반환하지 않으며 DB 변경을 롤백한다.
- 조회 요청의 회원 ID는 인증 정보에서 얻는다. 작성·조회 결과의 `isMine`은 서버에서 계산하며, 생성된 메모는 `true`를 반환한다.
- 영역 조회는 서비스의 `validateBounds()`에서 네 좌표의 필수값·허용 범위·최소 및 최대 순서를 검증한다. 잘못된 영역은 `STREET_MEMO_QUERY_INVALID`로 거부하며 저장소를 호출하지 않는다. 검증한 좌표 네 개와 회원 ID를 저장소에 직접 전달해 SQL에서 작성자, 삭제 여부와 위도·경도 범위로 조회한다. 빈 결과는 빈 목록으로 반환하고 DB 장애는 실패로 전달한다.
- 삭제는 대상 행을 잠근 뒤 도메인에서 소유권과 상태를 검증한다. 저장소에서도 메모 ID·작성자·미삭제 조건을 확인하며 실제 변경된 행이 없는 경우 삭제 성공으로 처리하지 않는다.
- 동일한 메모를 동시에 삭제할 때 한 요청만 성공하고 나머지는 `STREET_MEMO_NOT_FOUND`로 처리한다. 최초 삭제 시각을 덮어쓰지 않는다.
- 조회 결과의 정렬 순서·최대 개수는 현재 보장하지 않으며 5절의 후속 정책에서 결정한다. 인증 토큰 검증과 HTTP 응답 변환은 API 계층의 책임이다.

### 3.9. API 구현과 검증 경계

- [StreetMemoController](../../../backend/src/main/java/com/jachwisunbae/streetmemo/controller/StreetMemoController.java)는 기존 익명 인증 필터를 통해 작성·조회·삭제 요청의 Access Token을 검증한다. 작성·삭제의 회원 ID는 인증 정보에서만 얻는다.
- 작성 요청의 위도·경도·내용·선호 누락과 `null`은 Request DTO에서 검증한다. 빈 문자열·공백만 있는 메모는 아직 제한하지 않고 공백·줄바꿈을 보존한다. 선호는 도메인의 코드 변환을 통해 대문자 `LIKE`, `DISLIKE`만 허용한다.
- 지도 영역 좌표 네 개는 별도 영역 객체 없이 서비스로 전달한다. 누락·범위·순서 오류는 서비스의 `validateBounds()`가 검증하고, 숫자로 읽을 수 없는 요청은 공통 HTTP 예외 처리기가 거부한다.
- 생성 성공은 `201`과 생성 위치를, 조회 성공은 `200`과 메모 배열을, 삭제 성공은 본문 없는 `204`를 반환한다. 작성·조회 데이터는 전용 Response DTO를 거쳐 공통 성공 응답 형식에 담는다.
- Controller는 매핑 어노테이션과 `@Operation`으로 경로와 API 목적을 표시하고, `@SecurityRequirement`로 다른 API와 동일한 Bearer 인증을 Swagger에 선언한다. 요청·응답 구조는 DTO에서 확인한다. 인수 테스트는 실제 로그인 토큰과 MySQL을 사용해 본인 메모만 조회·삭제 권한·입력 검증·작성자 비노출과 인증 누락·잘못된 토큰 거부, Swagger의 인증 요구사항을 검증한다.
- 같은 입력 조합을 계층마다 반복 검사하지 않는다. 주요 기능 흐름은 API 인수 테스트에서 검증하고, 통합 테스트는 좌표 저장 정밀도·저장 실패 롤백·동시 삭제·저장 데이터 오류를 확인한다. 도메인 테스트는 좌표 경계와 삭제 시각 규칙에 집중하며 마이그레이션 테스트는 기존 데이터 보존과 주요 DB 제약을 확인한다.

### 3.10. 화면 구현

- 본 방 기록 지도 (`/properties`)는 메모 버튼 없이 지도 화면 범위의 메모를 늘 좋아요, 싫어요 색으로 나눈 마커로 보여준다(아주 멀리 축소하면 숨긴다). 매물 주변 분석 화면에는 메모 탭을 두지 않는다.
- 동네 찾기 결과 지도에는 거리 메모를 띄우지 않는다.
- 지도의 빈 곳을 찍으면 찍은 자리에서 할 일을 고른다. 본 방 기록 지도는 데스크탑과 휴대폰 모두 찍은 자리의 말풍선에서 메모 남기기와 매물 등록을 제공한다.
- 매물·메모·정류장 정보나 동작 목록이 열려 있을 때 지도를 찍으면 닫기만 하고 새 동작 목록을 띄우지 않는다.
- 멀리 볼 때의 행정동 묶음(`POL-STREET-021`)은 좋아요와 싫어요 개수를 `👍 n`, `👎 n`으로 적는다. 메모 마커는 배율 4까지 그대로 두고, 그보다 멀리 축소하면 한 단계마다 0.1씩 작게 그린다 (최소 0.6배). 낱개 메모를 누르면 배율 5까지 다가가되 지금보다 멀리 축소하지는 않는다.
- 찍은 자리를 꼬리로 가리키는 말풍선에서 고른다. 데스크탑은 메모를 기록 지도 위 카드에서, 휴대폰은 바텀시트에서 쓰고 본다. 동네 찾기 결과 지도에는 메모를 올리지 않는다.
- 작성 폼은 좋아요·싫어요를 기본값 없이 꼭 고르게 하고, 공백만 있는 내용은 보내지 않는다. 메모를 남기면 상세를 열지 않고 남긴 자리에 쓴 글을 말풍선으로 잠깐 띄웠다가 지우며, 기록 지도는 늘 켜 둔 메모에 마커로 남긴다.
- 메모 내용은 텍스트로만 표시하며 입력한 공백과 줄바꿈을 유지한다. `isMine`이 `true`인 메모에만 지우기 버튼을 두고, 한 번 더 확인한 뒤 지운다.
- 지도의 메모는 모두 내가 남긴 메모다. 화면 문구와 랜딩 안내에서 다른 사람이 보거나 다른 사람 메모를 본다고 안내하지 않는다.
- 메모는 개인 기록이라 분석 이벤트에 메모 내용을 싣지 않는다. 메모 ID와 선호만 싣는다.

| AC-STREET-013 | HTML·스크립트 형태의 메모를 조회한다.                                       | 코드가 실행되지 않고 텍스트로 표시된다.                                                          |
| AC-STREET-014 | A의 인증 정보가 사라져 새 익명 회원 C로 시작한 뒤 A의 메모 삭제를 시도한다. | C에게 A의 메모 삭제 권한을 자동으로 부여하지 않는다.                                             |
| AC-STREET-015 | 행정동 X 안의 위치에 메모를 작성한 뒤 영역 조회한다.                        | 작성·조회 응답의 `adminDongCode`가 X의 코드다.                                                   |
| AC-STREET-016 | 어느 행정동에도 들지 않는 위치에 메모를 작성한다.                           | 메모는 저장되고 작성·조회 응답의 `adminDongCode`는 `null`이다.                                   |

## 5. 미정 사항

다음 항목은 합의 전까지 구현자가 임의의 수치나 동작으로 확정하지 않는다.

| 항목             | 결정할 내용                                                                          |
| ---------------- | ------------------------------------------------------------------------------------ |
| 메모 입력        | 최대 글자 수, 빈 문자열·공백만 있는 내용 허용 여부, 앞뒤 공백·줄바꿈 처리            |
| 조회 조건        | 최대 조회 범위와 영역 조회의 정렬 기준 (지도 화면 영역과 경계 포함은 확정)           |
| 메모가 많은 지역 | 결과 상한과 페이지 처리                                                              |
| 성능 목표        | 예상 데이터량·동시 요청 수, 응답 시간 목표와 부하 측정 조건                          |
| 수정과 반복 요청 | 메모 내용·선호 수정 기능 제공 여부, 작성 연속 클릭·네트워크 재시도 시 중복 방지 방식 |
| 시간과 화면 갱신 | 작성·수정 시각 표시 여부·시간대, 같은 회원의 다른 기기 화면에서 삭제를 반영하는 시점 |
| 회원 상태와 보존 | 논리 삭제된 메모의 보존 기간과 후속 정리 정책                                        |
