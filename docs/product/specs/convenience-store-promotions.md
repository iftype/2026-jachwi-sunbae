# 편의점 행사상품 기능 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-10-27 / 대상: MVP1-2

## 1. 목적과 범위

자취생은 편의점을 방문하기 전에 해당 브랜드의 1+1, 2+1 등 행사상품을 한곳에서 확인한다.

이마트24 공식 홈페이지의 행사상품을 하루 한 번 수집·저장하고, 저장된 전체 목록을 조회하는 백엔드 기능을 다룬다. 상품 목록·카드 UI, 검색·정렬·필터 UX, 지도의 주변 편의점 연동, CU·GS25·세븐일레븐 등 다른 브랜드 수집과 상품 추천은 범위에 포함하지 않는다.

## 2. 요구사항

- `REQ-PROMOTION-001`: 서버는 이마트24 공식 행사상품 페이지에서 상품명, 판매가격, 이미지 URL, 상품 카테고리, 행사 유형을 수집한다.
- `REQ-PROMOTION-002`: 상품 카테고리는 간편식사·과자·음료·생활용품, 행사 유형은 1+1·2+1·3+1·세일·골라담기로 구분한다.
- `REQ-PROMOTION-003`: 서버는 매일 한 번 전체 목록을 수집해 브랜드의 기존 목록을 새 목록으로 교체한다.
- `REQ-PROMOTION-004`: 사용자는 브랜드의 저장된 행사상품 전체와 마지막 정상 수집 시각을 조회한다.

## 3. 정책

### 3.1. 수집과 저장

- `POL-PROMOTION-001`: KST 매일 04:00에 수집한다. 실패해도 즉시 재시도하지 않고 다음 날 다시 수집한다.
- `POL-PROMOTION-013`: 서버 기동 5분 뒤 저장된 목록이 없으면 한 번 수집한다. 이미 목록이 있으면 재배포해도 수집하지 않는다.
- `POL-PROMOTION-002`: 네 카테고리의 모든 페이지를 수집하고, 응답의 전체 상품 수와 실제 수집 건수가 같아야 성공이다. 요청 실패, 접근 제한, 응답 형식 변경이 하나라도 있으면 수집 전체가 실패한다.
- `POL-PROMOTION-003`: 브랜드·상품명·가격·이미지 URL·카테고리·행사 유형이 모두 같은 항목만 하나로 합친다. 상품명이 같아도 다른 값이 하나라도 다르면 별개의 행사로 유지한다.
- `POL-PROMOTION-004`: 전체 수집에 성공했을 때만 기존 목록을 삭제하고 새 목록을 저장하며, 두 작업은 함께 반영되거나 함께 취소된다. 수집 또는 저장에 실패하면 마지막 정상 목록과 수집 시각을 유지한다.
- `POL-PROMOTION-005`: 외부 요청 사이에 최소 1초 간격을 둔다.

### 3.2. 조회

- `POL-PROMOTION-006`: 조회는 저장된 데이터만 사용하며 외부 홈페이지를 호출하지 않는다.
- `POL-PROMOTION-007`: 페이지네이션, 검색, 서버 측 필터 없이 브랜드의 전체 목록을 저장 순서로 반환한다. 카테고리·행사 유형 필터는 클라이언트에서 처리한다.
- `POL-PROMOTION-008`: 저장된 상품이 없으면 오류가 아니라 빈 목록과 `collectedAt=null`을 반환한다.
- `POL-PROMOTION-009`: 수집 시각은 `+09:00` 오프셋을 포함한 KST 시각이다.

### 3.3. 데이터 제약

- `POL-PROMOTION-010`: 행사상품은 브랜드 공통 행사 정보다. 특정 매장의 재고나 행사 적용 여부를 보장하지 않는다.
- `POL-PROMOTION-011`: 데이터 출처는 이마트24 공식 홈페이지이며, 이마트24에 문의해 안내받은 이용 범위(상품명·판매가격·이미지·카테고리·행사 유형)만 사용한다. 이미지는 내려받지 않고 공식 이미지 URL을 그대로 제공한다.
- `POL-PROMOTION-012`: 목록은 최대 하루 전 상태일 수 있다. 사용자는 `collectedAt`으로 갱신 시각을 확인한다.

## 5. 미정사항

- 한 번에 전체 조회: 초기에는 2천여 개의 최신 행사 항목을 프론트에서 필터링하는 방향으로 검토한다. JSON 응답 크기·로드 시간·모바일 성능을 측정해 페이지네이션이나 서버 필터가 필요한지 판단한다. 상품 이미지는 한꺼번에 요청하지 않도록 지연 로딩을 검토한다.
