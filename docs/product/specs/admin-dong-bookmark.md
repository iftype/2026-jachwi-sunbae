# 동네 북마크 기능 명세

## 1. 목적과 범위

사용자는 동네 찾기 결과에서 마음에 드는 동네(행정동)를 북마크하고, 본 방 기록 지도에서 북마크한 동네를 다시 확인한다.
동네를 고르는 단계와 매물을 기록하는 단계를 이어, 후보 동네 안에서 매물을 찾고 기록하게 한다.

### 1.1. 범위

- 행정동 북마크 추가와 해제
- 내가 북마크한 행정동 코드 전체 조회
- 본 방 기록 지도에서 북마크한 행정동 구역 표시

북마크는 작성자 본인만 보는 개인 기록이다. 다른 회원과의 공유, 폴더·메모·순서 지정, 북마크 개수 상한은 이번 범위에 포함하지 않는다.

## 2. 요구사항

- `REQ-BOOKMARK-001`: 회원은 동네 찾기 결과의 행정동을 북마크한다.
- `REQ-BOOKMARK-002`: 회원은 북마크한 행정동의 북마크를 해제한다.
- `REQ-BOOKMARK-003`: 회원은 자신이 북마크한 행정동의 코드 전체를 한 번에 조회한다. 응답은 행정동 코드만 담는다.
- `REQ-BOOKMARK-004`: 본 방 기록 지도는 북마크한 행정동의 경계를 구분해 보여 준다.
- `REQ-BOOKMARK-005`: 다른 회원의 북마크는 조회 결과와 화면에 나오지 않는다.

## 3. 정책

### 3.1. 대상과 식별

- `POL-BOOKMARK-001`: 북마크 대상은 `admin_dongs`에 적재된 행정동이며 통계청 행정동 코드(8자리 숫자)로 식별한다. 형식이 다르거나 적재되지 않은 코드는 `ADMIN_DONG_BOOKMARK_INVALID`로 거부한다.
- `POL-BOOKMARK-002`: 회원과 행정동 코드 한 쌍에 북마크는 하나다.
- `POL-BOOKMARK-003`: 행정동 경계는 다시 적재할 때 모두 비우고 채우므로 북마크는 `admin_dongs`에 외래 키를 두지 않는다. 다시 적재한 뒤 사라진 코드의 북마크도 조회 결과에는 그대로 남고, 화면은 경계를 찾지 못한 코드를 표시하지 않는다.
- `POL-BOOKMARK-004`: 회원은 요청의 인증 정보로 결정한다. 클라이언트가 보낸 회원 ID로 다른 회원의 북마크를 만들거나 해제할 수 없다.

### 3.2. 추가와 해제

- `POL-BOOKMARK-005`: 추가는 멱등이다. 이미 북마크한 행정동을 다시 추가해도 오류 없이 같은 결과(`201`)를 돌려주고 북마크는 하나로 유지한다. 해제한 행정동을 다시 추가하면 새로 추가한 것으로 본다.
- `POL-BOOKMARK-006`: 해제는 논리 삭제다. 북마크하지 않았거나 이미 해제한 행정동의 해제 요청은 `ADMIN_DONG_BOOKMARK_NOT_FOUND`(`404`)로 응답한다.
- `POL-BOOKMARK-007`: 회원을 탈퇴하면 그 회원의 북마크도 논리 삭제한다. 익명 회원의 기록을 다른 회원으로 합치면 북마크도 옮기고, 두 회원이 같은 행정동을 북마크했으면 하나로 합친다.

### 3.3. 조회

- `POL-BOOKMARK-008`: 조회는 인증된 회원의 해제하지 않은 북마크만 돌려준다. 최근에 추가한 순서로 정렬한다. 북마크가 없으면 빈 배열이다.

### 3.4. 저장 데이터

테이블은 `admin_dong_bookmarks`이며 [V20 마이그레이션](../../../backend/src/main/resources/db/migration/V20__create_admin_dong_bookmarks.sql)으로 추가한다.

| 필드              | 저장 타입     | 필수 여부 | 의미                                     |
| ----------------- | ------------- | --------- | ---------------------------------------- |
| `id`              | `BIGINT`      | 필수      | 서버가 생성하는 북마크 식별자            |
| `member_id`       | `BIGINT`      | 필수      | 회원 참조. 응답에는 포함하지 않는다.     |
| `admin_dong_code` | `VARCHAR(10)` | 필수      | 북마크한 행정동 코드                     |
| `created_at`      | `DATETIME(6)` | 필수      | 추가한 시각. 다시 추가하면 새로 기록한다 |
| `deleted_at`      | `DATETIME(6)` | 선택      | 해제하지 않았으면 `NULL`, 해제한 시각    |

`(member_id, admin_dong_code)` 유일 제약으로 한 쌍에 한 행만 둔다. 해제한 북마크를 다시 추가하면 같은 행의 `deleted_at`을 비우고 `created_at`을 새로 기록한다.

### 3.5. API

| 동작 | 요청                                                                   | 성공                                      |
| ---- | ---------------------------------------------------------------------- | ----------------------------------------- |
| 추가 | `POST /api/admin-dong-bookmarks`, 본문 `{"adminDongCode": "11680640"}` | `201`, `{"adminDongCode": "11680640"}`    |
| 해제 | `DELETE /api/admin-dong-bookmarks/{adminDongCode}`                     | `204`, 본문 없음                          |
| 조회 | `GET /api/admin-dong-bookmarks`                                        | `200`, `{"adminDongCodes": ["11680640"]}` |

세 API 모두 기존 익명 인증의 Access Token이 필요하다.

### 3.6. 화면

- 동네 찾기 결과의 동네 상세에 북마크 버튼을 둔다. 누르면 추가하고, 다시 누르면 해제한다.
- 본 방 기록 지도는 북마크한 행정동의 경계를 다른 동네와 구분되게 칠한다. 경계를 찾지 못한 코드는 그리지 않는다.

## 4. 인수 기준

| ID              | 조건과 행동                                           | 관찰할 결과                                                                             |
| --------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| AC-BOOKMARK-001 | 회원 A가 행정동 X를 북마크한 뒤 목록을 조회한다.      | `201`과 X를 받고, 목록에 X가 있다.                                                      |
| AC-BOOKMARK-002 | A가 X를 두 번 북마크한다.                             | 두 번 모두 `201`이고 목록에 X가 한 번만 있다.                                           |
| AC-BOOKMARK-003 | A가 X를 해제한 뒤 목록을 조회하고, 한 번 더 해제한다. | 첫 해제는 `204`, 목록에 X가 없고, 두 번째 해제는 `404 ADMIN_DONG_BOOKMARK_NOT_FOUND`다. |
| AC-BOOKMARK-004 | A가 형식이 틀리거나 적재되지 않은 코드를 북마크한다.  | `400 ADMIN_DONG_BOOKMARK_INVALID`이고 저장되지 않는다.                                  |
| AC-BOOKMARK-005 | A가 X, 회원 B가 Y를 북마크한 뒤 각자 목록을 조회한다. | A는 X만, B는 Y만 받는다.                                                                |
| AC-BOOKMARK-006 | A가 X, Y 순서로 북마크한 뒤 목록을 조회한다.          | `[Y, X]` 순서다.                                                                        |
| AC-BOOKMARK-007 | 인증 없이 세 API를 호출한다.                          | `401`이고 데이터가 바뀌지 않는다.                                                       |

## 5. 미정 사항

| 항목        | 결정할 내용                                  |
| ----------- | -------------------------------------------- |
| 개수 상한   | 회원당 북마크 최대 개수와 초과 시 안내       |
| 화면 진입점 | 동네 찾기 목록 행에서도 바로 북마크할지 여부 |
| 지도 표시   | 북마크 동네의 이름표와 월세 시세 표시 여부   |
