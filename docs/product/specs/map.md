# 지도·주소·주변 분석 기능 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-09-13 / 대상: MVP1-2

## 1. 목적과 범위

사용자는 매물 위치를 선택하고 주변 시설을 확인한다.

지도 표시, 주소 검색 결과 선택, 좌표의 주소 변환, 대체 위치, 시설 필터와 조회 실패를 다룬다.

## 2. 요구사항

- `REQ-MAP-001`: 일반 지도에서 사용자가 현재 위치 조작을 실행하면 위치를 요청하고 성공 시 그 위치를 표시한다.
- `REQ-MAP-002`: 위치 조회 실패 시 모든 관련 화면의 대체 위치로 우테코 판교 사옥을 사용한다.
- `REQ-MAP-003`: 자신의 매물을 지도 핀으로 확인하고 선택한 매물의 주변 분석으로 이동한다.
- `REQ-MAP-004`: 지도에서 고른 좌표의 주소를 확인한다. 현재 위치 조회·좌표의 주소 변환 실패 시 대체 주소·위치를 사용한다.
- `REQ-MAP-005`: 지도 선택 또는 주소 검색 결과 선택으로 주소·좌표를 매물 등록·수정에 전달한다.
- `REQ-MAP-006`: 주변 조회 반경을 선택한다.
- `REQ-MAP-007`: 병원·교통·학교·편의점·중개사무소의 조회 결과와 개수를 확인한다.
- `REQ-MAP-008`: 신규 선택·수정·주변 분석의 시작 위치를 화면 목적에 맞게 정한다.
- `REQ-MAP-009`: 모든 시설 필터는 한 번에 한 카테고리만 선택한다.
- `REQ-MAP-010`: 최초 진입 시 시설 카테고리는 미선택이다.
- `REQ-MAP-011`: 위치 선택 중에도 현재 위치로 이동하는 조작을 제공한다.
- `REQ-MAP-012`: 매물을 등록하지 않아도 현재 위치 또는 지도에서 선택한 위치 주변의 착한가격업소를 조회한다.
- `REQ-MAP-013`: 착한가격업소의 이름, 업종, 연락처, 주소, 메뉴·가격, 기준 위치와의 거리, 데이터 기준일을 확인한다.
- `REQ-MAP-014`: 매물을 등록하지 않아도 현재 위치 또는 지도에서 선택한 위치 주변의 공공 CCTV를 조회한다.
- `REQ-MAP-015`: CCTV의 위치 (좌표·주소), 기준 위치와의 거리, 설치목적, 카메라 대수, 화소수, 영상 보관일수를 확인한다.
- `REQ-MAP-016`: 본 방 기록 지도에서 주변 시설과 다른 회원이 남긴 [거리 메모](../../specs/street-memo.md)를 확인하고, 지도에서 고른 위치에 메모를 남기거나 매물을 등록한다.

## 3. 정책

### 3.1. 위치와 주소의 공통 기준

| 화면                | 시작 위치와 실패 처리                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 일반 지도           | 마지막으로 본 위치를 사용하고 없으면 판교 사옥을 표시한다. 현재 위치는 사용자가 요청할 때 조회한다.               |
| 신규 매물 위치 선택 | 이미 선택한 위치를 유지한다. 선택한 위치가 없으면 마지막으로 본 위치 또는 판교 사옥을 사용한다.                   |
| 매물 위치 수정      | 수정 중 선택한 위치, 저장된 매물 위치 순으로 우선한다. 둘 다 없으면 마지막으로 본 위치 또는 판교 사옥을 사용한다. |
| 매물 주변 분석      | 해당 매물의 저장 위치를 사용한다. 매물은 존재하지만 위치를 확인할 수 없으면 판교 사옥을 대체 위치로 사용한다.     |

- `POL-MAP-001`: 주소와 좌표가 같은 선택 결과를 가리키도록 전달한다. 위도·경도는 함께 사용한다.
- `POL-MAP-002`: 주소 미입력 시 마지막으로 본 지도 위치를 사용하고, 없으면 우테코 판교 사옥 (금토로80번길 40)의 주소·위치를 사용한다. 현재 위치는 사용자가 위치 조작을 실행할 때만 요청한다.
- `POL-MAP-003`: 주소를 직접 타이핑하면 검색 결과를 선택해 확정한다.

### 3.2. 시설 카테고리·반경·개수

- `POL-MAP-004`: 반경은 500m·1km·2km를 지원하는 안을 둔다.
- `POL-MAP-005`: 시설 카테고리의 복수선택은 제공하지 않는다.
- `POL-MAP-006`: 처음에는 시설 카테고리를 선택하지 않는다. 다른 카테고리를 누르면 교체하고 같은 카테고리를 다시 누르면 해제한다. 매물 핀은 필터와 무관하게 유지한다.
- `POL-MAP-007`: 교통은 버스정류장만 보여준다. 지하철역은 포함하지 않는다.
  - 국토교통부 전국 버스정류장 위치정보 (연 1회 스냅샷)를 서비스 DB에 적재해 조회한다. 외부 API를 호출하지 않는다.
  - 승객이 타고 내릴 수 없는 미정차 정류장과 가상 정류장은 제외한다.
  - 길 건너 양방향 정류장처럼 이름이 같아도 정류장 ID가 다르면 각각 보여준다.
- `POL-MAP-008`: 거리 메모는 시설이 아니지만 같은 카테고리 레일의 `메모` 탭으로 켠다. 반경이 아니라 지도 화면 범위로 조회하며 주변 시설 개수 안내를 띄우지 않는다.

### 3.3. 주변 시설 조회 품질 및 개선 판단 기준

**단순히 조회 개수가 적다는 이유만으로 결함으로 판단하지 않으며, 기대 동작과 실제 결과의 차이 및 사용자에게 미치는 영향을 기준으로 판단한다.**

| 구분          | 판단 기준                                                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **검색 품질** | 실제 확인된 시설 대비 조회된 시설의 비율(조회율)을 측정한다. **조회율이 50% 미만이면 개선 대상으로 판정한다.**                |
| **개선 착수** | 검색 품질이 기준 미달이면 개선 이슈를 등록하고, 사용자 영향과 발생 범위와 수정 비용과 대안을 검토해 작업 우선순위를 결정한다. |

**정량적 품질 측정 방법**

- 도심, 주거지역, 비도심의 대표 좌표 10곳을 선정하고, 실제 시설과 API 결과를 비교한다.
- `조회율(%) = 실제 확인된 시설 중 조회된 수 / 실제 확인된 시설 수 × 100`으로 측정한다.
- 카테고리 및 반경별 조회율을 산출하며, 실제 시설이 0개인 사례와 API 조회 상한에 도달한 사례는 별도로 구분한다.
- **조회율 50% 미만:** 개선 대상 판정 및 원인 분석 착수.
- **조회율 50% 이상:** 기준 미달로 판정하지 않지만, 사용자에게 중요한 시설의 누락이나 반복적인 불편이 확인되면 별도 검토한다.

조회율 50%는 초기 품질 판단 기준으로 설정하며, 실제 측정 결과와 사용자 피드백을 바탕으로 재검토한다.

개선 이슈에는 **기대 결과, 실제 측정 결과, 결함 판단 근거, 사용자 영향, 검토한 대안과 선택 이유**를 기록한다.

### 3.4. 착한가격업소

- `POL-MAP-008`: 행정안전부 착한가격업소 현황 (파일데이터, 약 3개월마다 갱신)을 서비스 DB에 적재해 조회한다. 조회할 때 외부 API를 호출하지 않는다.
  - 원본에 좌표가 없어 적재할 때 주소를 SGIS로 WGS84 좌표로 변환한다. 주소를 찾지 못한 업소는 적재하지 않는다.
  - 필수 값 (시도, 업종, 업소명, 주소)이 없는 업소는 적재하지 않는다.
- `POL-MAP-009`: 업종, 연락처, 메뉴·가격은 공공데이터 원본 값 그대로 보여준다.
  - 업종은 음식점·미용 등 서비스 자체 카테고리로 묶지 않는다.
  - 가격은 `무료`, `25000~45000`처럼 숫자가 아닐 수 있어 숫자로 변환하지 않는다.
  - 메뉴명이 없는 메뉴·가격 칸은 메뉴로 보지 않는다. 메뉴명은 있고 가격이 없으면 가격 없이 보여준다.
- `POL-MAP-010`: 반경은 `POL-MAP-004`와 같은 500m·1km·2km를 사용한다. 반경 안의 업소를 개수 제한 없이 모두 가까운 순으로 보여준다.
- `POL-MAP-011`: 가격이 실시간 정보가 아니므로 공공데이터 기준일을 함께 제공한다. 기준일은 조회 결과가 아닌 적재된 데이터 전체의 값이라, 반경 안에 업소가 없어도 제공한다.

### 3.5. CCTV

- `POL-MAP-012`: 전국CCTV표준데이터 (표준데이터)를 서비스 DB에 적재해 조회한다. 조회할 때 외부 API를 호출하지 않는다.
  - 위치를 믿기 어려운 CCTV는 적재하지 않는다. 국내 범위 밖 좌표, 지자체가 일괄 입력한 가짜 좌표, 소수 2자리 이하로 정밀도가 낮은 좌표, 카메라 대수가 0인 CCTV가 해당한다.
  - 화소수와 영상 보관일수는 원본에 없거나 애매하면 (단위가 다른 화소수, 보관일수 0) 정보 없음으로 보여준다.
- `POL-MAP-013`: CCTV는 관리번호마다 하나씩 보여준다. 같은 좌표에 여러 CCTV가 있어도 합치지 않는다.
- `POL-MAP-014`: 반경은 `POL-MAP-004`와 같은 500m·1km·2km를 사용한다. 반경 안의 CCTV를 개수 제한 없이 모두 가까운 순으로 보여준다.

## 5. 미정 사항

### 본 방 기록 지도의 주변 시설과 로컬 확인

- 별도 인프라 지도 (`/map`)는 본 방 기록 (`/properties`) 지도로 합쳤다. 예전 주소 `/map`, `/map/:propertyId`로 들어오면 `/properties`, `/properties/:propertyId`로 보낸다. 지도에서 위치 선택 (`/map/select-location`)은 그대로 둔다.
- 기록 지도의 카테고리 레일은 거리 메모·병원·교통·학교·편의점·중개사무소 순서로 아이콘 없이 짧은 글자만 두고, 한 번에 하나만 켜며 켜진 칸은 파란색으로 칠한다. 휴대폰 기록 지도는 거리 메모를 켠 채로 연다. 시설은 반경 원 없이 지도 화면 범위를 덮는 지원 반경 (최대 2km)으로 조회하고 화면 안의 것만 보여준다. 반경 선택·매물 추가 모드의 중앙 핀은 두지 않는다.
- 데스크탑은 따로 기록하기 버튼을 두지 않고, 지도의 빈 곳을 찍어 메모 남기기와 매물 등록 중에서 고른다. 매물 등록은 찍은 좌표를 역지오코딩해 왼쪽 등록 칸에 주소와 함께 넘기며, 주소를 찾지 못하면 좌표만 넘긴다.
- 휴대폰은 마커를 누르려다 빈 곳을 잘못 찍기 쉬워, 평소에 지도를 찍으면 열린 매물·메모를 닫기만 한다. 메모·매물은 지도 가운데 아래 `+` 버튼을 눌러 고른다. `+`는 `X`로 바뀌고 위로 왼쪽 메모·오른쪽 매물 버튼을 띄운다. 고르면 추가 모드에 들어가 위쪽 탭과 지도의 모든 마커·카테고리 레일을 거두고, 위쪽 토스트로 무엇을 추가하는 중인지와 찍은 위치의 주소를 알리며, 아래에는 취소·확인 버튼만 둔다. 지도에서 찍은 위치로 메모는 작성 시트를 열고, 매물은 확인한 주소로 `/properties/new`에 넘긴다. 리스트 보기에는 기록하기 버튼을 둔다.
- 데스크탑과 휴대폰 기록 화면은 지도 컴포넌트 (`RecordsDesktopMap`, `RecordsMobileMap`)를 따로 두고, 시설·메모·찍은 위치 상태는 공용 `useRecordsMapLayers`로 함께 쓴다.
- 로컬 확인: `npm run dev:mock`으로 `/properties`를 열고 시설 탭 켜기 → 지도 이동 → 메모 탭 켜기 → 빈 곳 찍기 → 메모 남기기 → 다시 찍어 매물 등록 순서로 확인한다.
- MSW 지도 응답은 조회 좌표·반경·카테고리 조건을 반영한다. 역지오코딩은 가까운 샘플 매물의 주소를 사용하고, 그 외는 실제 주소로 오인하지 않도록 테스트 위치로 표시한다. 실제 운영 장소 데이터가 아닌 샘플이다.

- 시설 개수와 카테고리 범위 (#243)
  - 현재는 외부 API 호출량을 제한하기 위한 **임시 기준**으로 동작한다. 제품 정책은 이후 결정한다.
  - 임시 기준: 교통을 제외한 시설은 기준 위치에서 가까운 순으로 카테고리별 최대 45개까지 보여준다. 교통은 `POL-MAP-007`을 따른다.
  - 결정할 것: 상한 값, 상한에 도달했을 때의 안내 ("45개 이상" 등), 카테고리별 포함 범위, 캐싱 처리 등등
- 주소 정보 출처 표시 (#251)
  - 주소 검색과 좌표의 주소 변환은 공공데이터 (행정안전부 도로명주소, 국가데이터처 SGIS)를 사용한다.
  - SGIS는 공공누리 제1유형 (출처표시)이므로 서비스 화면에 출처를 표시해야 한다. 운영 배포 전에 반영한다.
  - 결정할 것: 표시 위치 (위치 선택 화면, 서비스 정보 페이지 등)와 문구
- 착한가격업소 (#351)
  - 공공데이터는 약 3개월마다 갱신되지만 파일데이터라 지금은 수동으로 다시 적재한다. 자동 갱신 (Scheduler)은 이후 검토한다.
  - 결정할 것: 업종 재분류, 업종 필터, 출처 표시 위치와 문구
- 공공 CCTV (#355)
  - 표준데이터는 지자체가 수시로 갱신하지만 지금은 내려받은 스냅샷을 수동으로 다시 적재한다. 자동 갱신 (Scheduler)은 이후 검토한다.
    - 버스정류장과 착한업소의 경우 6개월 1년으로 정해진 시기에 업데이트가 되지만, cctv는 지자체별로 업데이트된다.
  - 결정할 것: 데이터 갱신 주기, 출처 표시 위치와 문구
