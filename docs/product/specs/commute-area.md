# 생활권 탐색 기능 명세

## 1. 목적과 범위

사용자는 회사·학교 같은 목적지를 입력해, 대중교통으로 제한 시간 안에 출퇴근할 수 있는 동네를 찾는다.

자취선배의 기존 기능은 매물을 정한 뒤의 임장 단계에 집중되어 있다. 이 기능은 그보다 앞 단계인 "어디에 살지 정하는 단계"를 맡아 서비스의 진입점을 넓힌다.

### 1.1. 범위

| 구분      | 내용                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 이번 범위 | 수도권 GTFS 노선망 적재, 목적지 기준 도달권 탐색, 서울·경기 행정동 단위 결과 표시, 정류장별 상세 경로 안내, 동네별 관할 법정동 월세 시세 |
| 후속 범위 | TAGO 실시간 정보 연동                                                                                                                    |
| 제외      | 자가용·도보 전용 통근, 매물 단위 추천                                                                                                    |

## 2. 요구사항

- `REQ-COMMUTE-001`: 목적지를 주소 검색 또는 지도 선택으로 지정한다.
- `REQ-COMMUTE-002`: 최대 통근 시간을 선택한다.
- `REQ-COMMUTE-003`: 목적지까지 최대 통근 시간 안에 도착할 수 있는 동네를 행정동 단위로, 통근 시간과 함께 확인한다.
- `REQ-COMMUTE-004`: 결과 동네를 선택해 지도에서 위치를 확인한다.
- `REQ-COMMUTE-005`: 운영자는 GTFS 파일로 대중교통 노선망을 적재·교체한다.
- `REQ-COMMUTE-006`: 결과 정류장을 선택해 그 정류장에서 목적지까지 타고 갈 노선과 걷는 구간을 확인한다.
- `REQ-COMMUTE-007`: 로그인한 사용자는 등록한 매물마다 목적지까지 걸리는 통근 시간을 확인한다.
- `REQ-COMMUTE-008`: 결과 동네마다 실거래 월세 시세를 어느 법정동 기준인지와 함께 확인한다.

## 3. 정책

원천 CSV의 구조와 각 정책의 계산 과정은 [GTFS 데이터 구조와 파싱](commute-area-gtfs.md)에 실제 데이터 예시와 함께 정리한다.

### 3.1. 통근 시간 계산

- `POL-COMMUTE-001`: 통근 수단은 버스와 지하철·도시철도다. GTFS `route_type`이 `0`, `1`, `3`인 노선만 사용하고, KTDB 데이터에서 버스에 쓰는 `0`도 포함한다. 일반철도·항공·해운은 제외한다.
- `POL-COMMUTE-002`: 정류장 간 이동 시간은 같은 구간을 지나는 운행편 이동 시간의 중앙값으로 한다. 같은 분에 도착하는 구간도 최소 30초로 본다.
- 중앙값은 이동 시간과 운행 간격 모두 같은 정의를 쓴다. 값이 짝수 개면 가운데 두 값의 평균을 반올림한다.
- `POL-COMMUTE-003`: 노선에 탑승할 때마다 대기 시간을 더한다. 대기 시간은 첫 정류장 출발 간격 중앙값의 절반이며, 2분 이상 15분 이하로 제한한다. 쓸 수 있는 간격이 없으면 5분으로 둔다.
- `POL-COMMUTE-004`: 정류장 간 도보 환승은 GTFS `transfers.txt`의 최소 환승 시간을 쓴다. 같은 정류장 쌍이 여러 번 나오면 가장 짧은 시간을 쓴다. 환승 불가(`transfer_type` 3)이거나 최소 환승 시간이 비어 있는 환승은 쓰지 않는다. KTDB 2025-03 데이터의 환승 342건은 모두 `transfer_type` 2이고 최소 환승 시간이 있다. 이 환승은 모두 지하철역끼리라, 버스 정류장과 역, 서로 다른 버스 정류장 사이 환승은 `POL-COMMUTE-028`로 만든다.

### 3.2. 데이터

- `POL-COMMUTE-005`: 노선망 원천은 KTDB 대중교통 GTFS 2025년 3월 데이터셋이다. 노선 26,399개, 정류장 215,409개, 정차 기록 18,889,140건이다.
- `POL-COMMUTE-006`: 적재는 기존 노선망을 모두 지우고 새로 채우는 전체 교체다. 파일을 모두 읽은 뒤 삭제와 저장을 한 트랜잭션으로 처리해, 실패하면 이전 노선망을 유지한다.
- `POL-COMMUTE-007`: 대상 노선이 실제로 지나지 않는 정류장과, 출발·도착 정류장 중 한쪽이라도 적재 대상이 아닌 환승은 적재하지 않는다.
- `POL-COMMUTE-008`: `stop_times.txt`는 운행편별로 모여 있고 운행편 안의 `stop_sequence`가 증가한다고 보고 한 번만 읽는다. GTFS 표준은 행 순서를 보장하지 않으므로, 이 전제가 깨진 데이터는 틀린 구간을 만드는 대신 적재를 실패시킨다. KTDB 2025-03 데이터는 운행편 326,368개 모두 이 전제를 만족한다.

### 3.3. 행정동

- `POL-COMMUTE-009`: 행정동 원천은 통계청 SGIS 행정구역 경계(행정동) 2025-06-30 기준 데이터로, 행정동 3,559개다. 코드는 통계청 행정동 코드 8자리를 쓴다. 경계는 지도에 그리는 용도로 허용 오차 0.00015도(약 15m)로 단순화해 GeoJSON으로 저장하고, 변환 방법은 `backend/scripts/admin-dongs`에 둔다. 적재할 때 경계 좌표를 소수점 5자리(약 1m)로 반올림해 저장 크기를 줄인다(전국 경계 27.3MB → 14.6MB).
- `POL-COMMUTE-010`: 정류장의 행정동은 정류장 좌표가 들어 있는 행정동 경계로 정한다. 어느 경계에도 들지 않으면 비워 두고 탐색 결과에서 뺀다. 단순화한 경계가 이웃 행정동과 겹쳐 두 행정동에 들어가는 정류장(231개)은 코드가 작은 행정동으로 정해, 적재 순서와 상관없이 같은 결과가 나오게 한다. KTDB 2025-03 정류장 214,237개 중 213,981개(99.88%)가 행정동에 매칭되고, 256개는 단순화한 경계 밖에 놓인다.
- `POL-COMMUTE-011`: 행정동 경계와 GTFS 노선망은 하나의 일회성 적재 명령으로 함께 갱신한다. 행정동 경계를 먼저 전체 교체한 뒤, 새 경계를 기준으로 각 GTFS 정류장의 행정동을 계산하고 수도권 노선망을 전체 교체한다. 기존 정류장의 행정동 코드를 별도로 갱신하지 않는다. 행정동이 없으면 GTFS 적재를 실패시킨다.
- `POL-COMMUTE-012`: 행정동의 중심 좌표는 가장 넓은 폴리곤 바깥 고리의 무게중심이며, 지도에 이름을 올리는 위치로만 쓴다. 오목한 행정동은 중심이 경계 밖에 놓일 수 있다(3,559개 중 30개).

### 3.4. 탐색

- `POL-COMMUTE-013`: 목적지에서 걸어서 10분 안의 정류장·역을 도착 정류장으로 본다. 도보 속도는 초속 1.2m(10분에 약 720m)이고, 직선 거리로 걷는 시간을 계산해 통근 시간에 더한다. 도착 정류장이 없으면 `COMMUTE_DESTINATION_UNREACHABLE`로 응답한다.
- `POL-COMMUTE-014`: 도착 정류장에서 구간과 환승을 거꾸로 따라가며 정류장마다 목적지까지 가장 짧은 통근 시간을 구한다. 노선에 탈 때마다 `POL-COMMUTE-003`의 대기 시간을 더하고, 환승 횟수(탑승 횟수 - 1)가 최대 환승 횟수를 넘거나 통근 시간이 최대 통근 시간을 넘는 경로는 버린다.
- `POL-COMMUTE-023`: 최대 통근 시간은 1분 이상 60분 이하(기본 60분), 최대 환승 횟수는 0회 이상 2회 이하(기본 2회)로 요청할 수 있다. 범위를 넓히면 탐색 상태와 응답이 크게 늘어(180분·환승 10회는 탐색 약 5초, 응답 약 10MB) 1GB 서버에서 동시 요청을 감당하기 어렵다. 경로 안내도 같은 범위를 쓴다.
- `POL-COMMUTE-015`: 정류장의 통근 시간은 초 단위 결과를 분으로 올림해 보여 준다. 동네(행정동)의 통근 시간은 동네 안 정류장 중 가장 짧은 시간이다. 동네는 통근 시간, 행정동 코드 순서로, 동네 안 정류장은 통근 시간, 이름 순서로 정렬하고, 같은 이름의 정류장은 가장 빠른 순으로 1개만 나온다.
- `POL-COMMUTE-016` (사용 중단): 정류장 방향(8방위) 표시는 사용하지 않는다. 사용자가 방위로 길 건너편 정류장을 구분하기 어렵고, 동네를 고르는 데 필요한 정보가 아니어서 계산을 없앴다. 응답의 정류장 `direction` 필드는 기존 클라이언트의 응답 파싱이 깨지지 않도록 남겨 두고 항상 `null`을 보내며, 응답 형식은 바꾸지 않는다(3.7). 이전에는 버스 정류장에 다음 정류장 쪽 8방위를 붙이고, 지하철·도시철도 역은 비웠다.
- `POL-COMMUTE-017`: 노선망은 웹 서버가 뜰 때 한 번 DB에서 읽어 서버 메모리에 두고, 이후 탐색과 경로 안내는 DB 커넥션 없이 메모리의 노선망으로 계산한다. 읽기 트랜잭션은 노선망을 DB에서 읽을 때만 연다. 서버가 뜰 때 읽지 못해도 서버는 그대로 띄운다. 적재는 별도 프로세스로 실행하므로 다시 적재한 노선망과 정류장의 행정동은 서버를 재시작해야 반영된다. 노선망이 적재되지 않았거나 DB를 읽지 못하면 메모리에 담지 않고 `TRANSIT_NETWORK_UNAVAILABLE`(503)로 응답한다. 실패한 뒤 30초 동안은 DB를 다시 읽지 않고 바로 503으로 응답하고, 30초가 지난 뒤 요청에서 다시 읽는다. DB에 연결하지 못하면 읽기 한 번이 커넥션 타임아웃만큼 걸려, 기다리던 요청마다 같은 실패를 반복하지 않게 하기 위해서다.
- `POL-COMMUTE-018`: 생활권 탐색은 로그인 입력 없이 쓸 수 있다. 처음 찾아온 사용자에게 익명 인증을 발급한 뒤 `GET /api/commute-areas`와 `GET /api/commute-areas/with-rents`를 호출하며, 이 요청에도 Access Token을 검사한다.
- `POL-COMMUTE-019`: 탐색 결과는 정류장을 행정동 코드로 묶어 보내고, 행정동 이름·경계·중심은 보내지 않는다. 행정동 데이터는 자주 바뀌지 않으므로 클라이언트가 같은 기준(통계청 SGIS 2025-06-30, 8자리 코드)의 데이터를 가지고 코드로 찾는다. 서버는 탐색할 때 행정동을 조회하지 않는다.

### 3.5. 서비스 지역

- `POL-COMMUTE-024`: 서비스 지역은 수도권이다. 노선망에는 통계청 행정동 코드 앞 두 자리가 서울(`11`)·인천(`23`)·경기(`31`)인 정류장만 담고, 탐색 결과에는 서울·경기 동네만 보여 준다. 인천은 서울·경기를 오가는 경로가 인천을 지나도 끊기지 않도록 노선망에만 남긴다. 단순화한 경계 사이 틈에 놓여 행정동이 비어 있는 정류장(수도권 124개)은 남긴 정류장과 구간으로 이어져 있으면 함께 남긴다. 구간과 환승은 양쪽 정류장이 모두 남을 때만, 노선은 남은 구간이 있을 때만 남긴다. KTDB 2025-03 데이터에서 노선 4,476개, 정류장 58,138개(서울 12,822개, 인천 6,937개, 경기 38,255개, 행정동 없음 124개), 구간 239,331개, 환승 306건이 남는다. 서울·경기 목적지 8곳을 60분·환승 2회로 탐색해 전국 노선망과 비교하면, 결과의 서울·경기 정류장 39,009건과 동네 2,751건의 통근 시간이 모두 같았다.

### 3.6. 경로 안내

- `POL-COMMUTE-020`: 경로 안내는 탐색 결과의 정류장 하나에서 목적지까지, 생활권 탐색과 같은 규칙(대기 시간, 최대 환승 횟수, 도착 정류장 도보)으로 가장 빠른 경로를 찾는다. 같은 최대 통근 시간과 최대 환승 횟수로 요청하면 경로의 통근 시간은 탐색 결과의 정류장 통근 시간과 같다. KTDB 2025-03 데이터에서 역삼역 기준 무작위 정류장 600곳의 통근 시간이 모두 일치했다.
- `POL-COMMUTE-021`: 경로는 같은 노선으로 이어진 구간을 하나로 묶은 구간 목록이다. 구간은 버스(`route_type` `0`, `3`), 지하철·도시철도(`1`), 도보로 나누고, 걸어서 하는 환승과 도착 정류장에서 목적지까지 걷는 구간은 도보로 보여 준다. 노선 구간에는 탈 때 기다리는 대기 시간을 따로 보여 준다.
- `POL-COMMUTE-022`: 경로 안내는 탐색 API와 따로 요청한다. 탐색 결과마다 경로를 붙이면 응답이 커지므로, 사용자가 정류장을 고를 때만 계산한다. 메모리의 노선망으로 계산하며 한 번에 평균 약 0.001초가 걸린다.
- `POL-COMMUTE-028`: 직선 거리 100m 안의 서로 다른 정류장(버스 정류장과 역, 길 건너편 버스 정류장 등)은 걸어서 갈아탈 수 있다. 걷는 시간은 `POL-COMMUTE-013`과 같은 초속 1.2m로 계산하고 갈아탈 준비 시간 1분을 더한다. GTFS 환승이 있는 정류장 쌍은 그 시간을 쓴다. 걷기는 이어 붙이지 않아, 걸어서 갈아탄 뒤에 다시 걸어서 갈아타거나 목적지까지 걷지 않는다. 적재한 데이터는 그대로 두고 노선망을 메모리에 올릴 때 만든다. KTDB 2025-03 수도권 노선망에서 노선망을 올리는 시간은 약 0.08초에서 0.89초로, 60분·환승 2회 탐색은 목적지 6곳 평균 약 0.013초에서 0.035초로 늘었다. 같은 목적지에서 60분 안에 갈 수 있는 정류장은 2.0~~2.8배, 서울·경기 동네는 12~~40% 늘었다. 200m로 하면 정류장 2.2~~3.4배, 동네 19~~48%로 조금 더 늘지만 탐색이 평균 0.050초로 느려져, 길 건너편 정류장과 역 출구 정도를 잇는 100m로 정했다.
- 통근 시간은 시간대를 구분하지 않은 시간표 기반 추정치라, 심야 버스처럼 운행 시간이 제한된 노선도 경로에 나올 수 있다.

### 3.7. 정류장 방향 필드 사용 중단

`POL-COMMUTE-016`을 사용 중단해도 `GET /api/commute-areas`의 응답 형식은 바꾸지 않는다. 정류장 `direction` 필드는 이름과 타입(`string | null`)을 그대로 두고 사용 중단으로 표시해 항상 `null`을 보낸다. 기존 클라이언트도 `null`을 이미 방향 없음으로 처리하므로, 백엔드와 프론트엔드를 어떤 순서로 배포해도 동작한다.

변경 전:

```json
{
  "stopId": "BS_TAGO_SEB100000001",
  "stopName": "종로2가사거리",
  "latitude": 37.5698,
  "longitude": 126.988,
  "travelMinutes": 22,
  "direction": "북동"
}
```

변경 후 (`direction` 사용 중단, 항상 `null`):

```json
{
  "stopId": "BS_TAGO_SEB100000001",
  "stopName": "종로2가사거리",
  "latitude": 37.5698,
  "longitude": 126.988,
  "travelMinutes": 22,
  "direction": null
}
```

- 클라이언트는 `direction`을 읽지 않아도 된다. 새로 만드는 클라이언트는 이 필드에 기대지 않는다.
- 나중에 필드 자체를 지우려면, 먼저 클라이언트가 필드가 없어도 응답을 파싱하도록 바꿔 배포해야 한다. 지금 프론트엔드는 `direction`이 없으면 응답을 잘못된 형식으로 보고 실패한다.

### 3.8. 매물별 통근 시간

- `POL-COMMUTE-025`: `GET /api/properties/commute-times`는 로그인한 회원의 매물(삭제한 매물 제외) 전부를 매물 목록과 같은 매물 ID 내림차순으로 돌려준다. 최대 통근 시간 60분, 최대 환승 2회로 고정하며 요청으로 바꾸지 않는다. 목적지는 위도·경도로 받고, 도착 정류장이 없으면 생활권 탐색과 같이 `COMMUTE_DESTINATION_UNREACHABLE`로 응답한다.
- `POL-COMMUTE-026`: 목적지에서 한 번만 거꾸로 탐색해(`POL-COMMUTE-014`) 정류장마다 목적지까지의 시간을 구한 뒤, 매물에서 걸어서 10분 안의 정류장마다 매물에서 정류장까지 걷는 시간을 더해 가장 짧은 시간을 매물의 통근 시간으로 한다. 매물에서 목적지까지 걸어서 10분 안이면 걷는 시간도 후보로 본다. 걷는 시간은 `POL-COMMUTE-013`과 같이 직선 거리를 초속 1.2m로 나눈다. 초 단위 결과는 분으로 올림한다.
- `POL-COMMUTE-027`: 매물마다 상태를 함께 보낸다. 60분 안에 닿으면 `REACHABLE`과 통근 시간(분), 위치가 없는 매물은 `NO_LOCATION`, 위치는 있지만 60분 안에 닿지 못하거나 걸어서 10분 안에 정류장이 없으면 `UNREACHABLE`이며, 이 두 상태의 통근 시간은 `null`이다.

```json
{
  "maxMinutes": 60,
  "maxTransfers": 2,
  "properties": [
    { "propertyId": 12, "propertyName": "역삼동 원룸", "status": "REACHABLE", "commuteMinutes": 23 },
    { "propertyId": 9, "propertyName": "새 매물", "status": "NO_LOCATION", "commuteMinutes": null },
    { "propertyId": 4, "propertyName": "일산 투룸", "status": "UNREACHABLE", "commuteMinutes": null }
  ]
}
```

### 3.9. 동네 월세 시세

- `POL-COMMUTE-029`: 동네(행정동)의 월세 시세는 그 행정동이 관할하는 법정동의 실거래를 모두 합쳐 계산한다. 실거래 공개 자료가 법정동 단위라 행정동 안을 더 나눌 수 없다. 법정동 하나가 여러 행정동으로 나뉜 곳(신림동 등)은 그 행정동들이 같은 시세를 받고, 법정동 여러 개를 묶은 행정동(종로1·2·3·4가동 등)은 관할 법정동 거래를 합친다. 응답에는 거래가 있었던 관할 법정동을 거래가 많은 순서로 함께 보내 화면에서 어느 법정동 기준인지 밝힌다.
- `POL-COMMUTE-030`: 행정동과 관할 법정동의 연결은 행정안전부 행정표준코드관리시스템의 행정기관·관할구역 연계표(`KIKmix.연월일`, MS949 고정 폭 텍스트)를 쓴다. 연계표의 행정동 코드는 행정안전부 코드라, 통계청 행정동 코드와 시도·시군구·읍면동 이름으로 맞춘다. 공백과 가운뎃점은 무시하고 행정안전부의 "○○제1동"은 "○○1동"으로 읽는다. 행정동 경계가 바뀐 뒤의 이름과 어긋나지 않도록, 적재된 행정동 경계의 기준일(`POL-COMMUTE-009`)에 유효했던 연계표 행만 쓴다. 연계표에는 면적 비율이 없어 행정동에 조금만 걸친 법정동도 관할로 나오므로, 행정동 이름에서 번호를 뺀 이름(이매1동 → 이매동, 상계3·4동 → 상계동, 일원본동 → 일원동)과 같은 관할 법정동이 있으면 그 법정동만 잇는다. 같은 이름이 없는 행정동(종로1·2·3·4가동 등)과 거래가 법정리로 잡히는 읍·면은 관할 법정동을 모두 잇는다. 이 규칙이 없으면 판교동(행정동)에 일부만 걸친 백현동 거래가 합쳐져 시세가 62.5만원에서 105만원으로 올라가는 것처럼, 거래가 많은 이웃 법정동이 시세를 끌고 간다. 2026-07-01 연계표로 서울·경기 행정동 1,027개가 모두 이어지고, 전국에서는 연계표에 시군구명이 없는 세종시 25개만 이어지지 않는다.
- `POL-COMMUTE-031`: 연계표는 행정동 경계·GTFS 적재 명령에 `--transit.admin-legal-dong.file`을 넘기면 행정동 경계와 GTFS를 적재한 뒤 `admin_legal_dongs` 테이블에 전체 교체로 적재한다. 넘기지 않으면 기존 연결을 그대로 둔다. 이어지지 않은 행정동은 경고 로그로 남긴다. 행정동 경계를 다시 적재하면 연계표도 함께 다시 적재한다. 연결을 다시 적재하면 이미 적재된 월세 거래로 시세(`POL-COMMUTE-033`)도 같은 트랜잭션에서 다시 계산한다.
- `POL-COMMUTE-032`: 시세는 적재된 월세 수집본의 마지막 계약일부터 6개월 전까지의 관할 법정동 거래로 계산한 월세·보증금 중앙값과 거래 수다. 오늘 날짜가 아니라 수집본 기준이라, 수집본을 바꾸기 전까지 기간이 밀리지 않는다. 중앙값은 짝수 개면 가운데 두 값의 평균을 반올림한다. 5~10평 실거래 참고값이며 원룸 여부와 현재 매물 여부는 확인되지 않는다. 관할 법정동 거래를 합쳐 5건보다 적거나 연계표에 이어지지 않은 동네는 금액과 거래 수를 `null`로 보낸다.
- `POL-COMMUTE-033`: 시세는 적재할 때 계산해 `admin_dong_rents` 테이블에 저장한다. 월세 적재 명령(`--apply`)이 거래를 교체할 때와 연계표를 다시 적재할 때(`POL-COMMUTE-031`) 같은 트랜잭션에서 전부 다시 계산하므로, 둘 중 무엇을 먼저 적재해도 결과가 같다. 웹 서버는 노선망(`POL-COMMUTE-017`)처럼 뜰 때 한 번 읽어 메모리에 두고, 다시 적재한 시세는 서버를 재시작해야 반영된다. 읽지 못하면 시세 없이 응답한다. 응답 최상위 `rentStartDate`와 `rentEndDate`에 시세 기간을 보내고, 시세가 하나도 없으면 `null`이다.
- `POL-COMMUTE-034`: 시세를 포함한 생활권 탐색은 `GET /api/commute-areas/with-rents`로 따로 제공한다. 요청 파라미터, 탐색 규칙, 인증 정책(`POL-COMMUTE-018`)은 `GET /api/commute-areas`와 같고, 동네마다 `monthlyRentKrw`, `depositKrw`, `transactionCount`, `legalDongNames`와 응답 최상위 `rentStartDate`, `rentEndDate`만 더한다. 기존 `GET /api/commute-areas`는 사용 중단(deprecated)으로 표시하되 응답 형식은 바꾸지 않고 시세도 계산하지 않는다. 새 화면은 `with-rents`를 쓰고, 기존 API는 클라이언트가 모두 옮겨 간 뒤에 지운다.

`GET /api/commute-areas/with-rents` 응답 예:

```json
{
  "maxMinutes": 60,
  "areaCount": 2,
  "rentStartDate": "2026-03-30",
  "rentEndDate": "2026-09-30",
  "areas": [
    {
      "adminDongCode": "11210630",
      "commuteMinutes": 23,
      "monthlyRentKrw": 450000,
      "depositKrw": 5000000,
      "transactionCount": 312,
      "legalDongNames": ["신림동"],
      "stations": []
    },
    {
      "adminDongCode": "31250310",
      "commuteMinutes": 58,
      "monthlyRentKrw": null,
      "depositKrw": null,
      "transactionCount": null,
      "legalDongNames": [],
      "stations": []
    }
  ]
}
```

- 클라이언트는 시세 금액·거래 수와 시세 기간이 `null`일 수 있다고 보고 처리한다. 기존 `GET /api/commute-areas`의 응답은 그대로라 기존 클라이언트는 바뀌지 않는다.

### 3.10. 통합 지도의 검색 편집

회원의 동네 찾기는 기록과 같은 지도에서 전환한다. 데스크톱은 지도에 붙은 왼쪽 조건 카드, 휴대폰과 앱은 검색 영역에서 목적지와 조건을 수정한다. 처음 들어오면 검색 화면 없이 동네 찾기 지도로 바로 열고, 월세는 결과 지도의 슬라이더로 바꾸며 검색한 뒤에도 받아 둔 결과에서 바로 적용한다. 지도 탭으로 목적지를 바꾸려면 위치 선택을 먼저 켠다.

결과의 `검색 조건 바꾸기`는 기존 결과를 버리지 않고 편집을 연다. 목적지와 통근 조건의 편집값은 제출한 검색과 분리하며 입력만으로 통근 API를 다시 호출하지 않는다. `이전 결과 보기`로 제출한 조건을 복원하고, 제출하면 새 조건으로 다시 검색한다. 늦게 도착한 주소와 통근 응답은 최신 선택과 검색을 덮지 않는다. 실패 시 같은 검색을 재시도하거나 조건을 수정할 수 있다. 공개 `/explore`는 개인 기록을 조회하지 않는 기존 공개 탐색을 유지한다.

## 5. 미정 사항과 결정 근거

- 동네 시세는 행정동마다 따로 추정하지 않고 관할 법정동 실거래를 합쳐 보여 준다. 실거래가 법정동 단위라 경계 면적 비율로 나눠도 새 정보가 생기지 않고, 숫자가 어느 법정동의 값인지 설명하기 어려워진다. 공식 연계표를 쓰면 경계를 겹치는 계산 없이 행정동과 법정동을 이을 수 있다. 통근 시간은 행정동이 더 세밀하므로(신림동 하나가 행정동 10개 남짓) 결과 단위는 행정동으로 둔다.
- 전국 데이터로 재면 메모리에 둔 노선망은 힙 약 85MB를 차지한다. 노선망을 읽을 때 구간 117만 개를 목록으로 모으지 않고 DB에서 한 행씩 스트리밍해 번호 배열에 바로 담아, 읽는 순간의 메모리 사용을 줄인다. 탐색 상태는 객체 없이 원시 배열로 다루고 도착 정류장은 목적지 주변 격자 칸에서만 찾아, 60분·환승 2회 탐색이 평균 약 0.016초에 끝난다. 부하 테스트로 병목을 확인한 뒤 결과 캐시, 동시 실행 제한 순으로 개선한다.
- 응답은 역삼역 기준 40분이면 약 270KB, 60분이면 약 1MB, 90분이면 약 2.4MB다. 대부분 정류장 목록이므로 응답 압축이나 동네별 정류장 수 제한을 함께 검토한다.
- 노선망을 수도권으로 줄여 정류장은 전국의 약 27%(214,237개 → 58,138개), 구간은 약 20%(1,173,452개 → 239,331개)만 남는다. 아래 메모리·탐색 시간은 전국 노선망에서 잰 값이다.
