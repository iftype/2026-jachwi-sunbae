# 생활권 탐색 기능 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-10-09 / 대상: 스프린트 2

## 1. 목적과 범위

사용자는 회사·학교 같은 목적지를 입력해, 대중교통으로 제한 시간 안에 출퇴근할 수 있는 동네를 찾는다.

자취선배의 기존 기능은 매물을 정한 뒤의 임장 단계에 집중되어 있다. 이 기능은 그보다 앞 단계인 "어디에 살지 정하는 단계"를 맡아 서비스의 진입점을 넓힌다.

### 1.1. 범위

| 구분      | 내용                                                                                                       |
| --------- | ---------------------------------------------------------------------------------------------------------- |
| 이번 범위 | 수도권 GTFS 노선망 적재, 목적지 기준 도달권 탐색, 서울·경기 행정동 단위 결과 표시, 정류장별 상세 경로 안내 |
| 후속 범위 | 실거래 월세 정보와의 통합, TAGO 실시간 정보 연동                                                           |
| 제외      | 자가용·도보 전용 통근, 매물 단위 추천                                                                      |

## 2. 요구사항

- `REQ-COMMUTE-001`: 목적지를 주소 검색 또는 지도 선택으로 지정한다.
- `REQ-COMMUTE-002`: 최대 통근 시간을 선택한다.
- `REQ-COMMUTE-003`: 목적지까지 최대 통근 시간 안에 도착할 수 있는 동네를 행정동 단위로, 통근 시간과 함께 확인한다.
- `REQ-COMMUTE-004`: 결과 동네를 선택해 지도에서 위치를 확인한다.
- `REQ-COMMUTE-005`: 운영자는 GTFS 파일로 대중교통 노선망을 적재·교체한다.
- `REQ-COMMUTE-006`: 결과 정류장을 선택해 그 정류장에서 목적지까지 타고 갈 노선과 걷는 구간을 확인한다.

## 3. 정책

원천 CSV의 구조와 각 정책의 계산 과정은 [GTFS 데이터 구조와 파싱](commute-area-gtfs.md)에 실제 데이터 예시와 함께 정리한다.

### 3.1. 통근 시간 계산

- `POL-COMMUTE-001`: 통근 수단은 버스와 지하철·도시철도다. GTFS `route_type`이 `0`, `1`, `3`인 노선만 사용하고, KTDB 데이터에서 버스에 쓰는 `0`도 포함한다. 일반철도·항공·해운은 제외한다.
- `POL-COMMUTE-002`: 정류장 간 이동 시간은 같은 구간을 지나는 운행편 이동 시간의 중앙값으로 한다. 같은 분에 도착하는 구간도 최소 30초로 본다.
- 중앙값은 이동 시간과 운행 간격 모두 같은 정의를 쓴다. 값이 짝수 개면 가운데 두 값의 평균을 반올림한다.
- `POL-COMMUTE-003`: 노선에 탑승할 때마다 대기 시간을 더한다. 대기 시간은 첫 정류장 출발 간격 중앙값의 절반이며, 2분 이상 15분 이하로 제한한다. 쓸 수 있는 간격이 없으면 5분으로 둔다.
- `POL-COMMUTE-004`: 정류장 간 도보 환승은 GTFS `transfers.txt`의 최소 환승 시간을 쓴다. 같은 정류장 쌍이 여러 번 나오면 가장 짧은 시간을 쓴다. 환승 불가(`transfer_type` 3)이거나 최소 환승 시간이 비어 있는 환승은 쓰지 않는다. KTDB 2025-03 데이터의 환승 342건은 모두 `transfer_type` 2이고 최소 환승 시간이 있다.

### 3.2. 데이터

- `POL-COMMUTE-005`: 노선망 원천은 KTDB 대중교통 GTFS 2025년 3월 데이터셋이다. 노선 26,399개, 정류장 215,409개, 정차 기록 18,889,140건이다.
- `POL-COMMUTE-006`: 적재는 기존 노선망을 모두 지우고 새로 채우는 전체 교체다. 파일을 모두 읽은 뒤 삭제와 저장을 한 트랜잭션으로 처리해, 실패하면 이전 노선망을 유지한다.
- `POL-COMMUTE-007`: 대상 노선이 실제로 지나지 않는 정류장과, 출발·도착 정류장 중 한쪽이라도 적재 대상이 아닌 환승은 적재하지 않는다.
- `POL-COMMUTE-008`: `stop_times.txt`는 운행편별로 모여 있고 운행편 안의 `stop_sequence`가 증가한다고 보고 한 번만 읽는다. GTFS 표준은 행 순서를 보장하지 않으므로, 이 전제가 깨진 데이터는 틀린 구간을 만드는 대신 적재를 실패시킨다. KTDB 2025-03 데이터는 운행편 326,368개 모두 이 전제를 만족한다.

### 3.3. 행정동

- `POL-COMMUTE-009`: 행정동 원천은 통계청 SGIS 행정구역 경계(행정동) 2025-06-30 기준 데이터로, 행정동 3,559개다. 코드는 통계청 행정동 코드 8자리를 쓴다. 경계는 지도에 그리는 용도로 허용 오차 0.00015도(약 15m)로 단순화해 GeoJSON으로 저장하고, 변환 방법은 `backend/scripts/admin-dongs`에 둔다. 적재할 때 경계 좌표를 소수점 5자리(약 1m)로 반올림해 저장 크기를 줄인다(전국 경계 27.3MB → 14.6MB).
- `POL-COMMUTE-010`: 정류장의 행정동은 정류장 좌표가 들어 있는 행정동 경계로 정한다. 어느 경계에도 들지 않으면 비워 두고 탐색 결과에서 뺀다. 단순화한 경계가 이웃 행정동과 겹쳐 두 행정동에 들어가는 정류장(231개)은 코드가 작은 행정동으로 정해, 적재 순서와 상관없이 같은 결과가 나오게 한다. KTDB 2025-03 정류장 214,237개 중 213,981개(99.88%)가 행정동에 매칭되고, 256개는 단순화한 경계 밖에 놓인다.
- `POL-COMMUTE-011`: 행정동 경계와 GTFS 노선망은 하나의 일회성 적재 명령으로 함께 갱신한다. 행정동 경계를 먼저 전체 교체한 뒤, 새 경계를 기준으로 각 GTFS 정류장의 행정동을 계산하고 수도권 노선망을 전체 교체한다. 기존 정류장의 행정동 코드를 별도로 갱신하지 않는다. 행정동이 없으면 GTFS 적재를 실패시킨다.
- `POL-COMMUTE-012`: 행정동의 중심 좌표는 가장 넓은 폴리곤 바깥 고리의 무게중심이며, 지도에 이름을 올리는 위치로만 쓴다. 오목한 행정동은 중심이 경계 밖에 놓일 수 있다(3,559개 중 30개).

### 3.4. 탐색

- `POL-COMMUTE-013`: 목적지에서 걸어서 10분 안의 정류장·역을 도착 정류장으로 본다. 도보 속도는 초속 1.2m(10분에 약 720m)이고, 직선 거리로 걷는 시간을 계산해 통근 시간에 더한다. 도착 정류장이 없으면 `COMMUTE_DESTINATION_UNREACHABLE`로 응답한다.
- `POL-COMMUTE-014`: 도착 정류장에서 구간과 환승을 거꾸로 따라가며 정류장마다 목적지까지 가장 짧은 통근 시간을 구한다. 노선에 탈 때마다 `POL-COMMUTE-003`의 대기 시간을 더하고, 환승 횟수(탑승 횟수 - 1)가 최대 환승 횟수를 넘거나 통근 시간이 최대 통근 시간을 넘는 경로는 버린다.
- `POL-COMMUTE-023`: 최대 통근 시간은 1분 이상 60분 이하(기본 60분), 최대 환승 횟수는 0회 이상 2회 이하(기본 2회)로 요청할 수 있다. 범위를 넓히면 탐색 상태와 응답이 크게 늘어(180분·환승 10회는 탐색 약 5초, 응답 약 10MB) 1GB 서버에서 동시 요청을 감당하기 어렵다. 경로 안내도 같은 범위를 쓴다.
- `POL-COMMUTE-015`: 정류장의 통근 시간은 초 단위 결과를 분으로 올림해 보여 준다. 동네(행정동)의 통근 시간은 동네 안 정류장 중 가장 짧은 시간이다. 동네는 통근 시간, 행정동 코드 순서로, 동네 안 정류장은 통근 시간, 이름 순서로 정렬한다.
- `POL-COMMUTE-016` (사용 중단): 정류장 방향(8방위) 표시는 사용하지 않는다. 사용자가 방위로 길 건너편 정류장을 구분하기 어렵고, 동네를 고르는 데 필요한 정보가 아니어서 계산을 없앴다. 응답의 정류장 `direction` 필드는 기존 클라이언트의 응답 파싱이 깨지지 않도록 남겨 두고 항상 `null`을 보내며, 응답 형식은 바꾸지 않는다(3.7). 이전에는 버스 정류장에 다음 정류장 쪽 8방위를 붙이고, 지하철·도시철도 역은 비웠다.
- `POL-COMMUTE-017`: 노선망은 웹 서버가 뜰 때 한 번 DB에서 읽어 서버 메모리에 두고, 이후 탐색과 경로 안내는 DB 커넥션 없이 메모리의 노선망으로 계산한다. 읽기 트랜잭션은 노선망을 DB에서 읽을 때만 연다. 서버가 뜰 때 읽지 못해도 서버는 그대로 띄운다. 적재는 별도 프로세스로 실행하므로 다시 적재한 노선망과 정류장의 행정동은 서버를 재시작해야 반영된다. 노선망이 적재되지 않았거나 DB를 읽지 못하면 메모리에 담지 않고 `TRANSIT_NETWORK_UNAVAILABLE`(503)로 응답한다. 실패한 뒤 30초 동안은 DB를 다시 읽지 않고 바로 503으로 응답하고, 30초가 지난 뒤 요청에서 다시 읽는다. DB에 연결하지 못하면 읽기 한 번이 커넥션 타임아웃만큼 걸려, 기다리던 요청마다 같은 실패를 반복하지 않게 하기 위해서다.
- `POL-COMMUTE-018`: 생활권 탐색은 로그인 없이 쓸 수 있다. 처음 찾아온 사용자가 가입 없이 바로 써 볼 수 있어야 하므로 `GET /api/commute-areas`는 토큰을 검사하지 않는다.
- `POL-COMMUTE-019`: 탐색 결과는 정류장을 행정동 코드로 묶어 보내고, 행정동 이름·경계·중심은 보내지 않는다. 행정동 데이터는 자주 바뀌지 않으므로 클라이언트가 같은 기준(통계청 SGIS 2025-06-30, 8자리 코드)의 데이터를 가지고 코드로 찾는다. 서버는 탐색할 때 행정동을 조회하지 않는다.

### 3.5. 서비스 지역

- `POL-COMMUTE-024`: 서비스 지역은 수도권이다. 노선망에는 통계청 행정동 코드 앞 두 자리가 서울(`11`)·인천(`23`)·경기(`31`)인 정류장만 담고, 탐색 결과에는 서울·경기 동네만 보여 준다. 인천은 서울·경기를 오가는 경로가 인천을 지나도 끊기지 않도록 노선망에만 남긴다. 단순화한 경계 사이 틈에 놓여 행정동이 비어 있는 정류장(수도권 124개)은 남긴 정류장과 구간으로 이어져 있으면 함께 남긴다. 구간과 환승은 양쪽 정류장이 모두 남을 때만, 노선은 남은 구간이 있을 때만 남긴다. KTDB 2025-03 데이터에서 노선 4,476개, 정류장 58,138개(서울 12,822개, 인천 6,937개, 경기 38,255개, 행정동 없음 124개), 구간 239,331개, 환승 306건이 남는다. 서울·경기 목적지 8곳을 60분·환승 2회로 탐색해 전국 노선망과 비교하면, 결과의 서울·경기 정류장 39,009건과 동네 2,751건의 통근 시간이 모두 같았다.

### 3.6. 경로 안내

- `POL-COMMUTE-020`: 경로 안내는 탐색 결과의 정류장 하나에서 목적지까지, 생활권 탐색과 같은 규칙(대기 시간, 최대 환승 횟수, 도착 정류장 도보)으로 가장 빠른 경로를 찾는다. 같은 최대 통근 시간과 최대 환승 횟수로 요청하면 경로의 통근 시간은 탐색 결과의 정류장 통근 시간과 같다. KTDB 2025-03 데이터에서 역삼역 기준 무작위 정류장 600곳의 통근 시간이 모두 일치했다.
- `POL-COMMUTE-021`: 경로는 같은 노선으로 이어진 구간을 하나로 묶은 구간 목록이다. 구간은 버스(`route_type` `0`, `3`), 지하철·도시철도(`1`), 도보로 나누고, 걸어서 하는 환승과 도착 정류장에서 목적지까지 걷는 구간은 도보로 보여 준다. 노선 구간에는 탈 때 기다리는 대기 시간을 따로 보여 준다.
- `POL-COMMUTE-022`: 경로 안내는 탐색 API와 따로 요청한다. 탐색 결과마다 경로를 붙이면 응답이 커지므로, 사용자가 정류장을 고를 때만 계산한다. 메모리의 노선망으로 계산하며 한 번에 평균 약 0.001초가 걸린다.
- 통근 시간은 시간대를 구분하지 않은 시간표 기반 추정치라, 심야 버스처럼 운행 시간이 제한된 노선도 경로에 나올 수 있다.

### 3.7. 정류장 방향 필드 사용 중단

`POL-COMMUTE-016`을 사용 중단해도 `GET /api/commute-areas`의 응답 형식은 바꾸지 않는다. 정류장 `direction` 필드는 이름과 타입(`string | null`)을 그대로 두고 사용 중단으로 표시해 항상 `null`을 보낸다. 기존 클라이언트도 `null`을 이미 방향 없음으로 처리하므로, 백엔드와 프론트엔드를 어떤 순서로 배포해도 동작한다.

변경 전:

```json
{
  "stopId": "BS_TAGO_SEB100000001",
  "stopName": "종로2가사거리",
  "latitude": 37.5698,
  "longitude": 126.988,
  "travelMinutes": 22,
  "direction": "북동"
}
```

변경 후 (`direction` 사용 중단, 항상 `null`):

```json
{
  "stopId": "BS_TAGO_SEB100000001",
  "stopName": "종로2가사거리",
  "latitude": 37.5698,
  "longitude": 126.988,
  "travelMinutes": 22,
  "direction": null
}
```

- 클라이언트는 `direction`을 읽지 않아도 된다. 새로 만드는 클라이언트는 이 필드에 기대지 않는다.
- 나중에 필드 자체를 지우려면, 먼저 클라이언트가 필드가 없어도 응답을 파싱하도록 바꿔 배포해야 한다. 지금 프론트엔드는 `direction`이 없으면 응답을 잘못된 형식으로 보고 실패한다.

| -------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| AC-COMMUTE-001 | GTFS 파일 5개가 있는 디렉터리를 지정해 적재 모드로 실행한다.              | 노선·정류장·구간·환승 건수가 로그에 남고 `gtfs_*` 테이블이 그 건수로 채워진다. |
| AC-COMMUTE-002 | 적재된 상태에서 다른 GTFS로 다시 적재한다.                                | 이전 노선망은 남지 않고 새 노선망만 조회된다.                                  |
| AC-COMMUTE-003 | GTFS 파일이 없는 디렉터리를 지정해 적재 모드로 실행한다.                  | 적재가 실패하고 기존 노선망은 그대로 남는다.                                   |
| AC-COMMUTE-004 | 목적지와 최대 통근 시간을 지정해 탐색한다.                                | 최대 통근 시간 안의 동네만 행정동 단위로 통근 시간과 함께 표시된다.            |
| AC-COMMUTE-005 | 최대 통근 시간을 늘려 같은 목적지로 다시 탐색한다.                        | 이전 결과의 동네가 모두 포함되고 동네 수는 같거나 늘어난다.                    |
| AC-COMMUTE-006 | 탐색 결과의 정류장을 골라 같은 조건으로 경로를 요청한다.                  | 타고 갈 노선과 걷는 구간이 순서대로 나오고 전체 통근 시간이 탐색 결과와 같다.  |
| AC-COMMUTE-007 | 행정동 경계 또는 GTFS 파일이 누락된 상태에서 일회성 적재 명령을 실행한다. | 적재가 실패하고 기존 노선망은 그대로 유지된다.                                 |
| AC-COMMUTE-008 | 인천과 맞닿은 서울·경기 목적지로 탐색한다.                                | 결과에는 서울·경기 동네만 나오고 인천 동네는 나오지 않는다.                    |

## 5. 미정 사항과 결정 근거

- 실거래 월세 정보와 통합할지는 가설 검증의 가격 수요 결과로 결정한다.
- 전국 데이터로 재면 메모리에 둔 노선망은 힙 약 85MB를 차지한다. 노선망을 읽을 때 구간 117만 개를 목록으로 모으지 않고 DB에서 한 행씩 스트리밍해 번호 배열에 바로 담아, 읽는 순간의 메모리 사용을 줄인다. 탐색 상태는 객체 없이 원시 배열로 다루고 도착 정류장은 목적지 주변 격자 칸에서만 찾아, 60분·환승 2회 탐색이 평균 약 0.016초에 끝난다. 부하 테스트로 병목을 확인한 뒤 결과 캐시, 동시 실행 제한 순으로 개선한다.
- 응답은 역삼역 기준 40분이면 약 270KB, 60분이면 약 1MB, 90분이면 약 2.4MB다. 대부분 정류장 목록이므로 응답 압축이나 동네별 정류장 수 제한을 함께 검토한다.
- 노선망을 수도권으로 줄여 정류장은 전국의 약 27%(214,237개 → 58,138개), 구간은 약 20%(1,173,452개 → 239,331개)만 남는다. 아래 메모리·탐색 시간은 전국 노선망에서 잰 값이다.
