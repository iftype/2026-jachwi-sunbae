# 생활권 탐색 기능 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-10-09 / 대상: 스프린트 2

## 1. 목적과 범위

사용자는 회사·학교 같은 목적지를 입력해, 대중교통으로 제한 시간 안에 출퇴근할 수 있는 동네를 찾는다.

자취선배의 기존 기능은 매물을 정한 뒤의 임장 단계에 집중되어 있다. 이 기능은 그보다 앞 단계인 "어디에 살지 정하는 단계"를 맡아 서비스의 진입점을 넓힌다.

### 1.1. 기능 선정 기준

| 기준                                          | 이 기능이 만족하는 방식                                                                                                                                            |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 사용자에게 매력적이어야 한다                  | 매물을 먼저 고르고 거리를 따지는 기존 방식과 달리, 통근 시간에서 출발해 동네 후보를 좁힌다. 지역을 잘 모르는 상경 사용자도 어느 동네부터 알아볼지 바로 알 수 있다. |
| 자체 데이터셋 없이 가치를 만들 수 있어야 한다 | KTDB(국가교통DB) 대중교통 GTFS와 행정동 경계 같은 공개 데이터만으로 동작해, 첫 사용자부터 같은 품질의 결과를 준다.                                                 |

### 1.2. 범위

| 구분      | 내용                                                                      |
| --------- | ------------------------------------------------------------------------- |
| 이번 범위 | GTFS 노선망 적재, 목적지 기준 도달권 탐색, 행정동 단위 결과 표시          |
| 후속 범위 | 정류장별 상세 경로 안내, 실거래 월세 정보와의 통합, TAGO 실시간 정보 연동 |
| 제외      | 자가용·도보 전용 통근, 매물 단위 추천                                     |

## 2. 요구사항

- `REQ-COMMUTE-001`: 목적지를 주소 검색 또는 지도 선택으로 지정한다.
- `REQ-COMMUTE-002`: 최대 통근 시간을 선택한다.
- `REQ-COMMUTE-003`: 목적지까지 최대 통근 시간 안에 도착할 수 있는 동네를 행정동 단위로, 통근 시간과 함께 확인한다.
- `REQ-COMMUTE-004`: 결과 동네를 선택해 지도에서 위치를 확인한다.
- `REQ-COMMUTE-005`: 운영자는 GTFS 파일로 대중교통 노선망을 적재·교체한다.

## 3. 정책

원천 CSV의 구조와 각 정책의 계산 과정은 [GTFS 데이터 구조와 파싱](commute-area-gtfs.md)에 실제 데이터 예시와 함께 정리한다.

### 3.1. 통근 시간 계산

- `POL-COMMUTE-001`: 통근 수단은 버스와 지하철·도시철도다. GTFS `route_type`이 `0`, `1`, `3`인 노선만 사용하고, KTDB 데이터에서 버스에 쓰는 `0`도 포함한다. 일반철도·항공·해운은 제외한다.
- `POL-COMMUTE-002`: 정류장 간 이동 시간은 같은 구간을 지나는 운행편 이동 시간의 중앙값으로 한다. 같은 분에 도착하는 구간도 최소 30초로 본다.
- 중앙값은 이동 시간과 운행 간격 모두 같은 정의를 쓴다. 값이 짝수 개면 가운데 두 값의 평균을 반올림한다.
- `POL-COMMUTE-003`: 노선에 탑승할 때마다 대기 시간을 더한다. 대기 시간은 첫 정류장 출발 간격 중앙값의 절반이며, 2분 이상 15분 이하로 제한한다. 쓸 수 있는 간격이 없으면 5분으로 둔다.
- `POL-COMMUTE-004`: 정류장 간 도보 환승은 GTFS `transfers.txt`의 최소 환승 시간을 쓴다. 같은 정류장 쌍이 여러 번 나오면 가장 짧은 시간을 쓴다. 환승 불가(`transfer_type` 3)이거나 최소 환승 시간이 비어 있는 환승은 쓰지 않는다. KTDB 2025-03 데이터의 환승 342건은 모두 `transfer_type` 2이고 최소 환승 시간이 있다.

### 3.2. 데이터

- `POL-COMMUTE-005`: 노선망 원천은 KTDB 대중교통 GTFS 2025년 3월 데이터셋이다. 노선 26,399개, 정류장 215,409개, 정차 기록 18,889,140건이다.
- `POL-COMMUTE-006`: 적재는 기존 노선망을 모두 지우고 새로 채우는 전체 교체다. 파일을 모두 읽은 뒤 삭제와 저장을 한 트랜잭션으로 처리해, 실패하면 이전 노선망을 유지한다.
- `POL-COMMUTE-007`: 대상 노선이 실제로 지나지 않는 정류장과, 출발·도착 정류장 중 한쪽이라도 적재 대상이 아닌 환승은 적재하지 않는다.
- `POL-COMMUTE-008`: `stop_times.txt`는 운행편별로 모여 있고 운행편 안의 `stop_sequence`가 증가한다고 보고 한 번만 읽는다. GTFS 표준은 행 순서를 보장하지 않으므로, 이 전제가 깨진 데이터는 틀린 구간을 만드는 대신 적재를 실패시킨다. KTDB 2025-03 데이터는 운행편 326,368개 모두 이 전제를 만족한다.

### 3.3. 행정동

- `POL-COMMUTE-009`: 행정동 원천은 통계청 SGIS 행정구역 경계(행정동) 2025-06-30 기준 데이터로, 행정동 3,559개다. 코드는 통계청 행정동 코드 8자리를 쓴다. 경계는 지도에 그리는 용도로 허용 오차 0.00015도(약 15m)로 단순화해 GeoJSON으로 저장하고, 변환 방법은 `backend/scripts/admin-dongs`에 둔다. 적재할 때 경계 좌표를 소수점 5자리(약 1m)로 반올림해 저장·응답 크기를 줄인다(전국 경계 27.3MB → 14.6MB).
- `POL-COMMUTE-010`: 정류장의 행정동은 정류장 좌표가 들어 있는 행정동 경계로 정한다. 어느 경계에도 들지 않으면 비워 두고 탐색 결과에서 뺀다. 단순화한 경계가 이웃 행정동과 겹쳐 두 행정동에 들어가는 정류장(231개)은 코드가 작은 행정동으로 정해, 적재 순서와 상관없이 같은 결과가 나오게 한다. KTDB 2025-03 정류장 214,237개 중 213,981개(99.88%)가 행정동에 매칭되고, 256개는 단순화한 경계 밖에 놓인다.
- `POL-COMMUTE-011`: 행정동 적재는 기존 행정동을 모두 지우고 새로 채우는 전체 교체이며, 이미 적재된 정류장의 행정동도 새 경계로 다시 정한다. GTFS 적재도 행정동이 적재되어 있으면 정류장의 행정동을 함께 정하므로, 두 데이터를 어떤 순서로 적재해도 결과가 같다.
- `POL-COMMUTE-012`: 행정동의 중심 좌표는 가장 넓은 폴리곤 바깥 고리의 무게중심이며, 지도에 이름을 올리는 위치로만 쓴다. 오목한 행정동은 중심이 경계 밖에 놓일 수 있다(3,559개 중 30개).

### 3.4. 탐색

- `POL-COMMUTE-013`: 목적지에서 걸어서 10분 안의 정류장·역을 도착 정류장으로 본다. 도보 속도는 초속 1.2m(10분에 약 720m)이고, 직선 거리로 걷는 시간을 계산해 통근 시간에 더한다. 도착 정류장이 없으면 `COMMUTE_DESTINATION_UNREACHABLE`로 응답한다.
- `POL-COMMUTE-014`: 도착 정류장에서 구간과 환승을 거꾸로 따라가며 정류장마다 목적지까지 가장 짧은 통근 시간을 구한다. 노선에 탈 때마다 `POL-COMMUTE-003`의 대기 시간을 더하고, 환승 횟수(탑승 횟수 - 1)가 최대 환승 횟수를 넘거나 통근 시간이 최대 통근 시간을 넘는 경로는 버린다.
- `POL-COMMUTE-015`: 정류장의 통근 시간은 초 단위 결과를 분으로 올림해 보여 준다. 동네(행정동)의 통근 시간은 동네 안 정류장 중 가장 짧은 시간이다. 동네는 통근 시간, 행정동 코드 순서로, 동네 안 정류장은 통근 시간, 이름 순서로 정렬한다.
- `POL-COMMUTE-016`: 버스 정류장에는 다음 정류장 쪽 방향을 8방위로 붙여 길 건너편의 같은 이름 정류장을 구분한다. 지하철·도시철도 역은 양방향을 한 정류장으로 쓰므로 방향을 두지 않는다.
- `POL-COMMUTE-017`: 노선망은 처음 탐색할 때 한 번 DB에서 읽어 서버 메모리에 두고, 이후 탐색은 메모리의 노선망을 쓴다. 적재는 별도 프로세스로 실행하므로 다시 적재한 노선망과 정류장의 행정동은 서버를 재시작해야 반영된다. 노선망이 적재되지 않았으면 메모리에 담지 않고 `TRANSIT_NETWORK_UNAVAILABLE`(503)로 응답해, 적재한 뒤 다음 요청에서 바로 읽는다.
- `POL-COMMUTE-018`: 생활권 탐색은 로그인 없이 쓸 수 있다. 처음 찾아온 사용자가 가입 없이 바로 써 볼 수 있어야 하므로 `GET /api/commute-areas`는 토큰을 검사하지 않는다.

## 4. 인수 기준

| ID             | 조건과 행동                                                  | 관찰할 결과                                                                    |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| AC-COMMUTE-001 | GTFS 파일 5개가 있는 디렉터리를 지정해 적재 모드로 실행한다. | 노선·정류장·구간·환승 건수가 로그에 남고 `gtfs_*` 테이블이 그 건수로 채워진다. |
| AC-COMMUTE-002 | 적재된 상태에서 다른 GTFS로 다시 적재한다.                   | 이전 노선망은 남지 않고 새 노선망만 조회된다.                                  |
| AC-COMMUTE-003 | GTFS 파일이 없는 디렉터리를 지정해 적재 모드로 실행한다.     | 적재가 실패하고 기존 노선망은 그대로 남는다.                                   |
| AC-COMMUTE-004 | 목적지와 최대 통근 시간을 지정해 탐색한다.                   | 최대 통근 시간 안의 동네만 행정동 단위로 통근 시간과 함께 표시된다.            |
| AC-COMMUTE-005 | 최대 통근 시간을 늘려 같은 목적지로 다시 탐색한다.           | 이전 결과의 동네가 모두 포함되고 동네 수는 같거나 늘어난다.                    |

## 5. 미정 사항과 결정 근거

- 최대 통근 시간(1분 이상 180분 이하, 기본 60분)과 최대 환승 횟수(0회 이상 10회 이하, 기본 2회)는 프로토타입 값이며 선택지와 기본값을 확정하지 않았다.
- 실거래 월세 정보와 통합할지는 가설 검증의 가격 수요 결과로 결정한다.
- 전국 데이터로 재면 메모리에 둔 노선망은 힙 약 85MB를 차지하고, 처음 읽을 때는 노선망 목록까지 잠시 수백 MB를 쓴다. 이후 탐색은 60분·환승 2회 기준 0.1초 안에 끝난다. 부하 테스트로 병목을 확인한 뒤 결과 캐시, 동시 실행 제한 순으로 개선한다.
- 응답에 행정동 경계를 담으므로 역삼역 기준 60분이면 약 1.5MB, 90분이면 약 3.5MB다. 경계 좌표를 반올림한 뒤에도 정류장 목록과 경계가 응답의 대부분을 차지하므로 응답 압축을 함께 검토한다.
