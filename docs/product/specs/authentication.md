# 회원·인증 기능 명세

- 상태: 익명 인증 정책 / 수정일: 2026-10-22 / 대상: MVP1-2

## 1. 목적과 범위

사용자는 로그인 정보를 입력하지 않고 서비스를 시작해 자신의 매물과 체크 기록을 저장·조회한다. PostHog에서 기존 로그인 화면 방문자의 85%가 이탈한 것을 확인해 입력 화면을 제거한다.

첫 방문에는 익명 회원을 만들고, 이후에는 브라우저가 보관한 Refresh Token으로 같은 회원을 식별한다. 익명 회원은 자신의 실제 기록을 사용하며, 별도의 게스트 샘플 데이터 조회는 제공하지 않는다. 회원 ID는 사람이나 기기의 고유 ID를 뜻하지 않는다. 서로 다른 브라우저·앱의 기록 연결, 기존 닉네임 회원의 기록 전환과 외부 계정 연결은 이번 범위에서 제외한다.

## 2. 요구사항

- `REQ-AUTH-001`: 앱을 시작할 때 입력 없이 인증을 시작한다. 회원이 없으면 익명 회원을 자동 생성한다.
- `REQ-AUTH-002`: 유효한 Refresh Token을 보관한 환경에서는 재방문해도 같은 회원의 기록을 이용한다.
- `REQ-AUTH-003`: Access Token이 만료되면 화면 상태를 유지한 채 새 토큰을 발급받아 이용을 계속한다.
- `REQ-AUTH-004`: 로그인 요청에서 기존 인증을 복원할 수 없으면 새 익명 회원으로 시작한다. 이전 회원의 데이터는 이 요청으로 삭제하지 않는다.
- `REQ-AUTH-005`: 토큰 갱신 요청에서 기존 인증을 복원할 수 없으면 실패를 알리고 새 회원을 자동 생성하지 않는다.
- `REQ-AUTH-006`: 로그인·토큰 갱신을 제외한 업무 API는 익명 회원에게도 Access Token을 요구한다.
- `REQ-AUTH-007`: 회원은 다른 회원의 매물·체크 기록을 조회·변경·삭제할 수 없다.
- `REQ-AUTH-008`: DB 장애나 저장 데이터 손상을 인증 실패 또는 새 회원 생성으로 숨기지 않는다.

## 3. 정책

### 3.1. 익명 회원과 기록

- `POL-AUTH-001`: 첫 `POST /api/auth/login` 요청에 Refresh Token이 없으면 새 회원 ID를 생성한다. 닉네임·비밀번호 입력이나 기기 식별값은 사용하지 않는다.
- `POL-AUTH-002`: 유효한 Refresh Token이 정상 회원과 연결돼 있으면 같은 회원을 복원한다. 탈퇴한 회원은 복원하지 않는다.
- `POL-AUTH-003`: 로그인 요청의 Refresh Token이 없거나 만료·삭제됐거나 정상 회원과 연결되지 않으면 새 익명 회원을 생성한다. 기존 회원과 기록은 자동 삭제하지 않지만, 새 회원에게 이전 기록을 연결하지 않는다.
- `POL-AUTH-004`: 브라우저 프로필·앱마다 인증 정보를 별도로 보관하며, 같은 사람이라도 인증 정보를 공유하지 않으면 다른 회원으로 취급한다.
- `POL-AUTH-005`: 회원 소유 데이터는 인증된 회원 ID를 기준으로 조회·변경·삭제 권한을 확인한다. 다른 회원의 자원은 `404`로 응답하고 노출하지 않는다.

### 3.2. 토큰과 API 접근

- `POL-AUTH-006`: Access Token은 15분간 유효한 JWT다. 로그인·토큰 갱신을 제외한 모든 업무 API 요청에 `Authorization: Bearer <Access Token>` 헤더로 전달한다. 지도·검색 조회에도 적용한다.
- `POL-AUTH-007`: Refresh Token은 365일간 유효하며 HttpOnly·Secure 쿠키로 전달한다. 서버에는 원문 대신 해시를 저장한다.
- `POL-AUTH-008`: 유효한 Refresh Token으로 로그인하거나 토큰을 갱신하면 토큰 값은 유지하고 만료 시각을 그때부터 365일로 연장한다.
- `POL-AUTH-009`: `POST /api/auth/refresh`는 기존 회원의 Access Token만 재발급한다. Refresh Token이 없거나 유효하지 않으면 `401 REFRESH_TOKEN_INVALID`를 반환하고 새 회원을 생성하지 않는다.
- `POL-AUTH-010`: 업무 API에 Access Token이 없거나 유효하지 않으면 `401 ACCESS_TOKEN_INVALID`를 반환한다. Access Token 만료 후 갱신에 성공하면 원래 요청을 한 번 재시도한다.
- `POL-AUTH-011`: 로그인·토큰 갱신 과정의 DB 조회·저장 장애 또는 저장 데이터 손상은 서버 오류로 처리한다.

## 4. 인수 기준

| ID          | 조건과 행동                                                               | 관찰할 결과                                                                                             |
| ----------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| AC-AUTH-001 | 인증 정보 없이 앱을 시작한다.                                             | 입력 화면 없이 새 익명 회원이 생성되고 Access Token과 Refresh 쿠키로 자신의 기록을 저장·조회할 수 있다. |
| AC-AUTH-002 | 기록이 있는 회원의 유효한 Refresh 쿠키로 앱을 다시 시작한다.              | 새 회원을 만들지 않고 같은 회원의 기록을 조회하며 Refresh Token의 만료 시각이 연장된다.                 |
| AC-AUTH-003 | Refresh 쿠키가 없거나 만료·삭제된 상태로 앱을 시작한다.                   | 새 회원으로 시작하고 기존 회원의 기록은 삭제되지 않는다.                                                |
| AC-AUTH-004 | 유효한 Refresh 쿠키로 토큰 갱신을 요청한다.                               | 같은 회원의 Access Token이 발급되고 Refresh Token의 만료 시각이 연장된다.                               |
| AC-AUTH-005 | 쿠키가 없거나 유효하지 않은 상태로 토큰 갱신을 요청한다.                  | `401 REFRESH_TOKEN_INVALID`를 받고 새 회원은 생성되지 않는다.                                           |
| AC-AUTH-006 | Access Token 없이 지도·검색·월세 등 업무 API를 호출한다.                  | `401 ACCESS_TOKEN_INVALID`를 받고, 유효한 Access Token을 첨부하면 해당 API를 이용할 수 있다.            |
| AC-AUTH-007 | 이용 중 Access Token이 만료된다.                                          | 갱신 후 실패한 요청을 한 번 재시도하며 화면·입력 내용은 유지된다.                                       |
| AC-AUTH-008 | 회원 A의 토큰으로 회원 B의 매물·체크 기록을 조회·변경한다.                | B의 내용이 노출되거나 변경되지 않는다.                                                                  |
| AC-AUTH-009 | 서로 다른 브라우저에서 처음 접속한다.                                     | 각각 다른 익명 회원으로 시작하며 기록을 공유하지 않는다.                                                |
| AC-AUTH-010 | 로그인·토큰 갱신 중 DB에 장애가 발생하거나 저장된 인증 데이터가 손상된다. | 서버 오류를 반환하며 이를 새 회원 생성이나 인증 실패로 처리하지 않는다.                                 |

## 5. 미정 사항

- 브라우저·WebView 환경별 쿠키·CORS·CSRF 설정의 세부 계약
- 명시적 인증 폐기와 여러 탭의 토큰 갱신 조정 방식
- 장기 미접속 회원의 기록 보존·삭제 정책과 추후 OAuth 계정 연결 방식
