# 거리 메모 정책

- 상태: 검토용 초안 v0.5 / 작성일: 2026-10-26
- 대상: 지도 위 동네 정보와 작성자 선호의 작성·공유·조회·삭제
- 관련 이슈: [#436 거리 메모 기능 구현](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/436)
- 구현 범위: 스키마·도메인·JDBC 저장소·서비스와 작성·조회·삭제 API를 구현했다. 화면은 후속 구현 범위다.

## 1. 목적과 범위

사용자는 지도에서 선택한 위치에 동네 정보와 좋아요·싫어요 선호를 함께 남기고, 다른 사용자가 남긴 정보를 확인한다.
예를 들어 편리한 무인 세탁소에는 좋아요, 소음이 심한 골목에는 싫어요를 선택해 메모를 작성한다.

선호는 작성자가 메모를 처음 작성할 때 입력하는 단일 구분값이다.
프론트엔드는 서버가 제공하는 선호값으로 좋아요·싫어요를 구분해 표시한다.
공유 화면에는 작성자를 식별할 수 있는 정보를 제공하지 않으며, 서버는 본인 삭제 권한을 확인하기 위해 회원 ID를 내부적으로 보관한다.

### 제공 범위

- 지도에서 선택한 위치에 메모와 좋아요·싫어요 선호를 함께 작성
- 다른 회원이 작성한 메모의 위치·내용·선호 조회
- 작성자 본인의 메모 삭제
- 작성자 정보가 노출되지 않는 공유

메모 수정, 사진, 카테고리, 다른 사용자의 반응·투표 집계, 댓글, 북마크, 개별 사용자 공유와 링크 공유는 이번 범위에 포함하지 않는다.
인증은 기존 익명 인증을 사용하며, 우선 메모의 선호값을 저장하고 조회해 표시하는 데 집중한다.

## 2. 요구사항

### 2.1. 기능 요구사항

- `REQ-STREET-001`: 회원은 지도에서 위치를 선택하고 해당 위치에 메모를 작성할 수 있다.
- `REQ-STREET-002`: 매물을 등록하지 않은 회원도 거리 메모를 작성하고 조회할 수 있다.
- `REQ-STREET-003`: 작성자뿐 아니라 다른 회원도 메모의 위치·내용·선호를 확인할 수 있다.
- `REQ-STREET-004`: 조회 응답과 화면에 작성자의 회원 ID·닉네임·프로필 등 식별 정보를 제공하지 않는다.
- `REQ-STREET-005`: 작성자는 자신의 메모를 삭제할 수 있다. 작성·조회 응답의 `isMine`으로 본인 메모를 구분해 삭제 버튼을 표시할 수 있다. 다른 회원은 해당 메모를 삭제할 수 없다.
- `REQ-STREET-006`: 삭제한 메모는 이후 새로 조회하는 지도와 메모 조회 결과에서 제외한다.
- `REQ-STREET-007`: 저장 후 다시 조회하거나 화면에 재진입해도 저장한 위치·내용·선호가 유지된다.
- `REQ-STREET-008`: 작성·조회·삭제 실패를 성공과 구분해 안내한다. 메모 없음과 조회 실패를 구분한다.
- `REQ-STREET-009`: 작성자는 메모 최초 작성 시 좋아요 또는 싫어요 중 하나를 필수로 선택한다.
- `REQ-STREET-010`: 조회 응답은 메모마다 `preference`를 포함한다. 프론트엔드는 이 값으로 좋아요·싫어요를 구분해 표시한다.

## 3. 정책

### 3.1. 회원과 공유 범위

- `POL-STREET-001`: 기존 [익명 인증 정책](../product/specs/authentication.md)을 따른다. 별도의 닉네임·프로필 입력을 요구하지 않는다.
- `POL-STREET-002`: 작성자는 요청의 인증 정보로 결정한다. 클라이언트가 전달한 회원 ID로 다른 회원의 메모를 생성하거나 삭제할 수 없다.
- `POL-STREET-003`: 저장한 메모는 다른 회원도 위치·내용·선호를 조회할 수 있는 공유 데이터다. 특정 회원에게만 공개하거나 나만 보기로 전환하는 기능은 이번 범위에서 제공하지 않는다.
- `POL-STREET-004`: `member_id`는 내부 소유권 확인에만 사용하며 공유 응답에 포함하지 않는다. 작성·조회 응답의 `isMine`은 인증된 회원과 작성자가 일치하면 `true`, 다르면 `false`다. 프론트엔드는 이 값으로 본인 메모와 삭제 버튼을 구분한다. 실제 삭제 권한은 서버에서 별도로 검증하며 클라이언트가 보낸 `isMine`을 신뢰하지 않는다.
- `POL-STREET-005`: 소유권은 회원 ID를 기준으로 판단한다. 인증 정보가 사라져 새 익명 회원이 만들어지면 같은 사람이더라도 이전 메모의 삭제 권한을 자동으로 부여하지 않는다.

### 3.2. 위치와 메모 내용

- `POL-STREET-006`: 하나의 메모는 지도에서 선택한 하나의 위치·내용·선호를 가진다. 매물이나 외부 시설 ID 연결을 필수로 요구하지 않는다.
- `POL-STREET-007`: 위도·경도는 함께 입력하며 각각 -90 이상 90 이하, -180 이상 180 이하를 허용한다. 위치 선택이나 좌표 전달 실패 시 임의의 대체 위치에 메모를 저장하지 않는다.
- `POL-STREET-008`: 메모 내용은 필수이며 `null`을 허용하지 않는다. 빈 문자열·공백만 있는 내용의 처리와 최대 글자 수는 후속 입력 정책에서 결정한다.
- `POL-STREET-009`: 저장하는 좌표는 사용자가 선택한 메모 대상 위치다. 작성자의 현재 위치나 이동 경로를 거리 메모의 별도 데이터로 수집하지 않는다.

### 3.3. 좋아요·싫어요 선호

- `POL-STREET-010`: `preference`는 작성자가 메모 최초 작성 시 입력하는 필수 값이다. 메모당 하나만 저장하며 기본값을 지정하지 않는다.
- `POL-STREET-011`: 대문자 코드 `LIKE`, `DISLIKE`만 허용한다. 누락·`null`·빈 문자열·정의되지 않은 값은 거부한다. 중립·미선택 상태는 저장하지 않는다.
- `POL-STREET-012`: 조회 응답은 저장된 `preference`를 그대로 제공한다. 프론트엔드는 메모 내용에서 선호를 추측하지 않고 코드에 따라 표시한다.

| 저장·응답 코드 | 화면 의미 | 입력 주체   |
| -------------- | --------- | ----------- |
| `LIKE`         | 좋아요    | 메모 작성자 |
| `DISLIKE`      | 싫어요    | 메모 작성자 |

좋아요·싫어요 개수, 다른 회원의 투표 이력이나 반응 변경 기능은 현재 데이터에 포함하지 않는다.

### 3.4. 조회와 삭제

- `POL-STREET-013`: 지도에 보이는 사각형 영역을 기준으로 조회한다. 최소·최대 위도와 최소·최대 경도를 모두 전달하며 영역 경계의 메모도 포함한다. 작성자 구분 없이 해당 영역 안의 `deleted_at`이 `NULL`인 메모를 공유 조회한다.
- `POL-STREET-014`: 삭제 요청은 인증된 회원 ID와 메모의 `member_id`가 일치하는 경우에만 처리한다. 존재하지 않거나 이미 삭제됐거나 타인이 소유한 메모의 삭제 요청은 기존 자원 접근 정책에 맞춰 `404`로 처리한다.
- `POL-STREET-015`: 삭제는 `deleted_at`에 서버에서 정한 시각을 기록하는 논리 삭제다. `updated_at`도 같은 시각으로 갱신하며 기존 내용·선호·작성 시각을 유지한다. 해당 요청으로 행을 물리 삭제하지 않는다.
- `POL-STREET-016`: 작성·수정 시각은 `BaseTimeEntity`의 공통 필드로 보관한다. 메모 내용과 선호의 수정 기능 제공 여부는 5절에서 별도 결정한다.

### 3.5. 저장 데이터와 조회 응답

테이블은 `street_memos`이며 [V6 마이그레이션](../../backend/src/main/resources/db/migration/V6__create_street_memos.sql)으로 추가한다.
아래 표는 내부 저장 구조다. 공유 응답에서는 작성자 식별 정보를 제외한다.

| 필드         | 저장 타입        | 필수 여부 | 의미                                                     |
| ------------ | ---------------- | --------- | -------------------------------------------------------- |
| `id`         | `BIGINT`         | 필수      | 서버가 생성하는 메모 식별자                              |
| `member_id`  | `BIGINT`         | 필수      | 작성자 회원 참조. 공유 응답에서 제외한다.                |
| `latitude`   | `DECIMAL(10, 7)` | 필수      | 메모 대상 위치의 위도                                    |
| `longitude`  | `DECIMAL(11, 7)` | 필수      | 메모 대상 위치의 경도                                    |
| `memo`       | `TEXT`           | 필수      | 사용자 작성 내용. 최대 입력 길이는 별도 정책으로 정한다. |
| `preference` | `VARCHAR(10)`    | 필수      | 작성 시 선택한 `LIKE` 또는 `DISLIKE`. 기본값 없음.       |
| `created_at` | `DATETIME(6)`    | 필수      | 서버에서 기록하는 작성 시각                              |
| `updated_at` | `DATETIME(6)`    | 필수      | 서버에서 기록하는 수정 시각                              |
| `deleted_at` | `DATETIME(6)`    | 선택      | 미삭제 시 `NULL`, 삭제 시 삭제 시각                      |

현재 스키마는 작성자 외래 키, 좌표 범위·선호값 제약과 `(deleted_at, latitude, longitude)` 조회 인덱스를 둔다.
주소·장소명·사진·카테고리·공개 범위 필드는 현재 저장하지 않는다.
조회 기준 위치에서 메모까지의 거리가 필요하면 조회 시 계산하며 메모의 고정 데이터로 저장하지 않는다.

공유 응답의 메모 데이터는 본인 여부를 포함해 다음 여섯 필드를 제공한다. HTTP 식별자 이름은 API 컨벤션에 맞춰 `streetMemoId`를 사용하며 작성자·시각 필드는 포함하지 않는다.

```json
{
  "streetMemoId": 1,
  "latitude": 37.3948,
  "longitude": 127.1112,
  "memo": "저녁에 배달 오토바이가 많이 다녀요.",
  "preference": "DISLIKE",
  "isMine": false
}
```

### 3.6. 도메인 구현

`com.jachwisunbae.streetmemo.domain`에서 확정된 불변 조건과 상태 변경 규칙을 관리한다.

| 객체                                                                                                             | 책임                                                                  |
| ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| [StreetMemo](../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemo.java)                     | 생성·저장 데이터 복원, 작성자 소유권 판단, 논리 삭제와 시간 상태 관리 |
| [StreetMemoLocation](../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemoLocation.java)     | 필수 위도·경도와 허용 범위 검증                                       |
| [StreetMemoPreference](../../backend/src/main/java/com/jachwisunbae/streetmemo/domain/StreetMemoPreference.java) | `LIKE`·`DISLIKE` 구분과 대문자 코드 변환                              |

- 생성할 때 메모 ID와 삭제 시각은 없으며 작성·수정 시각은 전달받은 서버 시각으로 초기화한다.
- 복원할 때 저장된 ID, 내용·선호와 작성·수정·삭제 시각을 유지한다. 작성자 ID와 복원할 메모 ID는 양수여야 한다.
- 시각은 작성·수정·삭제 순서를 지켜야 한다. 삭제 요청의 시각은 마지막 수정 시각과 같거나 이후여야 한다.
- 현재 내용 검증은 `null` 필수 제약을 적용하며 전달받은 공백·줄바꿈을 보존한다. 최대 길이와 빈 문자열·공백만 있는 내용의 처리 정책은 5절에서 결정한다.
- 내용·위치·선호 입력 오류는 각각 `STREET_MEMO_CONTENT_INVALID`, `STREET_MEMO_LOCATION_INVALID`, `STREET_MEMO_PREFERENCE_INVALID`로 구분한다. 이미 삭제됐거나 타인이 소유한 메모의 삭제는 `STREET_MEMO_NOT_FOUND`로 거부한다.
- DB 복원 중 도메인 입력 검증이나 내부 불변식 검증에 실패하면 Repository에서 기존 [예외 컨벤션](../../backend/docs/conventions/exception-convention.md)에 따라 `DataInconsistencyException`으로 변환한다.

### 3.7. 서비스와 저장소 구현

| 객체                                                                                                                         | 책임                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| [StreetMemoService](../../backend/src/main/java/com/jachwisunbae/streetmemo/service/StreetMemoService.java)                  | 작성·지도 영역 조회·본인 삭제 유스케이스와 트랜잭션 관리             |
| [JdbcStreetMemoRepository](../../backend/src/main/java/com/jachwisunbae/streetmemo/repository/JdbcStreetMemoRepository.java) | 메모 저장, 영역 SQL 조회, 삭제 행 잠금과 논리 삭제, 저장 데이터 복원 |
| [StreetMemoResult](../../backend/src/main/java/com/jachwisunbae/streetmemo/service/dto/result/StreetMemoResult.java)         | 작성자 식별자를 제외한 메모 ID·위도·경도·내용·선호·본인 여부 전달    |

- 작성·삭제 시 회원 서비스를 통해 현재 유효한 회원인지 확인한다. 작성자는 인증 경계에서 전달받은 회원 ID로 정하고, 시각은 공통 `Clock`에서 얻는다.
- 작성·삭제는 쓰기 트랜잭션, 조회는 읽기 전용 트랜잭션으로 처리한다. 저장에 실패하면 성공 결과를 반환하지 않으며 DB 변경을 롤백한다.
- 조회 요청의 회원 ID는 인증 정보에서 얻는다. 작성·조회 결과의 `isMine`은 서버에서 계산하며, 생성된 메모는 `true`를 반환한다.
- 영역 조회는 서비스의 `validateBounds()`에서 네 좌표의 필수값·허용 범위·최소 및 최대 순서를 검증한다. 잘못된 영역은 `STREET_MEMO_QUERY_INVALID`로 거부하며 저장소를 호출하지 않는다. 검증한 좌표 네 개를 저장소에 직접 전달해 SQL에서 삭제 여부와 위도·경도 범위로 조회한다. 빈 결과는 빈 목록으로 반환하고 DB 장애는 실패로 전달한다.
- 삭제는 대상 행을 잠근 뒤 도메인에서 소유권과 상태를 검증한다. 저장소에서도 메모 ID·작성자·미삭제 조건을 확인하며 실제 변경된 행이 없는 경우 삭제 성공으로 처리하지 않는다.
- 동일한 메모를 동시에 삭제할 때 한 요청만 성공하고 나머지는 `STREET_MEMO_NOT_FOUND`로 처리한다. 최초 삭제 시각을 덮어쓰지 않는다.
- 조회 결과의 정렬 순서·최대 개수는 현재 보장하지 않으며 5절의 후속 정책에서 결정한다. 인증 토큰 검증과 HTTP 응답 변환은 API 계층의 책임이다.

### 3.8. API 구현과 검증 경계

- [StreetMemoController](../../backend/src/main/java/com/jachwisunbae/streetmemo/controller/StreetMemoController.java)는 기존 익명 인증 필터를 통해 작성·조회·삭제 요청의 Access Token을 검증한다. 작성·삭제의 회원 ID는 인증 정보에서만 얻는다.
- 작성 요청의 위도·경도·내용·선호 누락과 `null`은 Request DTO에서 검증한다. 빈 문자열·공백만 있는 메모는 아직 제한하지 않고 공백·줄바꿈을 보존한다. 선호는 도메인의 코드 변환을 통해 대문자 `LIKE`, `DISLIKE`만 허용한다.
- 지도 영역 좌표 네 개는 별도 영역 객체 없이 서비스로 전달한다. 누락·범위·순서 오류는 서비스의 `validateBounds()`가 검증하고, 숫자로 읽을 수 없는 요청은 공통 HTTP 예외 처리기가 거부한다.
- 생성 성공은 `201`과 생성 위치를, 조회 성공은 `200`과 메모 배열을, 삭제 성공은 본문 없는 `204`를 반환한다. 작성·조회 데이터는 전용 Response DTO를 거쳐 공통 성공 응답 형식에 담는다.
- Controller는 매핑 어노테이션과 `@Operation`으로 경로와 API 목적을 표시하고, `@SecurityRequirement`로 다른 API와 동일한 Bearer 인증을 Swagger에 선언한다. 요청·응답 구조는 DTO에서 확인한다. 인수 테스트는 실제 로그인 토큰과 MySQL을 사용해 공유 조회·삭제 권한·입력 검증·작성자 비노출과 인증 누락·잘못된 토큰 거부, Swagger의 인증 요구사항을 검증한다.
- 같은 입력 조합을 계층마다 반복 검사하지 않는다. 주요 기능 흐름은 API 인수 테스트에서 검증하고, 통합 테스트는 좌표 저장 정밀도·저장 실패 롤백·동시 삭제·저장 데이터 오류를 확인한다. 도메인 테스트는 좌표 경계와 삭제 시각 규칙에 집중하며 마이그레이션 테스트는 기존 데이터 보존과 주요 DB 제약을 확인한다.

## 4. 인수 기준

아래 기준은 기능 구현 완료 시 검증한다. DB 검증만으로 화면·API·권한 요구사항의 완료를 판단하지 않는다.

| ID            | 조건과 행동                                                                 | 관찰할 결과                                                                                             |
| ------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| AC-STREET-001 | 인증된 회원 A가 위치·내용·좋아요 선호를 선택해 작성한 뒤 다시 조회한다.     | 위치·내용과 `preference: LIKE`가 유지되고 화면에 좋아요로 표시된다.                                     |
| AC-STREET-002 | 회원 A가 위치·내용·싫어요 선호를 선택해 작성한 뒤 다시 조회한다.            | 위치·내용과 `preference: DISLIKE`가 유지되고 화면에 싫어요로 표시된다.                                  |
| AC-STREET-003 | 선호를 누락하거나 `null`·빈 문자열·`NEUTRAL`·소문자 `like`로 작성한다.      | 메모가 저장되지 않고 기본 선호로 대체되지 않는다.                                                       |
| AC-STREET-004 | 매물이 없는 회원이 메모를 작성하고 조회한다.                                | 매물 등록을 요구하지 않고 메모를 저장·조회할 수 있다.                                                   |
| AC-STREET-005 | 다른 회원 B가 A의 메모를 조회한다.                                          | `isMine: false`와 위치·내용·선호를 확인할 수 있고 작성자 회원 ID·프로필·고정 별칭은 응답과 화면에 없다. |
| AC-STREET-006 | A가 자신의 메모를 삭제한 후 A와 B가 해당 위치를 새로 조회한다.              | 메모가 조회에서 제외되고 DB에는 `deleted_at`이 기록된 행이 남는다.                                      |
| AC-STREET-007 | B가 A의 메모를 삭제하거나 삭제·미존재 메모의 삭제를 요청한다.               | `404`로 거부되며 다른 메모에 영향을 주지 않는다.                                                        |
| AC-STREET-008 | Access Token 없이 작성·조회·삭제를 요청한다.                                | 기존 인증 정책에 따라 `401 ACCESS_TOKEN_INVALID`로 거부된다.                                            |
| AC-STREET-009 | 위도·경도를 누락하거나 허용 범위를 벗어난 좌표로 저장한다.                  | 메모가 저장되지 않고 잘못된 위치임을 알 수 있다.                                                        |
| AC-STREET-010 | 위치 선택에 실패한 상태에서 작성을 완료하려 한다.                           | 임의의 대체 위치에 메모가 등록되지 않는다.                                                              |
| AC-STREET-011 | 메모가 없는 경우와 조회 요청 자체가 실패한 경우를 각각 확인한다.            | 메모 없음과 조회 실패를 서로 다른 상태로 안내한다.                                                      |
| AC-STREET-012 | 작성 또는 삭제 중 DB 저장을 실패시킨다.                                     | 성공으로 안내하지 않고 생성 실패 시 새 메모가 노출되지 않으며 삭제 실패 시 기존 메모가 유지된다.        |
| AC-STREET-013 | HTML·스크립트 형태의 메모를 조회한다.                                       | 코드가 실행되지 않고 텍스트로 표시된다.                                                                 |
| AC-STREET-014 | A의 인증 정보가 사라져 새 익명 회원 C로 시작한 뒤 A의 메모 삭제를 시도한다. | C에게 A의 메모 삭제 권한을 자동으로 부여하지 않는다.                                                    |
